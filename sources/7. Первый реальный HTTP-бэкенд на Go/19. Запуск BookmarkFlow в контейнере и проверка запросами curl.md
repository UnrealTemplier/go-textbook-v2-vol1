*Собираем образ Docker, пробрасываем порт `-p` и том `-v` для сохранения файла закладок под пользователем `nonroot`, а затем прогоняем полный сценарий проверки API командами `curl`.*

Самая частая ошибка при первом запуске веб-сервиса в контейнере выглядит так: вы запустили контейнер, создали пять закладок, пересобрали код и перезапустили контейнер — и все пять закладок бесследно исчезли. Дело не в баге вашего `FileStore`: файловая система внутри контейнера временная и удаляется вместе с ним. Чтобы данные переживали обновления и перезапуски, хранилищу нужен внешний том (*volume*), а при запуске под `nonroot` важно ещё и не упереться в права доступа к каталогу.

## Сборка образа и запуск с пробросом порта и тома

Из каталога `project/` (где лежит `go.mod`) образ собирается одной командой (конкретный вывод шагов сборки зависит от версии Docker):

```bash
docker build -f final/Dockerfile -t bookmarkflow:vol1 .
```

Обратите внимание: флаг `-f final/Dockerfile` указывает путь к рецепту сборки, а точка `.` в конце задаёт **корень контекста** — каталог `project/`, чтобы Docker увидел и `go.mod`, и папку `final/`.

Теперь запускаем контейнер с пробросом порта и подключённым томом для каталога `/data`:

```bash
docker run --rm -p 8080:8080 \
  -v bookmarkflow-data:/data \
  -e BOOKMARKFLOW_CHECK_WORKERS=8 \
  --name bookmarkflow \
  bookmarkflow:vol1
```

Разберём четыре флага запуска:

1. **`-p 8080:8080`** — пробрасывает порт `8080` вашего компьютера на порт `8080` внутри контейнера. Заметьте важную связку с Модулем 5: в `Dockerfile` задано `BOOKMARKFLOW_ADDR=":8080"` (эквивалент `0.0.0.0:8080`, то есть слушать на всех интерфейсах контейнера). Если бы мы указали `127.0.0.1:8080`, сервис принимал бы запросы только *внутри* контейнера и был бы недоступен снаружи через `-p`!
2. **`-v bookmarkflow-data:/data`** — монтирует именованный том Docker в каталог `/data`, где лежит файл `BOOKMARKFLOW_DATA_FILE="/data/bookmarks.json"`. При остановке и новом старте контейнера все сохранённые закладки останутся на месте.
3. **`-e BOOKMARKFLOW_CHECK_WORKERS=8`** — переопределяет настройку воркеров через переменную окружения прямо на этапе запуска без пересборки образа.
4. **`--rm`** — автоматически удаляет остановленный контейнер (но **не** именованный том `bookmarkflow-data`).

Если у вас нет установленного Docker под рукой, ту же проверку один в один можно запустить локально собранным бинарником из `project/`:
```bash
BOOKMARKFLOW_ADDR="127.0.0.1:8080" BOOKMARKFLOW_DATA_FILE="/tmp/bookmarks.json" go run ./final/cmd/bookmarkflow
```

## Полный сценарий проверки API командами `curl`

В [[13. Диагностика сети в терминале — curl, dig, ss и nc]] мы уже использовали `curl` для просмотра заголовков и тел HTTP-ответов. Ниже приведены реальные команды и живые ответы работающего `BookmarkFlow`:

**1. Проверка здоровья и заголовка `X-Request-Id`:**
```bash
curl -si http://127.0.0.1:8080/healthz
```
```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
X-Request-Id: req-1
Date: Mon, 23 Nov 2026 16:03:57 GMT
Content-Length: 16

{"status":"ok"}
```

**2. Создание закладки (`POST`, ожидаем `201 Created` и нормализацию тегов):**
```bash
curl -si -X POST http://127.0.0.1:8080/api/v1/bookmarks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Go Docs","url":"https://go.dev/doc","tags":["Go","docs"]}'
```
```http
HTTP/1.1 201 Created
Content-Type: application/json; charset=utf-8
X-Request-Id: req-2
Date: Mon, 23 Nov 2026 16:03:57 GMT
Content-Length: 147

{"id":1,"title":"Go Docs","url":"https://go.dev/doc","tags":["docs","go"],"created_at":"2026-11-23T16:03:57Z","updated_at":"2026-11-23T16:03:57Z"}
```

**3. Список с фильтром по тегу и обновление (`GET` и `PUT`):**
```bash
curl -si "http://127.0.0.1:8080/api/v1/bookmarks?tag=go"
curl -si -X PUT http://127.0.0.1:8080/api/v1/bookmarks/1 \
  -H 'Content-Type: application/json' \
  -d '{"title":"Official Go Docs","url":"https://go.dev/doc","tags":["go","ref"]}'
```
Второй запрос вернёт `200 OK` с обновлённым `title` и сохранившимся `created_at`:
```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
X-Request-Id: req-5
Date: Mon, 23 Nov 2026 16:03:57 GMT
Content-Length: 155

{"id":1,"title":"Official Go Docs","url":"https://go.dev/doc","tags":["go","ref"],"created_at":"2026-11-23T16:03:57Z","updated_at":"2026-11-23T16:03:57Z"}
```

**4. Проверка обработки ошибок (`400`, `422`, `404`) и удаление (`204`):**
```bash
curl -si -X POST http://127.0.0.1:8080/api/v1/bookmarks -d '{"title":'
# HTTP/1.1 400 Bad Request -> {"error":"некорректный JSON в теле запроса"}

curl -si -X POST http://127.0.0.1:8080/api/v1/bookmarks -d '{"title":"Bad","url":"ftp://go.dev"}'
# HTTP/1.1 422 Unprocessable Entity -> {"error":"ошибка валидации: укажите корректный http(s) URL"}

curl -si http://127.0.0.1:8080/api/v1/bookmarks/999
# HTTP/1.1 404 Not Found -> {"error":"закладка не найдена: #999"}

curl -si -X DELETE http://127.0.0.1:8080/api/v1/bookmarks/1
# HTTP/1.1 204 No Content (пустое тело)
```

И конечно, вы можете проверить доступность всех сохранённых ссылок командой `curl -si -X POST http://127.0.0.1:8080/api/v1/bookmarks/check`, а при нажатии `Ctrl+C` (или `docker stop bookmarkflow`) сервер выполнит `Graceful Shutdown`.

## Подводный камень: права пользователя `nonroot` на каталог `/data`

Обратите внимание на возможную ловушку при использовании bind-монтирования папки с хоста вида `-v $(pwd)/my-data:/data` под `USER nonroot:nonroot` (UID `65532`):

- Именованный том Docker (`-v bookmarkflow-data:/data`) создаётся самим Docker так, что процесс внутри получает доступ на запись.
- А вот если примонтировать существующий локальный каталог с вашего ноутбука (`-v ./my-data:/data`), у которого владелец — ваш пользователь (UID `1000`) и права `0755`, то пользователь `nonroot` (`65532`) **не сможет** создать в `/data` временный файл `.bookmarkflow-*.tmp` и получит `permission denied` при первом же `POST`. Решение простое: заранее создать каталог и разрешить запись (или сменить владельца на `65532`).

> [!check] Проверь понимание
> Что увидит клиент, если при запуске контейнера с флагом `-p 8080:8080` переопределить адрес на `-e BOOKMARKFLOW_ADDR="127.0.0.1:8080"`?
>
> Сервер внутри контейнера начнёт слушать только внутренний интерфейс обратной петли `127.0.0.1` самого контейнера. Запросы с хоста через проброшенный порт `-p 8080:8080` не смогут достучаться до сервера (клиент получит сброс соединения или пустой ответ). Внутри контейнера нужно слушать на всех интерфейсах — `":8080"`.

## Практика

**Упражнение 1 (Базовое). Выбор флагов `curl` для отладки.**  
Вы хотите отправить `POST` на `/api/v1/bookmarks`, увидеть все заголовки ответа сервера (включая `X-Request-Id`), но не видеть шкалу прогресса `curl` и не добавлять `--verbose` со стрелками `>`/`<`. Какую пару коротких флагов удобно передать в `curl`?

> [!solution] Показать решение
> Флаги `-s` (тихий режим, скрывает полосу прогресса) и `-i` (показать заголовки HTTP-ответа перед телом) — вместе `curl -si ...`. Именно их мы использовали в примерах выше.

**Упражнение 2 (Практическое). Сценарий проверки с сохранением между запусками.**  
Опишите (или выполните локально) минимальный сценарий из четырёх команд, который доказывает, что данные `BookmarkFlow` сохраняются между остановкой и повторным запуском сервера: (1) запуск, (2) создание закладки `POST`, (3) мягкая остановка `SIGTERM`, (4) повторный запуск на том же файле данных и проверка `GET /api/v1/bookmarks/1`.

> [!solution] Показать решение
> ```bash
> go run ./final/cmd/bookmarkflow -addr 127.0.0.1:8080 -data /tmp/persist.json &
> PID=$!
> sleep 0.5
> curl -s -X POST http://127.0.0.1:8080/api/v1/bookmarks \
>   -H 'Content-Type: application/json' -d '{"title":"Go","url":"https://go.dev"}'
> kill -TERM $PID && wait $PID
> go run ./final/cmd/bookmarkflow -addr 127.0.0.1:8080 -data /tmp/persist.json &
> PID=$!
> sleep 0.5
> curl -si http://127.0.0.1:8080/api/v1/bookmarks/1
> kill -TERM $PID && wait $PID
> rm -f /tmp/persist.json
> ```
> Второй запуск возвращает сохранённую закладку `#1` со статусом `200 OK` благодаря атомарному сохранению на диск в `FileStore`.

**Упражнение 3 (Со звёздочкой \*). Проверка `docker build` из корня репозитория vs из `final/`.**  
Почему попытка выполнить `docker build -t bookmarkflow:vol1 final/` из каталога `project/` (то есть передав в качестве контекста подпапку `final/`, а не `.`) немедленно упадёт с ошибкой на шаге `COPY go.mod ./`?

> [!solution] Показать решение
> Контекст сборки Docker изолирован: инструкция `COPY` внутри `Dockerfile` может обращаться только к файлам внутри переданного каталога-контекста (и его подкаталогов), и не имеет права выходить на уровень выше (`../go.mod`). Поскольку `go.mod` лежит в корне `project/`, контекстом сборки обязательно должна быть корневая папка `project/` (`.`), а путь к рецепту передаётся через `-f final/Dockerfile`.
