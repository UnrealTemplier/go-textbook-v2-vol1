*Как идеи инженеров Bell Labs из 1970-х напрямую воплотились в Go: маленькие ортогональные инструменты, потоки `io.Reader` как наследник Unix-конвейеров и продуктивность через удаление лишнего кода.*

> «Пишите ясно — не умничайте.»  
> — Брайан Керниган (совместно с П. Дж. Плоджером, *The Elements of Programming Style*; приводится в *UNIX: A History and a Memoir*)

Чтобы понять характер Go, достаточно взглянуть на биографии его авторов. Когда в 2007 году в Google началась работа над языком, двое из трёх его создателей принесли почти сорок лет опыта из Bell Labs: Кен Томпсон в 1969 году написал первую версию Unix, а позже вместе с Робом Пайком создал систему Plan 9 и кодировку UTF-8. Go не копирует синтаксис Си слепо, но почти каждое его крупное решение продолжает философию Unix.

## Четыре правила Дуга Макилроя в экосистеме Go

В 1978 году руководитель отдела Bell Labs Дуг Макилрой — автор идеи конвейеров (*pipes*) в Unix — сформулировал четыре классических правила:

> «(i) Пусть каждая программа хорошо делает одно дело. Для новой задачи пишите новую программу с нуля, а не усложняйте старую добавлением новых «фич».  
> (ii) Исходите из того, что вывод любой программы станет вводом для другой — пока неизвестной — программы. Не засоряйте вывод лишней информацией. Избегайте жёстко колоночных и бинарных форматов ввода. Не требуйте интерактивного ввода.  
> (iii) Проектируйте и собирайте ПО — даже операционные системы — так, чтобы его можно было опробовать рано, в идеале за считанные недели. Не бойтесь выбрасывать неуклюжие части и переписывать их заново.  
> (iv) Чтобы облегчить задачу программирования, опирайтесь на инструменты, а не на неквалифицированный ручной труд — даже если ради этого придётся отвлечься, написать эти инструменты самому и выбросить часть из них, как только работа будет закончена.»  
> — Дуг Макилрой, предисловие к *Bell Labs Technical Journal on Unix* (1978), цит. по *UNIX: A History and a Memoir*

Все четыре правила узнаются в Go с первого взгляда:

* **(i) Фокусированные единицы.** Инструментарий Go состоит из узких подкоманд (`go build`, `go test`, `go vet`, `go doc`, `gofmt`), а стандартная библиотека разбита на небольшие пакеты (`strings`, `bytes`, `strconv`, `encoding/json`) вместо одного монолита.
* **(ii) Универсальный поток байтов.** В Unix утилиты склеивает поток байтов и конвейер `|` (`cat urls.txt | grep https:// | wc -l`). Внутри Go ту же роль играют `io.Reader` и `io.Writer`: файл `os.File`, буфер `bufio.Reader`, декодер `json.NewDecoder` и ваш фильтр стыкуются без знания друг о друге.
* **(iii) Быстрая проверка гипотез.** Компиляция Go и `go test` занимают доли секунды — переписать неуклюжий узел дешевле, чем годами чинить его костылями.
* **(iv) Инструменты вместо ручной рутины.** `gofmt` форматирует код, `go vet` ловит ошибки спецификаторов `fmt.Printf`, а `go test -cover` считает покрытие.

## Продуктивность через удаление лишнего

В книге *UNIX: A History and a Memoir* Брайан Керниган описывает ещё одну привычку инженеров Bell Labs:

> «О продуктивности программистов иногда судят по числу написанных строк кода; в мире Unix её нередко измеряли числом особых случаев или строк кода, которые удалось удалить.»  
> — Брайан Керниган, *UNIX: A History and a Memoir*

Написать 400 строк с оговорками легко. Труднее найти модель данных, где половина особых случаев исчезает сама. Когда в Модуле 3 мы заменили три параллельных слайса `ids`, `titles`, `urls` на один `[]Bookmark`, целый класс багов с рассинхронизацией индексов перестал существовать.

## Ясный код против «умного» кода

Сравним два решения одной задачи: посчитать непустые строки, начинающиеся с `"https://"`. Сначала «хитроумный» однопроходный разбор байтов вручную:

```go
// «Умный» вариант: трудно проверить глазами, хрупкий на краях строк.
func countHTTPSClever(data []byte) int {
	n, lineStart := 0, true
	for i := 0; i < len(data); i++ {
		if data[i] == '\n' {
			lineStart = true
			continue
		}
		if lineStart && data[i] != ' ' && data[i] != '\t' {
			if i+8 <= len(data) && string(data[i:i+8]) == "https://" {
				n++
			}
			lineStart = false
		}
	}
	return n
}
```

Теперь прямой вариант на стандартных кирпичиках Go (`bufio.Scanner` + `strings`):

```go
package main

import (
	"bufio"
	"fmt"
	"io"
	"strings"
)

func CountHTTPS(r io.Reader) (int, error) {
	scanner := bufio.NewScanner(r)
	count := 0
	for scanner.Scan() {
		line := strings.TrimSpace(scanner.Text())
		if strings.HasPrefix(line, "https://") {
			count++
		}
	}
	if err := scanner.Err(); err != nil {
		return 0, err
	}
	return count, nil
}

func main() {
	input := "  https://go.dev\nhttp://example.com\n\n\thttps://pkg.go.dev\n"
	n, err := CountHTTPS(strings.NewReader(input))
	if err != nil {
		fmt.Println("Ошибка:", err)
		return
	}
	fmt.Println("HTTPS-ссылок:", n)
}
```

Вывод терминала:

```text
HTTPS-ссылок: 2
```

Ясный вариант сразу работает с любым `io.Reader` (включая гигабайтный файл без загрузки целиком в RAM), корректно снимает `\r` и все пробелы Unicode через `strings.TrimSpace` и проверяется глазами за три секунды. В культуре Unix и Go ценят спокойный, прозрачный код, который не подводит ночью.

> [!check] Проверь понимание
> Как второе правило Дуга Макилроя («вывод программы может стать вводом для другой») воплощено в стандартной библиотеке Go?
>
> Через потоковые интерфейсы `io.Reader` и `io.Writer`: файлы, буферы, сканеры и декодеры обмениваются потоками байтов и свободно складываются в цепочки без жёсткой связности.

**Упражнение 1 (Базовое). Конвейер Unix в Go.**  
Сопоставьте три шага команды `cat urls.txt | grep https:// | wc -l` с элементами функции `CountHTTPS`.

> [!solution] Показать решение

**Упражнение 2 (Практическое). Удаляем особые случаи.**  
Уберите лишние ветки `if len(tags) == 0` и `if len(tags) == 1` из функции склейки тегов, переписав её через `strings.Builder` с одним циклом (и укажите однострочную альтернативу из `strings`):

```go
func JoinTags(tags []string) string {
	if len(tags) == 0 {
		return ""
	}
	if len(tags) == 1 {
		return tags[0]
	}
	res := tags[0]
	for i := 1; i < len(tags); i++ {
		res = res + ", " + tags[i]
	}
	return res
}
```

> [!solution] Показать решение
> Однострочно: `return strings.Join(tags, ", ")`. Вручную без лишних веток:
> ```go
> package main
>
> import (
> 	"fmt"
> 	"strings"
> )
>
> func JoinTags(tags []string) string {
> 	var b strings.Builder
> 	for i, tag := range tags {
> 		if i > 0 {
> 			b.WriteString(", ")
> 		}
> 		b.WriteString(tag)
> 	}
> 	return b.String()
> }
>
> func main() {
> 	fmt.Printf("%q | %q | %q\n", JoinTags(nil), JoinTags([]string{"go"}), JoinTags([]string{"go", "unix"}))
> }
> ```
> Условие `if i > 0` одинаково чисто обрабатывает 0, 1 и N элементов.

**Упражнение 3 (Со звёздочкой \*). Дефекты «умного» кода.**  
Назовите два конкретных дефекта `countHTTPSClever`, которых нет в `CountHTTPS`.

> [!solution] Показать решение
> 1. **Память:** `countHTTPSClever` требует весь файл целиком в `[]byte`, тогда как `CountHTTPS` читает поток построчно.
> 2. **Пробелы и `\r\n`:** ручная проверка `!= ' ' && != '\t'` ломается на `\r` и неразрывных пробелах Unicode, сбрасывая `lineStart` и теряя строки; `strings.TrimSpace` снимает их корректно.
