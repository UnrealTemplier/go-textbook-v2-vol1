*Как менять переменные внутри функций, зачем существует встроенная `new(T)` и в каких случаях указатель только мешает.*

В девятом уроке Модуля 2 мы проверили закон Go: все аргументы передаются в функцию **по значению** (*pass by value*). Вызов `tryIncrement(visits)` копировал число `10` в параметр `counter`, увеличивал копию и выбрасывал её при выходе. Исходная переменная `visits` оставалась прежней.

Если нужно вычислить одно новое число, проще вернуть его через `return`. Но как обновить счётчик на месте, вернуть заодно ошибку или не копировать крупный блок данных на каждом вызове?

## Адрес тоже передаётся по значению

Указатели не отменяют правило *pass by value* — в Go нет «передачи по ссылке». Передавая `*int`, вы по-прежнему копируете аргумент, но копируется теперь 8-байтный адрес, а не само значение.

Сравним в памяти два вызова:

```text
1. По значению: resetValue(visits)
Память main()              Память resetValue()
+-------------+            +-------------+
| visits = 10 | --копия--> | n = 10 -> 0 |  (visits всё ещё 10)
+-------------+            +-------------+

2. По указателю: resetPtr(&visits)
Память main()              Память resetPtr()
0xc000018090               +------------------+
+-------------+ <----------| n = 0xc000018090 |  (*n = 0 меняет visits)
| visits = 10 |            +------------------+
+-------------+
```

Параметр `n` в `resetPtr` — локальная копия адреса `0xc000018090`. Запись `*n = 0` («положить ноль по адресу `n`») попадает прямо в переменную `visits` внутри `main`. При этом переприсваивание самого параметра `n = nil` изменит лишь локальную копию внутри функции.

## Встроенная функция `new(T)`

Кроме `&x`, в Go есть встроенная функция **`new(T)`**. Она выделяет безымянную переменную типа `T`, заполняет её нулевым значением и возвращает её адрес `*T`:

```go
p := new(int) // тип *int, *p == 0, p != nil
*p = 8080
```

Это точный эквивалент двух строк `var v int; p := &v`. В реальном Go `new(T)` используют редко (обычно берут `&x` или составной литерал структуры), но она удобна, когда нужен непустой указатель на нулевое базовое значение — например, флаг `new(bool)`.

## Рабочий код: мутация на месте и чистая функция рядом

Напишем две функции с `*T` (выдача ID для `BookmarkFlow` и списание комиссии в копейках) и рядом чистую функцию форматирования по значению:

```go
package main

import (
	"errors"
	"fmt"
)

var (
	ErrNilPointer       = errors.New("передан пустой указатель")
	ErrInsufficientFund = errors.New("недостаточно средств")
)

func allocateID(nextID *int) (int, error) {
	if nextID == nil {
		return 0, ErrNilPointer
	}
	id := *nextID
	*nextID++
	return id, nil
}

func chargeFee(balanceKopecks *int64, fee int64) error {
	if balanceKopecks == nil {
		return ErrNilPointer
	}
	if fee < 0 || *balanceKopecks < fee {
		return fmt.Errorf("%w: баланс %d, комиссия %d", ErrInsufficientFund, *balanceKopecks, fee)
	}
	*balanceKopecks -= fee
	return nil
}

func formatRubles(kopecks int64) string {
	return fmt.Sprintf("%d.%02d руб.", kopecks/100, kopecks%100)
}

func main() {
	seq := 1
	id1, _ := allocateID(&seq)
	id2, _ := allocateID(&seq)
	fmt.Printf("ID: #%d, #%d; следующий: #%d\n", id1, id2, seq)

	balance := int64(5000)
	if err := chargeFee(&balance, 1250); err != nil {
		fmt.Println("ошибка:", err)
		return
	}
	fmt.Println("остаток:", formatRubles(balance))

	if err := chargeFee(nil, 100); err != nil {
		fmt.Println("проверка nil:", err)
	}
}
```

Вывод терминала:

```text
ID: #1, #2; следующий: #3
остаток: 37.50 руб.
проверка nil: передан пустой указатель
```

Обе функции с `*T` проверяют `nil` в первой же строке и возвращают обычную ошибку вместо паники. А `formatRubles` принимает `int64` по значению: она ничего не меняет и только вычисляет строку.

## Когда указатель НЕ нужен

Узнав про `*T`, легко впасть в крайность и ставить звёздочки везде (`*string`, `*int`, `*bool`). Не делайте так. Указатель добавляет переход по адресу, проверки на `nil` и риск неожиданной мутации.

Указатель **не нужен** в трёх частых случаях:

1. **Маленькие базовые типы (`int`, `int64`, `float64`, `bool`).** Сам указатель занимает 8 байтов — столько же, сколько `int64`, и в 8 раз больше `bool`. Передача `*int` ничего не экономит. Если мутация на месте не нужна, принимайте и возвращайте значение.
2. **Строки (`string`).** Передача строки в 5 мегабайт по значению **не копирует** 5 мегабайт. Неизменяемая строка Go хранится как крошечный 16-байтный заголовок (адрес байтов + длина), копируется только он. Указатель `*string` нужен лишь в редких случаях, когда требуется отличить «поле не задано» (`nil`) от пустой строки `""`.
3. **Слайсы и мапы** (уроки 4–6): их заголовки уже содержат внутренний указатель на данные.

Выбирайте `*T` только по делу: когда функция обязана изменить переменную вызывающего кода, когда важно отличить отсутствие значения (`nil`) от нуля, или чтобы не копировать крупный массив либо большую структуру.

## Подводный камень: переприсваивание копии указателя

Частая ошибка — пытаться «проинициализировать» `nil`-указатель внутри функции:

```go
func initPort(p *int) {
	if p == nil {
		v := 8080
		p = &v // меняет ТОЛЬКО локальную копию p
	}
}
```

Если в `main` передать `var port *int`, после вызова `initPort(port)` переменная `port` останется `nil`: изменилась только локальная копия параметра `p`.

> [!check] Проверь понимание
> Что напечатает программа?
> ```go
> func redirect(p *int)  { x := 99; p = &x }
> func overwrite(p *int) { *p = 99 }
> func main() {
> 	n := 10
> 	redirect(&n)
> 	fmt.Println(n)
> 	overwrite(&n)
> 	fmt.Println(n)
> }
> ```
>
> Сначала `10`, потом `99`. `redirect` переписывает локальный параметр `p`, не трогая `n`; `overwrite` пишет прямо по адресу переменной `n`.

## Практика

**Упражнение 1 (Базовое). Обмен значений `swap`.**  
Напишите `swap(a, b *int)`, меняющую местами два `int`. Если любой из указателей равен `nil`, функция ничего не делает. Проверьте на `primary := 8080`, `backup := 8443`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func swap(a, b *int) {
> 	if a == nil || b == nil {
> 		return
> 	}
> 	*a, *b = *b, *a
> }
>
> func main() {
> 	primary, backup := 8080, 8443
> 	swap(&primary, &backup)
> 	fmt.Println(primary, backup) // 8443 8080
> 	swap(&primary, nil)
> }
> ```
> Параллельное присваивание `*a, *b = *b, *a` обходится без временной переменной.

**Упражнение 2 (Практическое). Ограничение на месте.**  
Реализуйте `func clampInPlace(val *int, minVal, maxVal int) bool`: ограничивает `*val` отрезком `[minVal, maxVal]` и возвращает `true`, если значение изменилось (иначе `false`, в том числе при `val == nil`). Проверьте на `-5`, `50`, `120` для `[0, 100]`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func clampInPlace(val *int, minVal, maxVal int) bool {
> 	if val == nil {
> 		return false
> 	}
> 	if *val < minVal {
> 		*val = minVal
> 		return true
> 	}
> 	if *val > maxVal {
> 		*val = maxVal
> 		return true
> 	}
> 	return false
> }
>
> func main() {
> 	a, b, c := -5, 50, 120
> 	fmt.Println(clampInPlace(&a, 0, 100), a) // true 0
> 	fmt.Println(clampInPlace(&b, 0, 100), b) // false 50
> 	fmt.Println(clampInPlace(&c, 0, 100), c) // true 100
> }
> ```
> Сигнатура честна: `val` передан по указателю ради мутации, границы `minVal` и `maxVal` — по значению.

**Упражнение 3 (Со звёздочкой \*). Объясни почему и перепиши.**  
Почему после `var cfg *int; applyDefaultPort(cfg)` переменная `cfg` остаётся `nil`, и как переписать логику проще с сигнатурой `func resolvePort(port *int) int`?
```go
func applyDefaultPort(port *int) {
	if port == nil {
		p := new(int)
		*p = 8080
		port = p
	}
}
```

> [!solution] Показать решение
> Указатель `port` передаётся по значению: строка `port = p` меняет лишь локальную копию внутри функции, а `cfg` снаружи остаётся `nil`.
>
> Идиоматично вернуть готовое значение:
> ```go
> func resolvePort(port *int) int {
> 	if port == nil {
> 		return 8080
> 	}
> 	return *port
> }
> ```
> Такой код короче и гарантирует валидный номер порта без двойных указателей.
