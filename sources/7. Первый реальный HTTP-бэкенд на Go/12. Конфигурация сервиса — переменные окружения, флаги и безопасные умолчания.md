*Проектируем конфигурацию веб-сервиса по схеме «безопасные умолчания → переменные окружения → флаги командной строки» и разбираем компромисс между фолбэком и строгим отказом при старте.*

Пока вы запускаете сервер на своём ноутбуке, порт `:8080` и путь `bookmarks.json` можно вписать прямо в `main()`. Но стоит перенести бинарник на сервер соседа или в контейнер, как оказывается, что порт `8080` там занят другим процессом, а файл данных обязан лежать в каталоге `/data/bookmarks.json`. Перекомпилировать программу ради смены порта — плохая практика: **один и тот же собранный бинарник должен настраиваться снаружи перед запуском**.

В [[8. Переменные окружения ENV и рабочий каталог процесса]] и [[6. Флаги командной строки flag и встроенные ресурсы embed]] мы уже разбирали оба механизма по отдельности. В веб-бэкендах их соединяют в предсказуемую иерархию приоритетов.

## Приоритет источников: умолчания → ENV → флаги

В `BookmarkFlow` настройки собираются в три шага — от самого общего уровня к самому конкретному:

```text
1. Безопасные значения по умолчанию (в коде)
        │  перекрываются
        ▼
2. Переменные окружения (BOOKMARKFLOW_*)   ← удобно в контейнерах и на сервере
        │  перекрываются
        ▼
3. Флаги командной строки (-addr, -data)   ← удобно при ручном локальном запуске
```

Посмотрим, как эта цепочка реализована в `project/final/config.go` и `project/final/cmd/bookmarkflow/main.go`. Сначала `ConfigFromEnv()` заполняет структуру `Config` из окружения:

```go
type Config struct {
	Addr            string
	DataFile        string
	CheckWorkers    int
	ShutdownTimeout time.Duration
}

func ConfigFromEnv() Config {
	cfg := Config{
		Addr:            envOrDefault("BOOKMARKFLOW_ADDR", ":8080"),
		DataFile:        envOrDefault("BOOKMARKFLOW_DATA_FILE", "bookmarks.json"),
		CheckWorkers:    4,
		ShutdownTimeout: 5 * time.Second,
	}
	if raw := os.Getenv("BOOKMARKFLOW_CHECK_WORKERS"); raw != "" {
		if n, err := strconv.Atoi(raw); err == nil && n > 0 {
			cfg.CheckWorkers = n
		}
	}
	if raw := os.Getenv("BOOKMARKFLOW_SHUTDOWN_TIMEOUT"); raw != "" {
		if d, err := time.ParseDuration(raw); err == nil && d > 0 {
			cfg.ShutdownTimeout = d
		}
	}
	return cfg
}
```

А в первых строках `main()` мы передаём уже заполненные поля `cfg` в качестве «значений по умолчанию» для пакета `flag`:

```go
	cfg := bookmarkflow.ConfigFromEnv()
	flag.StringVar(&cfg.Addr, "addr", cfg.Addr, "HTTP listen address")
	flag.StringVar(&cfg.DataFile, "data", cfg.DataFile, "path to JSON bookmarks file")
	flag.IntVar(&cfg.CheckWorkers, "workers", cfg.CheckWorkers, "concurrent link-check workers")
	flag.Parse()
```

Смотрите, как элегантно сработала эта связка:

- Если ничего не задавать, сервис стартанёт на `:8080` с файлом `bookmarks.json` и 4 воркерами.
- Если в системе задана переменная `BOOKMARKFLOW_ADDR=":9090"`, `ConfigFromEnv()` подхватит `:9090`, и даже без флагов сервер откроет порт `9090`.
- Если при наличии `BOOKMARKFLOW_ADDR=":9090"` вы запустите бинарник с флагом `-addr 127.0.0.1:18080`, `flag.Parse()` перезапишет значение поверх переменной окружения.

## Почему секреты и настройки не хранят в коде

Три правила гигиены конфигурации, которые сэкономят вам недели отладки:

1. **Единый префикс для переменных (`BOOKMARKFLOW_*`).** В окружении процесса живут десятки системных переменных вроде `` `$PATH` ``, `` `$HOME` `` и `` `$USER` ``. Если назвать свою переменную просто `PORT` или `WORKERS`, она легко столкнётся с переменной сторонней утилиты или самого хостинга. Префикс `BOOKMARKFLOW_` гарантирует изоляцию.
2. **Человекочитаемые длительности через `time.ParseDuration`.** Вместо загадочного числа `BOOKMARKFLOW_SHUTDOWN_TIMEOUT="5000"` (миллисекунды? секунды?) используйте явные единицы `"5s"` или `"1500ms"`.
3. **Никаких паролей и токенов в Git.** Сейчас у `BookmarkFlow` нет секретных ключей, но как только в Томах 2–3 появятся строки подключения и ключи подписи, их передают через переменные окружения (или защищённые хранилища секретов), но никогда не коммитят в исходники.

## Подводный камень: тихий фолбэк против падения при старте (*fail-fast*)

Присмотритесь внимательно к проверке внутри `ConfigFromEnv()`:

```go
	if raw := os.Getenv("BOOKMARKFLOW_CHECK_WORKERS"); raw != "" {
		if n, err := strconv.Atoi(raw); err == nil && n > 0 {
			cfg.CheckWorkers = n
		}
	}
```

Если администратор случайно опечатался и задал `BOOKMARKFLOW_CHECK_WORKERS="abc"` или `"0"`, текущая функция тихо проигнорирует неверное значение и оставит `4`. Для учебного сервиса это удобный безопасный фолбэк: программа хотя бы запустится.

Но в боевых системах часто выбирают противоположную стратегию — **быстрый отказ при старте (*fail-fast*)**. Представьте, что кто-то опечатался в имени переменной или значении таймаута `BOOKMARKFLOW_SHUTDOWN_TIMEOUT="5сек"` (по-русски вместо `"5s"`). Тихо подставив умолчание, сервис молча проработает с неверной настройкой, и проблему заметят лишь при реальном инциденте. Поэтому в зрелых проектах `LoadConfig() (Config, error)` возвращает явную ошибку при невалидном значении, чтобы процесс упал в первые 5 миллисекунд деплоя с понятным сообщением в лог.

> [!check] Проверь понимание
> Что выберет `BookmarkFlow`, если одновременно задать переменную окружения `BOOKMARKFLOW_DATA_FILE="/tmp/env.json"` и запустить команду `bookmarkflow -data /tmp/flag.json`?
>
> Сервер откроет файл `/tmp/flag.json`: `ConfigFromEnv()` сначала запишет в `cfg.DataFile` значение из окружения, а `flag.Parse()` перезапишет его значением явного флага `-data`.

## Практика

**Упражнение 1 (Базовое). Трассировка `ConfigFromEnv`.**  
Какими окажутся все четыре поля `Config`, если окружение содержит только `BOOKMARKFLOW_CHECK_WORKERS="-3"` и `BOOKMARKFLOW_SHUTDOWN_TIMEOUT="2m"`?

> [!solution] Показать решение
> - `Addr`: `":8080"` (значение по умолчанию);
> - `DataFile`: `"bookmarks.json"` (значение по умолчанию);
> - `CheckWorkers`: `4` (строка `"-3"` распарсилась, но не прошла условие `n > 0`, осталось умолчание);
> - `ShutdownTimeout`: `2 * time.Minute` (`time.ParseDuration("2m")` сработал успешно).

**Упражнение 2 (Практическое). Строгий `LoadConfigStrict() (Config, error)`.**  
Перепишите чтение `BOOKMARKFLOW_CHECK_WORKERS` и `BOOKMARKFLOW_SHUTDOWN_TIMEOUT` в виде функции `LoadConfigStrict() (Config, error)`, которая не проглатывает невалидные непустые переменные, а возвращает понятную ошибку с именем переменной.

> [!solution] Показать решение
> ```go
> func LoadConfigStrict() (Config, error) {
> 	cfg := Config{
> 		Addr:            envOrDefault("BOOKMARKFLOW_ADDR", ":8080"),
> 		DataFile:        envOrDefault("BOOKMARKFLOW_DATA_FILE", "bookmarks.json"),
> 		CheckWorkers:    4,
> 		ShutdownTimeout: 5 * time.Second,
> 	}
> 	if raw := os.Getenv("BOOKMARKFLOW_CHECK_WORKERS"); raw != "" {
> 		n, err := strconv.Atoi(raw)
> 		if err != nil || n <= 0 {
> 			return Config{}, fmt.Errorf("BOOKMARKFLOW_CHECK_WORKERS=%q: ожидается целое число > 0", raw)
> 		}
> 		cfg.CheckWorkers = n
> 	}
> 	if raw := os.Getenv("BOOKMARKFLOW_SHUTDOWN_TIMEOUT"); raw != "" {
> 		d, err := time.ParseDuration(raw)
> 		if err != nil || d <= 0 {
> 			return Config{}, fmt.Errorf("BOOKMARKFLOW_SHUTDOWN_TIMEOUT=%q: ожидается длительность > 0", raw)
> 		}
> 		cfg.ShutdownTimeout = d
> 	}
> 	return cfg, nil
> }
> ```
> Теперь опечатка в конфигурации сразу видна при запуске и не маскируется под «работающий по умолчанию» сервис.

**Упражнение 3 (Со звёздочкой \*). Проверка `flag.Visit` или пустой строки в окружении.**  
Обратите внимание на вспомогательную функцию из `config.go`:
```go
func envOrDefault(key, fallback string) string {
	if v := os.Getenv(key); v != "" {
		return v
	}
	return fallback
}
```
Почему здесь использовали `os.Getenv`, а не `os.LookupEnv`? В чём практическая разница между ситуациями, когда переменная не задана вообще и когда ей присвоена пустая строка `BOOKMARKFLOW_ADDR=""`?

> [!solution] Показать решение
> `os.Getenv` не различает «переменная отсутствует» и «переменная задана как пустая строка `""`». Для `BOOKMARKFLOW_ADDR` это плюс: если шаблон развёртывания подставил пустую переменную `BOOKMARKFLOW_ADDR=""`, `envOrDefault` подхватит безопасное `":8080"` вместо невалидного пустого адреса. Напротив, в ситуациях, где пустая строка означает «явно отключить функцию» (например, пустой путь к файлу логов), используют `v, ok := os.LookupEnv(key)`, чтобы отличить отсутствие настройки от явного пустого значения.
