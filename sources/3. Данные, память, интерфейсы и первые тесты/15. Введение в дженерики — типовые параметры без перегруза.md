*Как типовые параметры избавляют от копипаста алгоритмов для разных типов, что дают ограничения `comparable` и `cmp.Ordered` и когда лучше остаться на обычной функции или интерфейсе.*

В `BookmarkFlow` нужно проверить, есть ли тег в `[]string`, а рядом — есть ли идентификатор в `[]int` или сумма в `[]int64`. Без дженериков выбор сводился к двум плохим вариантам:

```go
func ContainsString(items []string, target string) bool { /* ... */ }
func ContainsInt(items []int, target int) bool          { /* ... */ }
func MinInt(a, b int) int                               { /* ... */ }
func MinFloat(a, b float64) float64                     { /* ... */ }
```

Либо множить функции-близнецы, отличающиеся только типом, либо переходить на `[]any` и терять проверку типов при компиляции.

## Типовые параметры и ограничение `comparable`

С Go 1.18 функции и типы принимают **типовые параметры** (*type parameters*) в квадратных скобках после имени:

```go
func Contains[T comparable](items []T, target T) bool {
	for _, item := range items {
		if item == target {
			return true
		}
	}
	return false
}
```

Здесь `T` — типовой параметр, а **`comparable`** — **ограничение типа** (*type constraint*). Оно гарантирует компилятору, что значения `T` поддерживают `==` и `!=` (числа, строки, `bool`, указатели и сравнимые структуры, но не слайсы и не мапы).

Если написать `[T any]`, компилятор остановит сборку на `item == target`:

```text
invalid operation: item == target (incomparable types in type set)
```

При вызове указывать тип в скобках обычно не нужно — работает **вывод типов**:

```go
Contains([]string{"go", "cli"}, "cli") // T = string
Contains([]int{10, 20, 30}, 25)        // T = int
```

## Упорядоченные типы: `cmp.Ordered`, `min`/`max` и пакеты `slices`/`maps`

Для `<` и `>` одного `comparable` мало — нельзя спросить, меньше ли `true`, чем `false`. Стандартный пакет `cmp` даёт ограничение **`cmp.Ordered`** (все целые, числа с плавающей точкой и строки). С ним легко написать зажатие в диапазон `Clamp[T cmp.Ordered](val, low, high T) T`.

А писать свои `MinInt` и `MinFloat` больше не нужно: с Go 1.21 в язык встроены **`min`** и **`max`** для любых упорядоченных типов:

```go
lowest := min(1200, 950, 1400)      // 950
latest := max("2025-01", "2026-03") // "2026-03"
```

Хорошая практика Go: прежде чем писать свой `Contains`, `Sort` или клонирование мапы, проверьте стандартные пакеты **`slices`**, **`maps`** и **`cmp`**. Они построены на тех же типовых параметрах и закрывают большинство задач с коллекциями (подробнее разберём их в Модуле 4).

## Своя обобщённая функция: `Filter`

Типовые параметры особенно полезны для небольших помощников над слайсами. Напишем `Filter[T any]` и применим её к закладкам и суммам в копейках:

```go
package main

import (
	"cmp"
	"fmt"
	"slices"
)

type Bookmark struct {
	ID    int
	Title string
	Tags  []string
}

func Filter[T any](items []T, keep func(T) bool) []T {
	result := make([]T, 0)
	for _, item := range items {
		if keep(item) {
			result = append(result, item)
		}
	}
	return result
}

func Clamp[T cmp.Ordered](val, low, high T) T {
	if val < low {
		return low
	}
	if val > high {
		return high
	}
	return val
}

func main() {
	bookmarks := []Bookmark{
		{ID: 1, Title: "Go Spec", Tags: []string{"go", "docs"}},
		{ID: 2, Title: "Git Book", Tags: []string{"git"}},
		{ID: 3, Title: "Go Blog", Tags: []string{"go", "news"}},
	}

	goOnly := Filter(bookmarks, func(b Bookmark) bool {
		return slices.Contains(b.Tags, "go")
	})
	fmt.Println("Закладок с тегом go:", len(goOnly))

	prices := []int64{450, 1200, 2900, 800}
	expensive := Filter(prices, func(p int64) bool { return p >= 1000 })
	fmt.Println("Дороже 10 RUB (в коп.):", expensive)

	fmt.Println("Лимит:", Clamp(150, 1, 100), "минимум:", min(450, 1200, 800))
}
```

Вывод:

```text
Закладок с тегом go: 2
Дороже 10 RUB (в коп.): [1200 2900]
Лимит: 100 минимум: 450
```

В `Filter[T any]` ограничение `any` уместно: сама функция не сравнивает элементы, всю логику задаёт колбэк `keep`. Внутри `keep` мы вызвали стандартную `slices.Contains` вместо ручного цикла.

*(Примечание: компилятор Go генерирует эффективный машинный код для семейств типов, не раздувая бинарник под каждый тип отдельно; детали компиляции дженериков разберём в Томе 5.)*

## Нулевое значение типа `T`

Если обобщённая функция возвращает `(T, bool)` и элемент не найден, написать `return nil, false` нельзя — для `int` или `string` значения `nil` нет. Используют простую идиому:

```go
var zero T
return zero, false
```

Компилятор подставит правильное нулевое значение для любого `T`: `0`, `""`, пустую структуру или `nil`.

## Когда дженерики нужны, а когда мешают

Не превращайте каждую функцию в дженерик «на будущее» — это ухудшает читаемость:

| Задача | Инструмент | Пример |
|---|---|---|
| Один алгоритм для разных типов данных | **Дженерики** | `Filter[T]`, `slices.Contains`, `Clamp[T]` |
| Разное поведение за общим контрактом | **Интерфейс** | `BookmarkStore`, `Notifier`, `error` |
| Логика для одного конкретного типа | **Обычная функция** | `ValidateBookmark(b Bookmark) error` |

Начинайте с обычных функций. Выносите типовой параметр только тогда, когда реально столкнулись с дублированием кода для двух и более типов.

> [!check] Проверь понимание
> Скомпилируется ли вызов `Contains([][]string{{"go"}}, []string{"go"})` для `func Contains[T comparable](items []T, target T) bool`?
>
> Нет. Компилятор сообщит `[]string does not satisfy comparable`: слайсы нельзя сравнивать оператором `==`.

## Практика

**Упражнение 1 (Базовое). Что сломается?**  
Почему не скомпилируется `func Equal[T any](a, b T) bool { return a == b }` и какое минимальное изменение исправит её для чисел и строк, но по-прежнему запретит мапы?

> [!solution] Показать решение
> `any` не гарантирует поддержку `==` (`incomparable types in type set`). Замените ограничение на `comparable`:
> ```go
> func Equal[T comparable](a, b T) bool { return a == b }
> ```
> Числа, строки и сравнимые структуры пройдут, а мапы и слайсы компилятор отклонит.

**Упражнение 2 (Практическое). Преобразование `MapSlice`.**  
Напишите `MapSlice[In any, Out any](items []In, fn func(In) Out) []Out` и в `main()` преобразуйте слайс `[]Bookmark` в `[]string` заголовков, а `[]int64` (копейки) — в строки вида `"12.50 RUB"`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> type Bookmark struct {
> 	ID    int
> 	Title string
> }
>
> func MapSlice[In any, Out any](items []In, fn func(In) Out) []Out {
> 	out := make([]Out, len(items))
> 	for i, item := range items {
> 		out[i] = fn(item)
> 	}
> 	return out
> }
>
> func main() {
> 	bookmarks := []Bookmark{{ID: 1, Title: "Go Spec"}, {ID: 2, Title: "Go Tour"}}
> 	fmt.Println(MapSlice(bookmarks, func(b Bookmark) string { return b.Title }))
>
> 	prices := []int64{1250, 500}
> 	fmt.Println(MapSlice(prices, func(k int64) string {
> 		return fmt.Sprintf("%d.%02d RUB", k/100, k%100)
> 	}))
> }
> ```
> `make([]Out, len(items))` сразу выделяет слайс нужной длины без лишних переаллокаций.

**Упражнение 3 (Со звёздочкой \*). Поиск первого совпадения.**  
Напишите `FirstMatch[T any](items []T, match func(T) bool) (T, bool)`, возвращающую первый подходящий элемент и `true`, либо нулевое значение `T` и `false`. Объясните, зачем здесь `var zero T`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func FirstMatch[T any](items []T, match func(T) bool) (T, bool) {
> 	for _, item := range items {
> 		if match(item) {
> 			return item, true
> 		}
> 	}
> 	var zero T
> 	return zero, false
> }
>
> func main() {
> 	nums := []int{3, 7, 12, 18}
> 	fmt.Println(FirstMatch(nums, func(n int) bool { return n > 10 }))  // Вывод: 12 true
> 	fmt.Println(FirstMatch(nums, func(n int) bool { return n > 100 })) // Вывод: 0 false
> }
> ```
> `nil` не существует для чисел, строк и структур, поэтому `var zero T` — единственный универсальный способ вернуть нулевое значение любого типа `T`.
