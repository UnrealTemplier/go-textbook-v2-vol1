## Что именно оптимизирует Go

Каждая сильная сторона Go оплачена осознанным отказом:

* **Мгновенная компиляция в один автономный бинарник** — оплачена отказом от тяжёлых макросов и сложного вывода типов при сборке.
* **Безопасность памяти и простой код** — оплачены сборщиком мусора (GC), что добавляет накладные расходы и микропаузы, неприемлемые в жёстких системах реального времени.
* **Лёгкое чтение чужого кода в большой команде** — оплачено отказом от алгебраических типов-сумм (`enum` с данными), сопоставления с образцом и перегрузки операторов.
* **Встроенная модель конкурентности** — один из главных козырей Go для серверов, к которому мы переходим сразу после этого эссе.

## Матрица компромиссов

| Критерий | Go | C / Rust | Python | Java / C# | TypeScript |
|---|---|---|---|---|---|
| **Скорость и RAM** | Быстрый, скромная RAM, есть GC | Максимум скорости, ручная память или владение, без GC | Медленный CPU, заметная RAM | Быстрый в долгой работе, тяжёлый старт и VM | Хорошая скорость на V8, заметная RAM |
| **Сборка и доставка** | Доли секунды → один файл | Быстрая (C) / долгая (Rust) → нативный бинарник | Без сборки, но нужен интерпретатор и окружение | Байт-код + установленная виртуальная машина | Транспиляция в JS + Node/Bun или браузер |
| **Типы** | Строгие и простые, без типов-сумм | Слабые (C) / очень богатые (Rust) | Динамические (проверка внешними линтерами) | Богатые ООП-типы и дженерики | Гибкая структурная типизация поверх JS |
| **Порог входа** | Очень низкий | Высокий | Низкий на старте, труднее рефакторить | Средний: много абстракций и фреймворков | Средний |
| **Сильная ниша** | Бэкенды, сетевые сервисы, CLI, облачная инфраструктура | Ядра ОС, драйверы, микроконтроллеры, игровые движки | Наука о данных, ML/AI, скрипты, прототипы | Крупный корпоративный софт и сложный бэкенд | Фронтенд в браузере, fullstack-веб |

## Где Go блистает, а где лучше выбрать другой язык

Go даёт максимальный эффект в трёх областях: **серверные бэкенды и сетевые сервисы**, **консольные утилиты (CLI)** с доставкой одним бинарником на Linux/macOS/Windows и **облачная инфраструктура** (прокси, агенты, балансировщики), которую годами поддерживают большие команды.

При этом зрелый инженер спокойно выберет другой инструмент в пяти ситуациях:

1. **Микроконтроллеры, драйверы и ядра ОС** — где 64 КБ памяти и недопустим сборщик мусора → **C** или **Rust**.
2. **Наука о данных и машинное обучение** — готовая научная экосистема живёт в **Python**.
3. **Интерфейсы в браузере и сложный GUI** — браузер нативно исполняет JS → **TypeScript**.
4. **Задачи, требующие исчерпывающих типов-сумм** (компиляторы, сложные конечные автоматы) → **Rust** или **OCaml/F#**.
5. **Одноразовые скрипты на 30 строк** — **Python** или консольные утилиты быстрее.

## Типичный компромисс Go в коде

В Rust статус задачи описали бы типом-суммой `enum`, и компилятор заставил бы обработать каждый вариант. В Go используют константы `iota`, явный `switch` и ветку `default`:

```go
package main

import (
	"fmt"
	"slices"
)

type Status int

const (
	StatusPending Status = iota
	StatusRunning
	StatusDone
)

func (s Status) String() string {
	switch s {
	case StatusPending:
		return "ожидает"
	case StatusRunning:
		return "выполняется"
	case StatusDone:
		return "готово"
	default:
		return fmt.Sprintf("неизвестно(%d)", int(s))
	}
}

func main() {
	states := []Status{StatusDone, StatusPending, StatusRunning}
	slices.Sort(states)
	for _, st := range states {
		fmt.Println(st)
	}
}
```

Вывод терминала:

```text
ожидает
выполняется
готово
```

Код прозрачен, сортируется через `slices.Sort` и компилируется мгновенно. Цена — компилятор не запретит `Status(99)` и не напомнит о новом статусе в `switch`; за этим следят ветка `default` и простой тест.

> [!check] Проверь понимание
> Назовите одну задачу, где Go — сильный выбор, и одну, где честнее взять C/Rust или Python, указав техническую причину.
>
> Для CLI и сетевых бэкендов Go силён сборкой в один бинарник, строгими типами и экономичной работой с сетью. Для прошивки микроконтроллера без GC лучше C или Rust; для анализа данных и ML — Python с готовой научной экосистемой.

>

> 	"fmt"
> 	"strings"
