*Почему изменение одного слайса способно незаметно испортить другой, как изолировать данные через `copy`, `slices.Clone` и `s[low:high:max]` и зачем нужна функция `clear`.*

Представьте, что в `BookmarkFlow` вы взяли первые два тега закладки как черновик и дописали туда `"security"`:

```go
tags := []string{"go", "cli", "tests", "docs"}
draft := tags[:2]
draft = append(draft, "security")

fmt.Println("draft:", draft) // [go cli security]
fmt.Println("tags: ", tags)  // [go cli security docs] — "tests" исчез!
```

Строка `draft = append(draft, "security")` незаметно переписала `tags[2]`, хотя к `tags` никто не прикасался. Схема заголовка `(ptr, len, cap)` объясняет это без остатка.

## Как рождается алиасинг

Подслайсинг `tags[:2]` **никогда не копирует массив**. Он создаёт новый заголовок с тем же указателем `ptr`, длиной `2` — и **прежней ёмкостью `4`**, унаследованной от базового массива:

```text
tags  (len=4, cap=4)           Базовый массив [4]string
+---------+                    0       1        2        3
| ptr ----+----------------> +------+-------+--------+--------+
+---------+              ^   | "go" | "cli" | "tests"| "docs" |
                         |   +------+-------+--------+--------+
draft (len=2, cap=4)     |                     ^
+---------+              |                     |
| ptr ----+--------------+        append(draft, "security")
+---------+                       пишет сюда, т. к. len=2 < cap=4
```

Ситуацию, когда два слайса разделяют один базовый массив, называют **алиасингом** (*aliasing*). Поскольку `len=2 < cap=4`, `append` положил `"security"` прямо в ячейку `[2]` общего массива поверх `"tests"`. Если бы у `tags` изначально было `cap=2`, `append` переехал бы в новый массив и `tags` уцелел бы. Именно такая зависимость от ёмкости делает алиасинг коварным.

## Четыре инструмента защиты в Go 1.24

### 1. Встроенная функция `copy(dst, src)`

`copy` копирует **`min(len(dst), len(src))`** элементов и возвращает их число. Она не паникует из-за разных длин, но требует, чтобы у `dst` уже была нужная **длина**, а не только ёмкость:

```go
dst := make([]string, len(src)) // именно len, не (0, len)
copy(dst, src)
```

Если передать пустой `var dst []string` с `len == 0`, `copy` молча скопирует `0` элементов.

### 2. Клонирование через `slices.Clone` (Go 1.21+)

Когда нужна независимая копия слайса с собственным массивом, пакет `slices` заменяет ручной `make` + `copy` одной строкой:

```go
draft := slices.Clone(tags[:2]) // свой массив: len=2, cap=2
```

При передаче `nil` функция честно вернёт `nil`.

### 3. Срез с тремя индексами `s[low:high:max]`

Когда копировать данные сразу не хочется, но нужно запретить чужому `append` выходить за границу окна, используют **срез с тремя индексами** `s[low:high:max]`. Третий индекс задаёт потолок ёмкости `cap = max - low`:

```go
draft := tags[:2:2] // len=2, cap=2
```

Запаса ёмкости больше нет (`len == cap`). При первом же `append(draft, "security")` рантайм выделит новый массив, не затронув `tags[2]`. *(Индексы обязаны соблюдать `0 <= low <= high <= max <= cap(s)`, иначе случится паника `slice bounds out of range`.)*

### 4. Встроенная функция `clear` (Go 1.21+)

`clear(s)` записывает нулевое значение типа (`0`, `""`, `nil`) во все элементы от `0` до `len(s)-1`, **сохраняя `len` и `cap`**.

При удалении элемента сдвигом (`copy(items[i:], items[i+1:])`) в последней ячейке массива остаётся старая строка или указатель — сборщик мусора не сможет освободить эти данные, пока жив слайс. Один вызов `clear` на хвостовую ячейку перед укорачиванием решает проблему:

```go
func deleteAt(items []string, idx int) []string {
	copy(items[idx:], items[idx+1:])
	clear(items[len(items)-1:]) // обнуляем «хвост»
	return items[:len(items)-1]
}
```

## Рабочий код: все приёмы вместе

```go
package main

import (
	"fmt"
	"slices"
)

func deleteAt(items []string, idx int) []string {
	copy(items[idx:], items[idx+1:])
	clear(items[len(items)-1:])
	return items[:len(items)-1]
}

func main() {
	base := []string{"go", "cli", "tests", "docs"}

	safeDraft := base[:2:2]
	safeDraft = append(safeDraft, "security")
	fmt.Println("base:     ", base)
	fmt.Println("safeDraft:", safeDraft)

	cloned := slices.Clone(base)
	cloned[0] = "golang"
	fmt.Println("base после правки клона:", base)

	trimmed := deleteAt(slices.Clone(base), 1)
	fmt.Println("после deleteAt(1):      ", trimmed)

	buf := []int{10, 20, 30}
	clear(buf)
	fmt.Printf("после clear: %v (len=%d, cap=%d)\n", buf, len(buf), cap(buf))
}
```

Вывод терминала:

```text
base:      [go cli tests docs]
safeDraft: [go cli security]
base после правки клона: [go cli tests docs]
после deleteAt(1):       [go tests docs]
после clear: [0 0 0] (len=3, cap=3)
```

## Удержание большого массива в памяти

Алиасинг способен и тихо съедать память. Если прочитать 10 МБ файла в `raw := make([]byte, 10<<20)` и вернуть подслайс первых 16 байт `return raw[:16]`, заголовок держит указатель на весь 10-мегабайтный массив. Пока жив маленький подслайс, сборщик мусора не освободит ни байта из 10 МБ.

Лекарство — отцепить нужный кусок копированием: `return slices.Clone(raw[:16])`. Тогда огромный `raw` освободится сразу после возврата из функции.

> [!check] Проверь понимание
> Чем `clear(buf)` отличается от `buf = buf[:0]`?
>
> `clear(buf)` обнуляет элементы, но сохраняет `len` и `cap`. Переприсваивание `buf = buf[:0]` сбрасывает `len` в `0` (сохраняя `cap`), но оставляет старые значения в массиве. Чтобы и стереть данные, и начать запись заново, делают оба шага: `clear(buf); buf = buf[:0]`.

## Практика

**Упражнение 1 (Базовое). Проследи алиасинг.**  
Определите без запуска, что напечатает код:

```go
package main

import "fmt"

func main() {
	orig := []int{10, 20, 30, 40}
	a := orig[:2]
	b := orig[:2:2]

	a = append(a, 99)
	b = append(b, 77)

	fmt.Println("orig:", orig)
	fmt.Println("a:   ", a)
	fmt.Println("b:   ", b)
}
```

> [!solution] Показать решение
> `orig: [10 20 99 40]`, `a: [10 20 99]`, `b: [10 20 77]`. У `a` ёмкость `4`, поэтому `append(a, 99)` перезаписал `orig[2]`. У `b` потолок `cap=2`, поэтому `append(b, 77)` выделил новый массив и не тронул `orig`.

**Упражнение 2 (Практическое). Безопасный префикс.**  
Напишите `extractPrefix(raw []byte, n int) []byte`, возвращающую независимую копию первых `n` байтов без удержания исходного `raw` в памяти. При `n <= 0` или пустом `raw` верните `nil`; при `n > len(raw)` скопируйте весь `raw`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"slices"
> )
>
> func extractPrefix(raw []byte, n int) []byte {
> 	if n <= 0 || len(raw) == 0 {
> 		return nil
> 	}
> 	if n > len(raw) {
> 		n = len(raw)
> 	}
> 	return slices.Clone(raw[:n])
> }
>
> func main() {
> 	raw := []byte("GET /bookmarks HTTP/1.1")
> 	prefix := extractPrefix(raw, 3)
> 	prefix[0] = 'P'
> 	fmt.Printf("prefix=%q, raw=%q\n", prefix, raw)
> }
> ```
> Вывод: `prefix="PET", raw="GET /bookmarks HTTP/1.1"`. `slices.Clone` выделяет ровно `n` байтов нового массива.

**Упражнение 3 (Со звёздочкой \*). Неразрушающее удаление тега.**  
Напишите `removeTag(tags []string, idx int) []string`, удаляющую элемент по индексу `idx`, **не изменяя** исходный слайс `tags`. Если `idx` вне `[0, len(tags))`, верните независимую копию `tags`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"slices"
> )
>
> func removeTag(tags []string, idx int) []string {
> 	if idx < 0 || idx >= len(tags) {
> 		return slices.Clone(tags)
> 	}
> 	out := make([]string, 0, len(tags)-1)
> 	out = append(out, tags[:idx]...)
> 	out = append(out, tags[idx+1:]...)
> 	return out
> }
>
> func main() {
> 	orig := []string{"go", "cli", "tests", "docs"}
> 	next := removeTag(orig, 1)
> 	fmt.Println("orig:", orig) // [go cli tests docs]
> 	fmt.Println("next:", next) // [go tests docs]
> }
> ```
> Новый слайс точной ёмкости `len(tags)-1` полностью изолирован от базового массива `orig`. В отличие от `deleteAt` и `slices.Delete`, исходная версия списка остаётся нетронутой.
