*Как разбить проект на пакеты и модуль `go.mod`, управлять видимостью через регистр букв, защищать внутренний код каталогом `internal/` и не попадать в циклы импортов.*

Пока весь `BookmarkFlow` умещается в 80 строках одного `main.go`, его легко держать в голове. На 600 строках хранение, валидация, форматирование и разбор аргументов терминала сплетаются в один ком, а код вывода начинает лезть прямо во внутренние слайсы хранилища.

В Go для наведения порядка служат две единицы: **пакет** и **модуль**.

## Пакеты и экспорт по регистру букв

**Пакет** (`package`) — все `.go`-файлы в одном каталоге. У всех обычных файлов каталога одинаковое объявление `package` в первой строке (например, `package store`), и они видят все имена друг друга.

В Go нет ключевых слов `public`, `private` и `protected`. Видимость задаёт **регистр первой буквы**:
- **Заглавная буква** (`Bookmark`, `MemoryStore`, `New`, `Add`) — имя **экспортируется** и доступно другим пакетам.
- **Строчная буква** (`items`, `nextID`, `normalizeURL`) — имя скрыто внутри своего пакета.

Читая вызов `store.Add(...)`, вы мгновенно видите, публичное это имя или внутреннее. То же правило работает для полей структур: если поле `kop int64` начинается со строчной буквы, внешний код не сможет изменить его в обход конструктора.

## Модуль: `go.mod`, `go.sum` и `go mod tidy`

**Модуль** — дерево пакетов с общим файлом `go.mod` в корне. Его создают одной командой:

```bash
go mod init bookmarkflow
```

Получается короткий `go.mod`:

```text
module bookmarkflow

go 1.24
```

Строка `module bookmarkflow` задаёт префикс путей импорта для всех пакетов проекта, а `go 1.24` фиксирует версию языка.

При подключении внешних библиотек в `go.mod` появляется секция `require (...)` с точными версиями, а рядом — файл **`go.sum`** с криптографическими контрольными суммами зависимостей. Если кто-то подменит пакет на сервере, Go остановит сборку. Оба файла всегда хранят в Git.

После добавления или удаления импортов запускайте `go mod tidy`: команда сама допишет нужные зависимости, удалит лишние и обновит `go.sum`.

## Раскладка проекта: `cmd/` и `internal/`

Для утилит и сервисов в Go прижилась прозрачная структура каталогов:

```text
bookmarkflow/
├── go.mod
├── cmd/
│   └── bookmarkflow/
│       └── main.go        // package main — тонкая точка входа
└── internal/
    ├── bookmark/
    │   └── bookmark.go    // package bookmark — доменная модель
    └── store/
        └── memory.go      // package store — хранилище
```

- **`cmd/<имя>/main.go`** — точка входа (`package main`). Она собирает зависимости и запускает программу, оставляя бизнес-логику в отдельных пакетах.
- **`internal/`** — не договорённость, а **правило компилятора**. Пакет внутри `.../internal/...` доступен для импорта только коду из родительского дерева этого `internal/`. Чужой модуль получит ошибку сборки:

```text
use of internal package bookmarkflow/internal/store not allowed
```

Так вы свободно переписываете внутренние пакеты, не ломая внешних пользователей.

## Два пакета на практике

Пакет `internal/money/money.go` прячет поле `kop` и гарантирует, что сумма не станет отрицательной:

```go
// Файл: internal/money/money.go
package money

import (
	"errors"
	"fmt"
)

type Amount struct {
	kop int64 // не экспортируется
}

func New(kop int64) (Amount, error) {
	if kop < 0 {
		return Amount{}, errors.New("сумма не может быть отрицательной")
	}
	return Amount{kop: kop}, nil
}

func (a Amount) Kopecks() int64 { return a.kop }

func (a Amount) String() string {
	return fmt.Sprintf("%d.%02d RUB", a.kop/100, a.kop%100)
}
```

Точка входа `cmd/demo/main.go` импортирует пакет по полному пути модуля:

```go
// Файл: cmd/demo/main.go
package main

import (
	"fmt"

	"bookmarkflow/internal/money"
)

func main() {
	price, err := money.New(14990)
	if err != nil {
		fmt.Println("Ошибка:", err)
		return
	}
	fmt.Println("Цена:", price) // Вывод: Цена: 149.90 RUB
	// price.kop = -100 // compile error: price.kop undefined
}
```

Инвариант `kop >= 0` защищён компилятором, а не просьбой в комментарии.

## Функция `init()` и запрет циклов импортов

В пакете можно объявить `func init()` без аргументов и возвращаемых значений — Go вызовет её автоматически при импорте пакета, до `main()`. Но злоупотреблять `init()` вредно: она не умеет возвращать `error`, прячет побочные эффекты за строкой `import` и усложняет тестирование. Предпочитайте явные конструкторы вроде `store.NewMemoryStore()` в `main()`.

Ещё одно жёсткое правило компилятора — **циклы импортов запрещены**. Если `store` импортирует `format`, а `format` — `store`, сборка упадёт:

```text
import cycle not allowed
```

Ациклический граф зависимостей ускоряет компиляцию и удерживает архитектуру чистой. Цикл почти всегда лечится просто: общие типы выносят в отдельный маленький пакет (например, `internal/bookmark`), от которого зависят оба пакета.

> [!check] Проверь понимание
> Можно ли положить в каталог `internal/store/` два файла: `memory.go` (`package store`) и `helpers.go` (`package utils`)?
>
> Нет. Компилятор выдаст `found packages store (memory.go) and utils (helpers.go)`. Все обычные `.go`-файлы в одном каталоге обязаны принадлежать одному пакету.

## Практика

**Упражнение 1 (Базовое). Правила экспорта.**  
В пакете `wallet` объявлены:

```go
package wallet

type Account struct {
	Owner      string
	balanceKop int64
}

func NewAccount(owner string) *Account { return &Account{Owner: owner} }
func (a *Account) Deposit(kop int64)   { a.balanceKop += kop }
func (a *Account) reset()              { a.balanceKop = 0 }
```

Какие строки в `package main` не скомпилируются и почему?

```go
acc := wallet.NewAccount("Анна")
acc.Deposit(500)
fmt.Println(acc.Owner, acc.balanceKop)
acc.reset()
```

> [!solution] Показать решение
> Не скомпилируются третья (`acc.balanceKop`) и четвёртая (`acc.reset()`) строки: оба имени начинаются со строчной буквы и не экспортируются из пакета `wallet`.

**Упражнение 2 (Практическое). Дерево модуля `spendlog`.**  
Спроектируйте каталоги с `go.mod`, `cmd/` и `internal/` для CLI-трекера расходов `spendlog` (модель `Expense`, хранилище в памяти и пакет отчётов) и напишите пути `import` в `main.go`.

> [!solution] Показать решение
> ```text
> spendlog/
> ├── go.mod
> ├── cmd/spendlog/main.go
> └── internal/
>     ├── expense/expense.go
>     ├── store/memory.go
>     └── report/summary.go
> ```
> Импорты в `main.go`: `"spendlog/internal/expense"`, `"spendlog/internal/store"`, `"spendlog/internal/report"`. Вынесение `Expense` в отдельный пакет избавляет `store` и `report` от циклической зависимости.

**Упражнение 3 (Со звёздочкой \*). Разорви цикл импортов.**  
`internal/store` при сохранении закладки зовёт `audit.Record(id)`, а `internal/audit` импортирует `internal/store`, чтобы узнать название закладки по `id`. Предложите два чистых способа убрать `import cycle not allowed`.

> [!solution] Показать решение
> 1. **Передать данные сразу:** вызывать `audit.Record(id, title)` (или передавать `bookmark.Bookmark` из общего пакета `internal/bookmark`). Зависимость становится односторонней: `store -> audit`.
> 2. **Узкий интерфейс у потребителя:** объявить в `internal/store` интерфейс `type AuditRecorder interface { Record(id int, title string) }` и передавать реализацию из `internal/audit` в `store.NewMemoryStore(auditor)` внутри `main.go`. Пакеты перестают знать друг о друге.
