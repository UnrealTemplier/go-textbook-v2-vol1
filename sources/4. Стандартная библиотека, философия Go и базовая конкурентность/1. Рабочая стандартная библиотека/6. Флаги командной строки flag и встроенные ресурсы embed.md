*Как разбирать флаги и подкоманды командной строки пакетом `flag` без глобального состояния и как вшивать шаблоны и справочники в единый бинарник директивой `//go:embed`.*

В Модуле 2 мы разбирали аргументы `BookmarkFlow` через `os.Args`. Пока команд две, этого хватает. Но с опциями `-file=data.json`, `-limit=20` и `-verbose` ручные циклы превращаются в хрупкую стену `if`-ов без справки `-help`. Вторая боль CLI-утилит — внешние шаблоны и конфиги: стоит запустить бинарник из другой папки, и относительные пути ломаются. Обе задачи решают пакеты `flag` и `embed`.

## Базовые флаги: `flag.String`, `Int`, `Bool`, `Parse` и `Usage`

Пакет `flag` объявляет параметры со значениями по умолчанию и разбирает командную строку одним вызовом `flag.Parse()`:

```go
file := flag.String("file", "bookmarks.json", "путь к файлу закладок")
limit := flag.Int("limit", 10, "максимум записей")
verbose := flag.Bool("verbose", false, "подробный вывод")

flag.Usage = func() {
	fmt.Fprintln(flag.CommandLine.Output(), "Использование: bookmarkflow [флаги] <запрос>")
	flag.PrintDefaults()
}
flag.Parse()

fmt.Println(*file, *limit, *verbose, flag.Args())
```

`flag.String`, `flag.Int` и `flag.Bool` возвращают **указатели** (`*string`, `*int`, `*bool`), которые заполняются после `flag.Parse()`. Для привязки к полям структуры есть варианты с суффиксом `Var` (`flag.StringVar(&cfg.File, ...)`). Поддерживаются записи `-limit 20`, `--limit=20` и булево `-verbose`, а `-h`/`--help` автоматически печатают справку из `flag.Usage`.

## Подкоманды и тестируемость: `flag.NewFlagSet`

Функции верхнего уровня пишут в глобальный набор `flag.CommandLine` и при ошибке вызывают `os.Exit(2)`. Из-за этого неудобно делать подкоманды (`add`, `list`) и невозможно тестировать разбор флагов без риска уронить `go test`.

Решение — изолированный `flag.NewFlagSet(name, flag.ContinueOnError)`:

```go
package main

import (
	"bytes"
	"errors"
	"flag"
	"fmt"
	"io"
)

func runCLI(args []string, stdout, stderr io.Writer) error {
	if len(args) == 0 {
		return errors.New("укажите подкоманду: add или list")
	}

	switch args[0] {
	case "add":
		fs := flag.NewFlagSet("add", flag.ContinueOnError)
		fs.SetOutput(stderr)
		title := fs.String("title", "", "заголовок закладки")
		url := fs.String("url", "", "адрес закладки")
		if err := fs.Parse(args[1:]); err != nil {
			return err
		}
		if *title == "" || *url == "" {
			return errors.New("для add обязательны флаги -title и -url")
		}
		fmt.Fprintf(stdout, "Добавлено: %s (%s)\n", *title, *url)
		return nil

	case "list":
		fs := flag.NewFlagSet("list", flag.ContinueOnError)
		fs.SetOutput(stderr)
		limit := fs.Int("limit", 10, "максимум записей")
		if err := fs.Parse(args[1:]); err != nil {
			return err
		}
		fmt.Fprintf(stdout, "Показываем до %d закладок (фильтры: %v)\n", *limit, fs.Args())
		return nil

	default:
		return fmt.Errorf("неизвестная подкоманда %q", args[0])
	}
}

func main() {
	var out, errBuf bytes.Buffer
	if err := runCLI([]string{"add", "-title=Go Docs", "-url=https://go.dev"}, &out, &errBuf); err != nil {
		fmt.Println("ошибка:", err)
	}
	fmt.Print(out.String())

	out.Reset()
	if err := runCLI([]string{"list", "-limit=5", "stdlib"}, &out, &errBuf); err != nil {
		fmt.Println("ошибка:", err)
	}
	fmt.Print(out.String())
}
```

Вывод терминала:

```text
Добавлено: Go Docs (https://go.dev)
Показываем до 5 закладок (фильтры: [stdlib])
```

Посмотрите, насколько чистой стала функция `runCLI`: она не трогает `os.Args`, `os.Stdout` и не вызывает `os.Exit`. В реальной `main()` достаточно одной строки `runCLI(os.Args[1:], os.Stdout, os.Stderr)`, а в unit-тестах вы передаёте любые срезы аргументов и проверяете вывод через `bytes.Buffer`.

## Встроенные ресурсы прямо в бинарнике: `//go:embed`

Один из козырей Go — программа собирается в единственный автономный бинарник без внешних зависимостей. С Go 1.16 директива компилятора `//go:embed` позволяет вшить статические файлы прямо внутрь этого бинарника на этапе компиляции.

Чтобы использовать директиву, импортируйте пакет `embed` и объявите переменную **уровня пакета** одного из трёх типов:

* `string` — содержимое одного файла как строка;
* `[]byte` — содержимое одного файла как срез байтов;
* `embed.FS` — один или несколько файлов и целые каталоги в виде файловой системы только для чтения (она реализует `fs.FS` из прошлого урока).

```go
package assets

import "embed" // если embed.FS не используется (только string/[]byte), пишите: import _ "embed"

//go:embed banner.txt
var Banner string

//go:embed defaults/config.json
var DefaultConfig []byte

//go:embed templates/*.txt
var Templates embed.FS
```

Обратите внимание на строгий синтаксис директивы:

1. Между `//` и `go:embed` **не должно быть пробела** (иначе компилятор сочтёт строку обычным комментарием).
2. Директива ставится непосредственно над переменной уровня пакета (внутри функции `//go:embed` не работает).
3. Путь указывается относительно каталога текущего `.go`-файла с прямым слэшем `/`, и выходить наверх через `..` запрещено.
4. Если встроенный файл отсутствует при сборке, компилятор `go build` сразу сообщит об ошибке — сломанный релиз без нужного шаблона просто не соберётся.

Поскольку `embed.FS` реализует `fs.FS`, вы можете передавать его прямо в `fs.ReadFile`, `fs.WalkDir` и любые ваши функции из предыдущего урока. Вшитые данные доступны только на чтение и живут прямо в бинарнике, поэтому программа запускается из любой папки без потери ресурсов.

## Подводные камни

**Ловушка 1. Флаги после позиционного аргумента игнорируются.**  
Стандартный пакет `flag` останавливает разбор флагов ровно на **первом** аргументе без дефиса. Если вызвать программу как `bookmarkflow go.dev -limit=5`, то `-limit=5` попадёт в `flag.Args()` как обычная строка, а `limit` останется со значением по умолчанию `10`. Правильный порядок: сначала флаги, потом позиционные аргументы (`bookmarkflow -limit=5 go.dev`).

**Ловушка 2. Пустой импорт `_ "embed"` забыт при встраивании в `string` или `[]byte`.**  
Если в файле нет типа `embed.FS`, а есть только `//go:embed help.txt` над `var helpText string`, компилятор потребует явный импорт `_ "embed"`:

```text
// compile error: //go:embed only allowed in Go files that import "embed"
```

> [!check] Проверь понимание
> Что вернёт `fs.Args()`, если запустить разбор `fs.Parse([]string{"-limit=3", "go", "-verbose"})`, где объявлены оба флага `-limit` и `-verbose`?
>
> `[]string{"go", "-verbose"}`. Аргумент `"go"` не начинается с `-`, поэтому `flag` прекратил разбор флагов на нём и оставил всё остальное в `fs.Args()`. Значение `*verbose` останется `false`.

## Практика

**Упражнение 1 (Базовое). Почини порядок флагов и указатель.**  
Найдите две ошибки в фрагменте ниже и объясните, почему программа ведёт себя неверно:

```go
port := flag.Int("port", 8080, "порт запуска")
fmt.Println("Порт:", port)
flag.Parse()
```

> [!solution] Показать решение
> 1. `fmt.Println` вызван **до** `flag.Parse()`, поэтому переданный флаг из командной строки ещё не прочитан.
> 2. `port` имеет тип `*int` (указатель), поэтому напечатается адрес в памяти (`0xc000...`), а не число `8080`. Нужно сначала вызвать `flag.Parse()`, а затем разыменовать указатель: `fmt.Println("Порт:", *port)`.

**Упражнение 2 (Практическое). Тестируемый парсер флагов.**  
Напишите функцию `ParseExportFlags(args []string) (format string, limit int, err error)` на основе `flag.NewFlagSet("export", flag.ContinueOnError)` с флагами `-format` (по умолчанию `"json"`, допустимы `"json"` и `"csv"`) и `-limit` (по умолчанию `100`, должен быть `> 0`). Отключите печать ошибок в терминал через `fs.SetOutput(io.Discard)` и проверьте на валидных и невалидных аргументах.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"errors"
> 	"flag"
> 	"fmt"
> 	"io"
> )
>
> func ParseExportFlags(args []string) (format string, limit int, err error) {
> 	fs := flag.NewFlagSet("export", flag.ContinueOnError)
> 	fs.SetOutput(io.Discard)
>
> 	fs.StringVar(&format, "format", "json", "формат: json или csv")
> 	fs.IntVar(&limit, "limit", 100, "лимит записей")
>
> 	if err := fs.Parse(args); err != nil {
> 		return "", 0, err
> 	}
> 	if format != "json" && format != "csv" {
> 		return "", 0, fmt.Errorf("неподдерживаемый формат %q", format)
> 	}
> 	if limit <= 0 {
> 		return "", 0, errors.New("limit должен быть больше 0")
> 	}
> 	return format, limit, nil
> }
>
> func main() {
> 	fmt.Println(ParseExportFlags([]string{"-format=csv", "-limit=25"})) // Вывод: csv 25 <nil>
> 	fmt.Println(ParseExportFlags([]string{"-format=xml"}))              // Вывод:  0 неподдерживаемый формат "xml"
> 	fmt.Println(ParseExportFlags([]string{"-limit=0"}))                 // Вывод:  0 limit должен быть больше 0
> }
> ```
> Изолированный `FlagSet` с `flag.ContinueOnError` и `io.Discard` делает разбор флагов обычной чистой функцией, которую легко проверить табличным тестом.

**Упражнение 3 (Со звёздочкой \*). Выбор источника шаблона: диск или `embed.FS`.**  
Представьте, что у утилиты есть встроенная `defaultFS fs.FS` (в реальной программе это `embed.FS`) с файлом `"report.txt"`, но пользователь может передать флаг `-template=/path/to/custom.txt`. Напишите функцию `LoadTemplate(customPath string, fallback fs.FS) ([]byte, error)`, которая при непустом `customPath` читает файл с диска через `os.ReadFile`, а при пустом — берёт `"report.txt"` из `fallback` через `fs.ReadFile`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"io/fs"
> 	"os"
> 	"testing/fstest"
> )
>
> func LoadTemplate(customPath string, fallback fs.FS) ([]byte, error) {
> 	if customPath != "" {
> 		return os.ReadFile(customPath)
> 	}
> 	return fs.ReadFile(fallback, "report.txt")
> }
>
> func main() {
> 	embedded := fstest.MapFS{
> 		"report.txt": {Data: []byte("Отчёт BookmarkFlow\n")},
> 	}
> 	data, err := LoadTemplate("", embedded)
> 	fmt.Printf("%q %v\n", string(data), err) // Вывод: "Отчёт BookmarkFlow\n" <nil>
> }
> ```
> Принимая абстрактный `fs.FS`, функция работает и со встроенным `embed.FS` в бою, и с `fstest.MapFS` в unit-тестах.
