*Как превращать строки в числа и обратно пакетом `strconv`, когда доставать регулярные выражения `regexp` и почему компиляция шаблона внутри цикла убивает производительность.*

В консольной программе аргументы и строки файлов приходят как `string`. Чтобы получить порт `"8080"`, дробь `"199.50"` или флаг `"true"`, строку нужно разобрать в типизированное значение. Попытка написать `int("8080")` не скомпилируется (`cannot convert "8080" to type int`), а `string(65)` вернёт символ `"A"` вместо `"65"`. За честные преобразования отвечает пакет `strconv`, а за сложные шаблоны — `regexp`.

## Преобразования чисел и флагов: `strconv`

Для десятичного `int` есть короткая пара функций: `strconv.Atoi("42")` возвращает `(42, nil)` (или ошибку на неверной строке), а `strconv.Itoa(42)` — `"42"`. Для точного контроля разрядности и системы счисления служат `Parse*` и `Format*`:

| Задача | Функция | Пример | Результат |
|---|---|---|---|
| Целое с основанием | `strconv.ParseInt(s, base, bits)` | `ParseInt("ff", 16, 64)` | `int64(255), nil` |
| Беззнаковое целое | `strconv.ParseUint(s, base, bits)` | `ParseUint("10", 10, 32)` | `uint64(10), nil` |
| Дробное число | `strconv.ParseFloat(s, bits)` | `ParseFloat("3.14", 64)` | `float64(3.14), nil` |
| Булево значение | `strconv.ParseBool(s)` | `ParseBool("true")` | `true, nil` |
| Обратно в строку | `FormatInt` / `FormatFloat` / `FormatBool` | `FormatBool(false)` | `"false"` |

При `base == 0` функция `ParseInt` сама распознаёт префиксы `0x`, `0b` и `0o`, а `bits` (например, `16` или `32`) проверяет попадание в диапазон типа.

Когда вы уже собираете байтовый буфер `[]byte`, семейство `strconv.AppendInt` / `AppendFloat` / `AppendBool` дописывает число прямо в срез без временной строки:

```go
buf := make([]byte, 0, 32)
buf = append(buf, "id="...)
buf = strconv.AppendInt(buf, 1024, 10) // "id=1024"
```

## Регулярные выражения: пакет `regexp`

Когда нужен шаблон сложнее простого префикса (дата `2026-11-23`, код тега `[a-z0-9-]+`), подключают `regexp`. Движок Go основан на RE2: время поиска всегда линейно от длины строки, поэтому хитрая строка не «подвесит» программу (цена — отсутствие обратных ссылок `\1` и опережающих проверок `(?=...)`).

Шаблон сначала компилируют в `*regexp.Regexp`:
* `regexp.Compile(pattern)` — возвращает `(*regexp.Regexp, error)` для динамических шаблонов;
* `regexp.MustCompile(pattern)` — паникует при ошибке синтаксиса; используйте **только для константных шаблонов на уровне пакета**.

Два главных метода: `re.MatchString(s)` проверяет наличие совпадения, а `re.FindStringSubmatch(s)` возвращает срез, где `[0]` — всё совпадение, а `[1]`, `[2]`, … — группы в скобках `(...)` (или `nil`, если совпадения нет).

Пример разбора строки лога закладок:

```go
package main

import (
	"fmt"
	"regexp"
	"strconv"
)

// Компилируем шаблон ОДИН раз при старте пакета.
// Сырые строковые литералы в обратных кавычках избавляют от двойного экранирования \\.
var entryRe = regexp.MustCompile(`^(\d{4}-\d{2}-\d{2})\s+#(\d+)\s+([a-z0-9-]+)$`)

func parseLogLine(line string) (date string, id int, tag string, err error) {
	m := entryRe.FindStringSubmatch(line)
	if m == nil {
		return "", 0, "", fmt.Errorf("неверный формат строки: %q", line)
	}
	parsedID, err := strconv.Atoi(m[2])
	if err != nil {
		return "", 0, "", fmt.Errorf("некорректный id %q: %w", m[2], err)
	}
	return m[1], parsedID, m[3], nil
}

func main() {
	lines := []string{
		"2026-11-23 #42 go-stdlib",
		"2026-11-23 #abc broken",
	}
	for _, l := range lines {
		date, id, tag, err := parseLogLine(l)
		if err != nil {
			fmt.Println("ошибка:", err)
			continue
		}
		fmt.Printf("дата=%s id=%d тег=%s\n", date, id, tag)
	}
}
```

Вывод терминала:

```text
дата=2026-11-23 id=42 тег=go-stdlib
ошибка: неверный формат строки: "2026-11-23 #abc broken"
```

Обратите внимание на обратные кавычки `` `...` `` вокруг шаблона: в обычных двойных кавычках пришлось бы писать `"^(\\d{4}-\\d{2}-\\d{2})..."`, удваивая каждый обратный слэш. В сырой строке шаблон читается глазами без лишнего шума.

## Когда лучше обойтись пакетом `strings` вместо `regexp`

Регулярные выражения заманчивы своей выразительностью, но их работа обходится в десятки раз дороже простых проверок из `strings`, а сложный шаблон труднее читать и сопровождать.

Хорошее правило инженера Go: **доставайте `regexp` только там, где `strings` действительно не справляется.**

| Задача | Не тяните `regexp` | Чистое решение на `strings` |
|---|---|---|
| Проверить протокол URL | `regexp.MustCompile("^https://")` | `strings.HasPrefix(u, "https://")` |
| Найти подстроку | `regexp.MatchString("error", line)` | `strings.Contains(line, "error")` |
| Разделить `key=value` | `regexp.MustCompile("^([^=]+)=(.*)$")` | `strings.Cut(line, "=")` |
| Убрать пробелы по краям | `re.ReplaceAllString(s, "")` | `strings.TrimSpace(s)` |

## Подводные камни

**Ловушка 1. `regexp.MustCompile` внутри цикла или функции.**  
Компиляция регулярного выражения строит конечный автомат и выделяет десятки объектов в памяти. Если вызвать `regexp.MustCompile(...)` внутри цикла на 50 000 строк, программа потратит львиную долю времени на пересборку одного и того же автомата 50 000 раз подряд. Всегда выносите константные шаблоны в переменную уровня пакета `var myRe = regexp.MustCompile(...)` — скомпилированный `*regexp.Regexp` безопасен для многократного вызова.

**Ловушка 2. Забытые якоря `^` и `$` в `MatchString`.**  
`regexp.MustCompile(`\d{4}`).MatchString("id=202699")` вернёт `true`, потому что `MatchString` ищет совпадение **внутри** строки. Если нужно проверить всю строку целиком, обязательно ставьте `^` в начале и `$` в конце: `` `^\d{4}$` ``.

> [!check] Проверь понимание
> Что вернёт `strconv.ParseInt("70000", 10, 16)`?
>
> Ошибку `strconv.ErrRange` (`value out of range`) и максимальное значение `int16` (`32767`). Параметр `bitSize = 16` ограничивает допустимый диапазон значениями знакового 16-битного целого (`-32768..32767`), куда `70000` не помещается.

## Практика

**Упражнение 1 (Базовое). Проследи `ParseBool` и `FormatInt`.**  
Что напечатает фрагмент ниже?

```go
b1, err1 := strconv.ParseBool("1")
b2, err2 := strconv.ParseBool("yes")
hex := strconv.FormatInt(255, 16)
fmt.Println(b1, err1 == nil, b2, err2 == nil, hex)
```

> [!solution] Показать решение
> Вывод: `true true false false ff`.  
> `strconv.ParseBool` принимает только `1`, `t`, `T`, `TRUE`, `true`, `True` и `0`, `f`, `F`, `FALSE`, `false`, `False`. Строка `"yes"` даёт ошибку (`err2 != nil`). `FormatInt(255, 16)` форматирует 255 в шестнадцатеричной системе строчными буквами: `"ff"`.

**Упражнение 2 (Практическое). Разбор номера порта.**  
Напишите функцию `ParsePort(raw string) (uint16, error)`, которая принимает строку, обрезает пробелы, разбирает её через `strconv.ParseUint(s, 10, 16)` и дополнительно отклоняет порт `0` с понятной ошибкой. Проверьте на `"8080"`, `"0"`, `"70000"` и `"-1"`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"errors"
> 	"fmt"
> 	"strconv"
> 	"strings"
> )
>
> func ParsePort(raw string) (uint16, error) {
> 	s := strings.TrimSpace(raw)
> 	n, err := strconv.ParseUint(s, 10, 16)
> 	if err != nil {
> 		return 0, fmt.Errorf("некорректный порт %q: %w", raw, err)
> 	}
> 	if n == 0 {
> 		return 0, errors.New("порт должен быть в диапазоне 1..65535")
> 	}
> 	return uint16(n), nil
> }
>
> func main() {
> 	for _, in := range []string{" 8080 ", "0", "70000", "-1"} {
> 		p, err := ParsePort(in)
> 		fmt.Printf("%q -> %d, err=%v\n", in, p, err)
> 	}
> }
> ```
> `ParseUint(..., 10, 16)` сам отсекает отрицательные числа и значения больше `65535`, а проверка `n == 0` закрывает оставшийся крайний случай.

**Упражнение 3 (Со звёздочкой \*). Извлечение тегов и замена без `regexp` vs с `regexp`.**  
Напишите функцию `ExtractIssueIDs(text string) []int`, которая находит в строке все упоминания задач вида `#123` (решётка и одна или более цифр) и возвращает слайс их целых номеров. Скомпилируйте регулярное выражение на уровне пакета и используйте `FindAllStringSubmatch`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"regexp"
> 	"strconv"
> )
>
> var issueRe = regexp.MustCompile(`#(\d+)`)
>
> func ExtractIssueIDs(text string) []int {
> 	matches := issueRe.FindAllStringSubmatch(text, -1)
> 	ids := make([]int, 0, len(matches))
> 	for _, m := range matches {
> 		if id, err := strconv.Atoi(m[1]); err == nil {
> 			ids = append(ids, id)
> 		}
> 	}
> 	return ids
> }
>
> func main() {
> 	msg := "Исправлен экспорт (#14) и тест (#208), проверено на #7"
> 	fmt.Println(ExtractIssueIDs(msg)) // Вывод: [14 208 7]
> }
> ```
> Второй аргумент `-1` в `FindAllStringSubmatch` означает «найти все вхождения без ограничения», а `m[1]` содержит цифры из первой скобочной группы без символа `#`.
