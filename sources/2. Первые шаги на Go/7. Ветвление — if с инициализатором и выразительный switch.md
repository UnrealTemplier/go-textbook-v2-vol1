*Как писать лаконичные ветвления в Go: `if` с коротким инициализатором, `switch` без `break` и `switch` без выражения вместо громоздких цепочек `if-else`.*

Почти каждый разработчик, пришедший в Go из C, Java или JavaScript, по привычке ставит круглые скобки вокруг условия `if (x > 0)` и дописывает `break` в конце каждой ветки `switch`. В Go обе эти привычки лишние — `gofmt` снимет скобки, а `switch` устроен безопаснее с самого начала.

Более того, у `if` и `switch` в Go есть два приёма, которые делают проверку входных данных и разбор команд поразительно чистыми. Разберём их на задачах, которые скоро войдут в `BookmarkFlow`.

## `if` без скобок и `if` с инициализатором

Обычное ветвление в Go пишется без круглых скобок вокруг условия, но **фигурные скобки `{ ... }` обязательны всегда**, даже для одной строки внутри:

```go
statusCode := 404

if statusCode == 200 {
	fmt.Println("Страница доступна")
} else if statusCode == 404 {
	fmt.Println("Страница не найдена")
} else {
	fmt.Println("Неожиданный код:", statusCode)
}
```

Зачем обязательны `{}` даже для одной строки? В истории C и Apple случались громкие уязвимости безопасности (знаменитый баг `goto fail` в SSL в 2014 году), когда программист добавил вторую строчку под `if` без фигурных скобок — отступ выглядел «внутри», а выполнялась строка безусловно. В Go синтаксис закрывает этот класс ошибок на корню.

Заметьте также, что `else` должен начинаться **на той же строке**, где закрывается `}` предыдущей ветки (`} else {`), иначе автоматическая точка с запятой сломает синтаксис.

Теперь — фирменный приём Go: **`if` с коротким инициализатором**. Перед условием можно выполнить короткую инструкцию, отделив её точкой с запятой `;`:

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	title := "Спецификация языка Go"

	if n := utf8.RuneCountInString(title); n == 0 {
		fmt.Println("Ошибка: название пустое")
	} else if n > 80 {
		fmt.Printf("Ошибка: название слишком длинное (%d символов)\n", n)
	} else {
		fmt.Printf("Название принято (%d символов)\n", n)
	}

	// Здесь переменная n уже НЕ существует!
	// fmt.Println(n) // compile error: undefined: n
}
```

Переменная `n`, объявленная в заголовке `if`, живёт **только внутри всей конструкции `if / else if / else`** и исчезает сразу за последней `}`. Это держит область видимости узкой и не засоряет функцию временными переменными. Когда мы дойдём до обработки ошибок (`if err := ...; err != nil`), вы будете встречать эту форму почти в каждом файле на Go.

## `switch`: без ловушки проваливания (*fallthrough*)

В C и JavaScript забытый `break` в конце `case` приводит к тому, что выполнение молча «проваливается» в следующую ветку — один из самых коварных источников багов. В Go всё наоборот: **каждая ветка `case` автоматически завершает `switch`**.

Кроме того, в одном `case` можно перечислять несколько значений через запятую, а сравнивать можно не только числа, но и строки:

```go
package main

import "fmt"

func main() {
	cmd := "ls"

	switch cmd {
	case "add", "new":
		fmt.Println("Добавляем закладку")
	case "list", "ls":
		fmt.Println("Показываем список закладок")
	case "delete", "rm":
		fmt.Println("Удаляем закладку")
	default:
		fmt.Printf("Неизвестная команда: %q\n", cmd)
	}
}
```

Вывод:

```text
Показываем список закладок
```

Ветка `default` выполняется, если не подошёл ни один `case`. Её порядок синтаксически не важен, но по общему соглашению её всегда пишут последней.

Если вдруг вам действительно нужно перейти в следующую ветку (редкий случай), в Go есть явное ключевое слово `fallthrough` — но оно переходит безусловно, не проверяя условие следующего `case`, поэтому на практике к нему прибегают крайне редко.

## `switch` без выражения: чистая замена лестнице `if / else if`

В Go можно вообще не писать переменную после слова `switch` — тогда это эквивалентно `switch true`, и в каждом `case` пишется произвольное логическое условие. Ветки проверяются строго сверху вниз до первого совпадения:

```go
package main

import "fmt"

func main() {
	latencyMs := 420

	switch {
	case latencyMs < 0:
		fmt.Println("Некорректный замер")
	case latencyMs < 100:
		fmt.Println("Быстрый ответ")
	case latencyMs < 500:
		fmt.Println("Приемлемая задержка")
	default:
		fmt.Println("Медленный сервер: нужна диагностика")
	}
}
```

Сравните эту запись с четырёхэтажной лестницей `if ... else if ... else if ... else`: читается в два раза спокойнее, и глаз сразу схватывает таблицу диапазонов.

В `switch`, как и в `if`, можно писать короткий инициализатор перед условием: `switch code := statusCode / 100; code { ... }`.

## Чего в Go нет: тернарный оператор `?:`

Если вы искали в Go запись `label := ok ? "да" : "нет"` — её **нет в языке намеренно**. Авторы Go сочли, что вложенные тернарные выражения быстро превращаются в нечитаемые ребусы, и оставили единственное средство ветвления:

```go
label := "нет"
if ok {
	label = "да"
}
```

На две строчки длиннее, зато через полгода любой инженер прочитает это за полсекунды.

> [!check] Проверь понимание
> Что выведет код ниже?
> ```go
> x := 2
> switch x {
> case 1, 2:
> 	fmt.Print("A")
> case 2, 3:
> 	fmt.Print("B")
> default:
> 	fmt.Print("C")
> }
> ```
>
> Выведет только `A`. Хотя `2` подходит и под второй `case`, `switch` в Go останавливается на первом совпадении и не проваливается в следующие ветки.

## Практика

**Упражнение 1 (Базовое). Классификатор HTTP-статусов.**  
Задайте переменную `code` (проверьте на `200`, `301`, `404`, `503` и `999`) и с помощью `switch` без выражения напечатайте класс ответа:
* `200..299` → `"Успех (2xx)"`
* `300..399` → `"Перенаправление (3xx)"`
* `400..499` → `"Ошибка клиента (4xx)"`
* `500..599` → `"Ошибка сервера (5xx)"`
* иначе → `"Неизвестный код"`

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func main() {
> 	code := 404
>
> 	switch {
> 	case code >= 200 && code < 300:
> 		fmt.Println("Успех (2xx)")
> 	case code >= 300 && code < 400:
> 		fmt.Println("Перенаправление (3xx)")
> 	case code >= 400 && code < 500:
> 		fmt.Println("Ошибка клиента (4xx)")
> 	case code >= 500 && code < 600:
> 		fmt.Println("Ошибка сервера (5xx)")
> 	default:
> 		fmt.Println("Неизвестный код")
> 	}
> }
> ```
> Ещё короче можно записать через `switch code / 100 { case 2: ... case 3: ... }`, предварительно проверив `code >= 100 && code <= 599`.

**Упражнение 2 (Практическое). Проверка протокола ссылки для `BookmarkFlow`.**  
Используя `strings.HasPrefix` и `if` с инициализатором, очистите строку `rawURL := "  https://go.dev/doc  "` через `strings.TrimSpace` и проверьте:
* если очищенная строка пуста → напечатайте `"Пустая ссылка"`;
* если начинается с `"https://"` → `"Безопасная ссылка: <url>"`;
* если начинается с `"http://"` → `"Нешифрованная ссылка: <url>"`;
* иначе → `"Неподдерживаемый протокол"`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"strings"
> )
>
> func main() {
> 	rawURL := "  https://go.dev/doc  "
>
> 	if clean := strings.TrimSpace(rawURL); clean == "" {
> 		fmt.Println("Пустая ссылка")
> 	} else if strings.HasPrefix(clean, "https://") {
> 		fmt.Println("Безопасная ссылка:", clean)
> 	} else if strings.HasPrefix(clean, "http://") {
> 		fmt.Println("Нешифрованная ссылка:", clean)
> 	} else {
> 		fmt.Println("Неподдерживаемый протокол:", clean)
> 	}
> }
> ```
> Переменная `clean` доступна во всех ветках `else if` и `else`, но не засоряет остальную часть функции `main`.

**Упражнение 3 (Со звёздочкой \*). Что сломается?**  
Найдите две ошибки компиляции в этом фрагменте и исправьте его:

```go
package main

import "fmt"

func main() {
	if limit := 10; limit > 0 {
		fmt.Println("Лимит активен")
	}
	else {
		fmt.Println("Без лимита")
	}
	fmt.Println("Итог:", limit)
}
```

> [!solution] Показать решение
> 1. `else` перенесён на новую строку — после `}` лексер вставит `;`, что даст `syntax error: unexpected else`. Нужно писать `} else {`.
> 2. `fmt.Println("Итог:", limit)` — за пределами блока `if/else` переменная `limit` уже не существует (`undefined: limit`). Если переменная нужна после `if`, её объявляют до него: `limit := 10`.
