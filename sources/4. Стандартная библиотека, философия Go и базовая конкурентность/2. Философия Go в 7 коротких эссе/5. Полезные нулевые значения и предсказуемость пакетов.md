*Почему `bytes.Buffer`, `strings.Builder` и пустой слайс работают без конструктора, как проектировать структуры с безопасным нулевым состоянием и где конструктор всё-таки нужен.*

В C или C++ забыть инициализировать переменную — значит прочитать из памяти случайный мусор. В Java или Python неинициализированное поле часто оказывается `null`/`None` и роняет программу при первом вызове метода.

В Go каждая переменная рождается в **нулевом значении** (*zero value*): числа равны `0`, строки — `""`, логические значения — `false`, указатели, слайсы, мапы и интерфейсы — `nil`, а поля структуры рекурсивно обнуляются.

Создатели Go превратили эту гарантию в принцип проектирования пакетов: **стремитесь к тому, чтобы нулевое значение типа было готово к работе без конструктора.**

## Почему `bytes.Buffer`, `strings.Builder` и `var s []T` работают сразу

Взгляните на три типа, которыми вы уже пользовались в Модулях 3 и 4:

```go
var tags []string
tags = append(tags, "go", "stdlib")

var b strings.Builder
b.WriteString("BookmarkFlow")

var buf bytes.Buffer
buf.WriteString("строка 1\n")
```

Ни для одного из них мы не вызывали `New...()`. Почему они не падают?

* **Слайс `var tags []string`.** Его нулевое значение — `(ptr: nil, len: 0, cap: 0)`. Функции `len`, `cap`, цикл `for range` и `append` работают с `nil`-слайсом без особых случаев: первый `append` сам выделит базовый массив.
* **`strings.Builder` и `bytes.Buffer`.** Внутри обеих структур лежит обычный байтовый слайс `[]byte` и нулевые смещения. Пока вы ничего не записали, буфер не тратит память в куче; при первом `Write` внутренний `append` выделяет нужный блок.

Отсюда мощное следствие композиции: **если у всех полей вашей структуры полезные нулевые значения, то и сама структура автоматически получает полезное нулевое значение.**

## Два приёма проектирования своих структур

### 1. Выбирайте имена так, чтобы `0` или `false` задавали безопасный режим

Если в структуре настроек назвать поле `EnableTrimming bool`, то `false` выключит очистку пробелов, и каждому придётся помнить о флаге. Назовите поле `KeepRawSpaces bool` — и пустой литерал `ExportOptions{}` сразу работает безопасно. Точно так же `MaxItems == 0` можно трактовать как «разумный лимит по умолчанию».

### 2. Ленивая инициализация скрытой мапы

Как мы помним из Модуля 3, чтение из `nil`-мапы безопасно (возвращает `0`), а запись вызывает панику. Если мапа скрыта в неэкспортируемом поле, метод записи может создать её при первом вызове:

```go
package main

import (
	"fmt"
	"strings"
)

// TagCounter считает частоту тегов. Нулевое значение готово к работе.
type TagCounter struct {
	counts map[string]int
}

func (tc *TagCounter) Add(tag string) {
	tag = strings.ToLower(strings.TrimSpace(tag))
	if tag == "" {
		return
	}
	if tc.counts == nil {
		tc.counts = make(map[string]int)
	}
	tc.counts[tag]++
}

func (tc *TagCounter) Count(tag string) int {
	return tc.counts[strings.ToLower(strings.TrimSpace(tag))]
}

func (tc *TagCounter) TotalUnique() int { return len(tc.counts) }

func main() {
	var counter TagCounter // без NewTagCounter()
	fmt.Println("До:", counter.Count("go"), counter.TotalUnique())

	counter.Add("Go")
	counter.Add("  go ")
	counter.Add("stdlib")
	fmt.Println("После:", counter.Count("go"), counter.TotalUnique())
}
```

Вывод терминала:

```text
До: 0 0
После: 2 2
```

Переменная `var counter TagCounter` готова к работе сразу, даже если её встроить полем в другую структуру.

## Честная граница: когда конструктор всё-таки нужен

Полезное нулевое значение — не догма. В четырёх случаях явный конструктор `New...` или `Open...` честнее и безопаснее:

1. **Ненулевой стартовый инвариант.** В `MemoryStore` из шага 4 `BookmarkFlow` идентификаторы начинаются с `1`, поэтому `NewMemoryStore()` явно задаёт `nextID: 1`.
2. **Обязательная зависимость.** Без пути к файлу (`FileStore`) или `io.Writer` структура не может работать — конструктор требует аргумент на этапе компиляции.
3. **Инициализация с возможной ошибкой.** `OpenFileStore(path)` возвращает `(*FileStore, error)` и сразу сообщает о битом JSON или нехватке прав, чего нулевое значение сделать не может.
4. **Несколько мап и много методов записи.** Расставлять `if s.m == nil` в десятке мест рискованно — один `make` в `New...()` надёжнее.

Хороший пакет предсказуем: если тип готов к работе из нуля, об этом прямо пишут в `godoc`-комментарии. Если нужен конструктор — его объявляют рядом с типом.

> [!check] Проверь понимание
> Почему `var s []string` сразу работает с `append`, а запись в `var m map[string]int` вызывает панику?
>
> `append` возвращает новый заголовок слайса, поэтому спокойно выделяет новый базовый массив для `nil`-слайса. Запись `m[k] = v` не возвращает новую мапу, а пытается изменить внутреннюю структуру по пустому указателю.

## Практика

**Упражнение 1 (Базовое). Безопасный ноль.**  
В структуре `type LimitConfig struct { MaxBytes int64 }` какой смысл лучше задать для `MaxBytes == 0`: «запретить чтение» или «безопасный лимит по умолчанию 1 МБ»? Почему?

> [!solution] Показать решение
> «Безопасный лимит по умолчанию 1 МБ». Тогда `LimitConfig{}` сразу даёт рабочий защищённый режим, а не тихий отказ при забытом поле.

**Упражнение 2 (Практическое). Счётчик ID без конструктора.**  
Напишите структуру `SimpleStore` с методами `Add(title string) int` и `Count() int`, которая **без** конструктора выдаёт идентификаторы `1, 2, 3...`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> // SimpleStore хранит заголовки. Нулевое значение готово к работе.
> type SimpleStore struct {
> 	lastID int
> 	items  []string
> }
>
> func (s *SimpleStore) Add(title string) int {
> 	s.lastID++
> 	s.items = append(s.items, title)
> 	return s.lastID
> }
>
> func (s *SimpleStore) Count() int { return len(s.items) }
>
> func main() {
> 	var store SimpleStore
> 	fmt.Println(store.Add("Go Spec"), store.Add("Go Blog"), store.Count())
> 	// Вывод: 1 2 2
> }
> ```
> Замена `nextID` на `lastID` превращает `0` в естественное начальное состояние: первый инкремент даёт `1`.

**Упражнение 3 (Со звёздочкой \*). Конструктор или ноль.**  
Нужен тип `JSONFileLogger`, дописывающий строки в файл на диске. Делать ли его готовым из нулевого значения или завести `OpenJSONFileLogger(path string) (*JSONFileLogger, error)`? Приведите два аргумента.

> [!solution] Показать решение
> Нужен конструктор `OpenJSONFileLogger(path string) (*JSONFileLogger, error)`: (1) без пути к файлу логгеру некуда писать — разумного «нулевого пути» нет; (2) ошибки открытия файла или прав доступа лучше получить сразу при старте из возвращённого `error`, а не спустя час работы.
