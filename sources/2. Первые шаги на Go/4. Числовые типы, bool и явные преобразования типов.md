*Какие числовые типы и логические значения есть в Go, почему компилятор запрещает складывать `int` с `int64` и зачем хранить деньги в целых копейках.*

В Python или JavaScript вы спокойно пишете `10 + 2.5` и получаете `12.5` — язык сам незаметно превращает целое число в дробное. Удобно на пяти строках, но в большом серверном коде такие скрытые превращения нередко прячут потерю точности или внезапное переполнение.

В Go правило жёсткое и простое: **никаких неявных преобразований типов**. Даже два похожих целых типа — `int` и `int64` — для компилятора полностью разные типы. Давайте разберёмся, какие базовые типы есть в языке и как выбирать нужный.

## Целые числа: со знаком и без

В Прологе мы видели, что ячейка памяти имеет фиксированную ширину в битах. Целые типы Go прямо называют эту ширину в своём имени:

| Тип | Размер | Диапазон значений | Где используется |
|---|---:|---|---|
| `int8` / `uint8` (`byte`) | 1 байт | `-128..127` / `0..255` | Сырые байты, компактные флаги |
| `int16` / `uint16` | 2 байта | `-32 768..32 767` / `0..65 535` | Сетевые порты (`uint16`) |
| `int32` (`rune`) / `uint32` | 4 байта | `±2.14 млрд` / `0..4.29 млрд` | Символы Unicode (`rune`) |
| `int64` / `uint64` | 8 байт | `±9.22 × 10¹⁸` / `0..1.84 × 10¹⁹` | Временные метки, большие счётчики, деньги в копейках |
| `int` / `uint` | 4 или 8 байт | Зависит от CPU (на 64-бит — как `int64`) | **Основной выбор по умолчанию** |

Практическое правило Go: **почти всегда берите `int`** для счётчиков, индексов и обычных целых величин. Переходите на `int64`, когда нужен гарантированный 64-битный диапазон на любой платформе (например, размер файла или идентификатор записи), а на `uint8`/`byte` — при работе с сырыми байтами.

Не используйте беззнаковый `uint` только потому, что «число не бывает отрицательным». Стоит вычесть `1` из `uint(0)` — и вместо `-1` вы получите переполнение и огромное положительное число `18446744073709551615`. С обычным `int` условие `if n < 0` ловит ошибку сразу.

Кстати, в длинных числах Go позволяет ставить подчёркивания для читаемости: `1_000_000` или `0xFF_00_80` — компилятор их игнорирует.

## Дробные числа (`float64`) и ловушка `0.1 + 0.2`

Для вещественных чисел в Go есть два типа: `float32` (4 байта, ~7 значащих десятичных цифр) и **`float64`** (8 байт, ~15–17 значащих цифр). По умолчанию берите `float64` — именно его компилятор выбирает для литерала вроде `rate := 3.14` и именно с ним работает почти весь пакет `math`.

Но у двоичных дробей есть фундаментальное свойство, о котором нужно знать с первого дня. Запустите короткую программу:

```go
package main

import "fmt"

func main() {
	priceA := 0.1
	priceB := 0.2
	total := priceA + priceB

	fmt.Println("0.1 + 0.2 =", total)
	fmt.Println("Равно 0.3?", total == 0.3)
}
```

Вывод удивит, если вы видите это впервые:

```text
0.1 + 0.2 = 0.30000000000000004
Равно 0.3? false
```

Это не баг Go — так работает двоичная арифметика на всех процессорах мира. Десятичная дробь $\frac{1}{10}$ в двоичной системе превращается в бесконечную периодическую дробь (как $\frac{1}{3} = 0.3333\dots$ в десятичной) и неизбежно округляется на границе 64 бит. Как именно устроены биты дробного числа, мы детально разберём в Модуле 5.

А практический вывод нужно запомнить прямо сейчас:
1. **Никогда не храните деньги в `float64`.** Храните суммы в минимальных неделимых единицах — копейках или центах — в типе `int64` (например, `1990` копеек вместо `19.90` рублей), а дробный вид рисуйте только при выводе пользователю.
2. **Не сравнивайте `float64` через `==`** после вычислений — проверяйте, что модуль разности `math.Abs(a - b)` меньше допустимой погрешности (например, `1e-9`).

## Логический тип `bool`

Тип `bool` принимает ровно два значения: `true` и `false`. В отличие от C, Python или JavaScript, в Go **числа и строки не превращаются в `bool` автоматически**. Выражения `if 1` или `if ""` не скомпилируются — условие обязано быть строго булевым (`count > 0`, `title != ""`).

Логические операторы работают с **коротким замыканием** (*short-circuit*):
* `a && b` (И) не вычисляет `b`, если `a` уже `false`.
* `a || b` (ИЛИ) не вычисляет `b`, если `a` уже `true`.
* `!a` (НЕ) переворачивает значение.

Короткое замыкание спасает от падений: в выражении `divisor != 0 && total/divisor > 10` деление на ноль никогда не выполнится, если `divisor` равен нулю.

## Явные преобразования типов и целочисленное деление

Попробуем посчитать среднее время ответа сервера в миллисекундах:

```go
package main

import "fmt"

func main() {
	totalMs := 53
	requests := 4

	// Ошибка №1: деление int на int отбрасывает дробную часть!
	avgInt := totalMs / requests
	fmt.Println("Целочисленное среднее:", avgInt) // 13, а не 13.25!

	// Ошибка №2: смешивание типов без преобразования не скомпилируется
	// var bonus int64 = 10
	// sum := totalMs + bonus // compile error: invalid operation: totalMs + bonus (mismatched types int and int64)

	// Правильно: явное преобразование типа T(значение)
	avgFloat := float64(totalMs) / float64(requests)
	fmt.Println("Точное среднее:", avgFloat) // 13.25
}
```

Разберём два важных правила из этого примера:

1. **Деление двух целых даёт целое.** `53 / 4` равно `13`, дробная часть `.25` молча отбрасывается (остаток можно получить оператором `%`: `53 % 4 == 1`). Чтобы получить дробь, преобразуйте операнды к `float64` **до** деления.
2. **Синтаксис преобразования — `T(x)`.** Например, `float64(totalMs)`, `int(price)`, `int64(count)`. Если переменная `x` не помещается в новый тип или имеет дробную часть, преобразование отбросит лишнее: для переменной `x := 3.99` выражение `int(x)` даст `3` (не округление, а усечение к нулю; причём на константе `int(3.99)` компилятор вообще остановится с ошибкой), а для `n := 260` выражение `uint8(n)` даст `4` (переполнение по модулю 256).

> [!warning] Ловушка преобразования числа в `string`
> Выражение `string(65)` **не** превращает число `65` в текст `"65"`. Оно трактует `65` как код символа Unicode (`U+0041`) и возвращает `"A"`. Для перевода числа в строку цифр используют `strconv.Itoa(65)` или `fmt.Sprintf("%d", 65)` — мы разберём их в ближайших уроках.

> [!check] Проверь понимание
> На 64-битном сервере типы `int` и `int64` оба занимают 8 байт. Скомпилируется ли `var a int = 5; var b int64 = 10; fmt.Println(a + b)`?
>
> Нет. Для компилятора Go `int` и `int64` — разные именованные типы независимо от разрядности процессора. Чтобы сложить их, нужно явно написать `int64(a) + b` или `a + int(b)`.

## Практика

**Упражнение 1 (Базовое). Проследи вывод (Code Tracing).**  
Определите без запуска, что выведет программа, и объясните каждую цифру:

```go
package main

import "fmt"

func main() {
	a := 7 / 2
	b := float64(7 / 2)
	c := float64(7) / 2
	x := 9.99
	d := int(x)
	fmt.Println(a, b, c, d)
}
```

> [!solution] Показать решение
> Вывод:
> ```text
> 3 3 3.5 9
> ```
> * `a`: целочисленное деление `7 / 2` даёт `3`.
> * `b`: сначала выполняется `7 / 2` (получается `3`), и только потом `3` превращается в `float64(3)` — это частая ловушка.
> * `c`: `float64(7)` задаёт тип `float64`, нетипизированная константа `2` подстраивается под него, деление даёт `3.5`.
> * `d`: `int(x)` отбрасывает дробную часть к нулю, а не округляет, поэтому получается `9`.

**Упражнение 2 (Практическое). Чек в копейках без погрешностей.**  
Напишите программу, которая хранит цены трёх позиций в копейках (`int64`): `1990`, `3450` и `560`, считает общую сумму в копейках, вычисляет скидку 10% (целочисленно) и выводит итоговую сумму в формате `X руб. Y коп.` (подсказка: рубли — `total / 100`, копейки — `total % 100`).

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func main() {
> 	var item1, item2, item3 int64 = 1990, 3450, 560
> 	subtotal := item1 + item2 + item3 // 6000 копеек
> 	discount := subtotal * 10 / 100   // 600 копеек
> 	total := subtotal - discount      // 5400 копеек
>
> 	rub := total / 100
> 	kop := total % 100
> 	fmt.Println("К оплате:", rub, "руб.", kop, "коп.")
> }
> ```
> Вся арифметика прошла в целых копейках — никакой ошибки округления `0.00000000000000004` возникнуть не может.

**Упражнение 3 (Со звёздочкой \*). Что сломается и почему?**  
Найдите ошибку компиляции и логическую ловушку переполнения в этом коде:

```go
package main

import "fmt"

func main() {
	var used uint8 = 250
	var added int = 10
	used = used + uint8(added)
	fmt.Println("Занято слотов:", used)

	var isFull bool = used
	fmt.Println("Заполнено:", isFull)
}
```

> [!solution] Показать решение
> 1. **Ошибка компиляции:** `var isFull bool = used` не скомпилируется (`cannot use used (variable of type uint8) as bool value`) — в Go числа нельзя приводить к `bool`. Нужно явное сравнение, например `isFull := used >= 250`.
> 2. **Ловушка переполнения:** `250 + 10 = 260`, но `uint8` вмещает только `0..255`. Сложение переполнится, и `used` станет равен **`4`** вместо `260`. Для счётчика, который может превысить 255, следует брать `int`.
