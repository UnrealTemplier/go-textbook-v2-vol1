На пятнадцатом уроке `BookmarkFlow` умел лишь валидировать и печатать закладки. Теперь соберём полноценное консольное приложение в памяти, которое понимает четыре команды — **`add`**, **`list`**, **`search`** и **`delete`** — и чётко различает пять видов ошибок через `errors.Is`.

Попутно мы честно упрёмся в **первый настоящий архитектурный потолок** базового синтаксиса Go — и именно он станет идеальным поводом перейти к Модулю 3.

## Команды и сигнальные ошибки шага 2

Зафиксируем контракт нашего CLI — он полностью совпадает с контрактом `project/step02/cli.go`:

| Команда | Аргументы | Действие |
|---|---|---|
| `add` | `<название> <url>` | Валидирует поля, выдаёт следующий `ID` (`1, 2, 3...`), сохраняет закладку |
| `list` | — | Печатает все закладки ровной таблицей `%-4d \| %-24s \| %s` |
| `search` | `<запрос>` | Ищет подстроку в названии или URL без учёта регистра |
| `delete` | `<id>` | Разбирает положительный `ID` и удаляет запись из памяти |

Пять сигнальных ошибок, покрывающих все нештатные ситуации:

```go
var (
	ErrEmptyTitle     = errors.New("название закладки не может быть пустым")
	ErrInvalidURL     = errors.New("ссылка должна начинаться с http:// или https://")
	ErrNotFound       = errors.New("закладка не найдена")
	ErrUnknownCommand = errors.New("неизвестная команда")
	ErrInvalidArgs    = errors.New("некорректные аргументы команды")
)
```

Обратите внимание на важное требование к `ID`: если у вас были закладки `#1` и `#2`, вы удалили `#1` и добавили новую, её номер должен стать **`#3`**, а не заново `#2`. Поэтому мы храним отдельный растущий счётчик `nextID`, а не берём `len(titles) + 1`.

## Как удалить элемент по индексу из списка

Чтобы удалить элемент с индексом `i` из списка `ids`, соединяют часть до `i` и часть после `i` через `append`:

```go
ids = append(ids[:i], ids[i+1:]...)
```

Троеточие `...` распаковывает элементы второй части списка как отдельные аргументы для `append`. (Под капотом здесь меняется базовый массив — в Модуле 3 мы разберём эту операцию на схеме памяти и увидим её скрытые подводные камни.)

## Полная сборка шага 2 (`main.go`)

Чтобы в одном запуске можно было проверить весь жизненный цикл (`add` → `add` → `search` → `delete` → `list`), мы напишем центральную функцию `execute`, которая принимает текущее состояние и команду в виде `args []string`. А из `main` можно либо передать одну команду прямо из `os.Args[1:]`, либо прогнать сценарий из нескольких команд подряд:

```go
package main

import (
	"errors"
	"fmt"
	"os"
	"strconv"
	"strings"
)

var (
	ErrEmptyTitle     = errors.New("название закладки не может быть пустым")
	ErrInvalidURL     = errors.New("ссылка должна начинаться с http:// или https://")
	ErrNotFound       = errors.New("закладка не найдена")
	ErrUnknownCommand = errors.New("неизвестная команда")
	ErrInvalidArgs    = errors.New("некорректные аргументы команды")
)

func execute(
	nextID int,
	ids []int,
	titles, urls []string,
	args []string,
) (int, []int, []string, []string, error) {
	if len(args) == 0 {
		return nextID, ids, titles, urls,
			fmt.Errorf("%w: укажите команду (add, list, search, delete)", ErrInvalidArgs)
	}

	switch args[0] {
	case "add":
		if len(args) != 3 {
			return nextID, ids, titles, urls,
				fmt.Errorf("%w: формат add <название> <url>", ErrInvalidArgs)
		}
		cleanTitle := strings.TrimSpace(args[1])
		cleanURL := strings.TrimSpace(args[2])
		if cleanTitle == "" {
			return nextID, ids, titles, urls, ErrEmptyTitle
		}
		lower := strings.ToLower(cleanURL)
		if !strings.HasPrefix(lower, "http://") && !strings.HasPrefix(lower, "https://") {
			return nextID, ids, titles, urls, fmt.Errorf("%w: %q", ErrInvalidURL, cleanURL)
		}
		id := nextID
		nextID++
		ids = append(ids, id)
		titles = append(titles, cleanTitle)
		urls = append(urls, cleanURL)
		fmt.Printf("Добавлена закладка #%d\n", id)
		return nextID, ids, titles, urls, nil

	case "list":
		printTable(ids, titles, urls)
		return nextID, ids, titles, urls, nil

	case "search":
		if len(args) != 2 {
			return nextID, ids, titles, urls,
				fmt.Errorf("%w: формат search <запрос>", ErrInvalidArgs)
		}
		q := strings.ToLower(strings.TrimSpace(args[1]))
		var mIDs []int
		var mTitles, mURLs []string
		for i := range len(ids) {
			if q == "" ||
				strings.Contains(strings.ToLower(titles[i]), q) ||
				strings.Contains(strings.ToLower(urls[i]), q) {
				mIDs = append(mIDs, ids[i])
				mTitles = append(mTitles, titles[i])
				mURLs = append(mURLs, urls[i])
			}
		}
		printTable(mIDs, mTitles, mURLs)
		return nextID, ids, titles, urls, nil

	case "delete":
		if len(args) != 2 {
			return nextID, ids, titles, urls,
				fmt.Errorf("%w: формат delete <id>", ErrInvalidArgs)
		}
		targetID, err := strconv.Atoi(args[1])
		if err != nil || targetID <= 0 {
			return nextID, ids, titles, urls,
				fmt.Errorf("%w: некорректный id %q", ErrInvalidArgs, args[1])
		}
		for i := range len(ids) {
			if ids[i] == targetID {
				ids = append(ids[:i], ids[i+1:]...)
				titles = append(titles[:i], titles[i+1:]...)
				urls = append(urls[:i], urls[i+1:]...)
				fmt.Printf("Закладка #%d удалена\n", targetID)
				return nextID, ids, titles, urls, nil
			}
		}
		return nextID, ids, titles, urls, fmt.Errorf("%w: #%d", ErrNotFound, targetID)

	default:
		return nextID, ids, titles, urls, fmt.Errorf("%w: %q", ErrUnknownCommand, args[0])
	}
}

func printTable(ids []int, titles, urls []string) {
	if len(ids) == 0 {
		fmt.Println("Ничего не найдено.")
		return
	}
	for i := range len(ids) {
		fmt.Printf("%-4d | %-24s | %s\n", ids[i], titles[i], urls[i])
	}
}

func main() {
	nextID := 1
	var ids []int
	var titles, urls []string

	// Демонстрационный сценарий (или запуск одной команды из os.Args[1:])
	if len(os.Args) > 1 {
		_, _, _, _, err := execute(nextID, ids, titles, urls, os.Args[1:])
		if err != nil {
			fmt.Fprintln(os.Stderr, "Ошибка:", err)
			os.Exit(1)
		}
		return
	}

	script := [][]string{
		{"add", "Go Standard Library", "https://pkg.go.dev/std"},
		{"add", "Go Spec", "https://go.dev/ref/spec"},
		{"search", "spec"},
		{"delete", "1"},
		{"list"},
	}
	for _, cmd := range script {
		var err error
		nextID, ids, titles, urls, err = execute(nextID, ids, titles, urls, cmd)
		if err != nil {
			fmt.Fprintln(os.Stderr, "Ошибка:", err)
			os.Exit(1)
		}
	}
}
```

Запустите `go run .` без аргументов — вы увидите полный цикл работы приложения:

```text
Добавлена закладка #1
Добавлена закладка #2
2    | Go Spec                  | https://go.dev/ref/spec
Закладка #1 удалена
2    | Go Spec                  | https://go.dev/ref/spec
```

А теперь проверьте ошибочные команды из терминала:

```bash

# Ошибка: некорректные аргументы команды: некорректный id "abc"
# exit status 1

go run . export
# Ошибка: неизвестная команда: "export"
# exit status 1
```

## Посмотрите честно на боль этого кода

Программа работает, компилируется чисто и решает задачу. Но вглядитесь в сигнатуру `execute`:

```go
func execute(
	nextID int,
	ids []int,
	titles, urls []string,
	args []string,
) (int, []int, []string, []string, error)
```

Пять входных параметров и **пять** возвращаемых значений — только ради того, чтобы протаскивать состояние из одного вызова в другой.

И это лишь верхушка айсберга. Посмотрите, что сломается завтра, как только мы захотим развить `BookmarkFlow`:
1. **Хрупкость параллельных списков.** Данные одной закладки размазаны по трём разным спискам (`ids`, `titles`, `urls`). Стоит в ветке `delete` забыть удалить элемент из `urls` — и все ссылки тихо сдвинутся к чужим названиям. А если завтра добавятся теги и дата создания, списков станет уже пять.
2. **Всё исчезает после завершения процесса.** Программа хранит данные только в оперативной памяти: закрыли терминал — все закладки пропали.
3. **Проверка только глазами.** Каждый раз после правки вы вручную запускаете команды и вглядываетесь в экран, проверяя, не сломался ли старый сценарий.

Откройте эталонный файл `project/step02/cli.go` в репозитории этого тома: там вы увидите первый взгляд на то, как те же 4 команды выглядят гораздо чище, когда поля одной закладки объединены в единый тип, а состояние приложения держит собственный объект с методами.

> [!check] Проверь понимание
> Почему после добавления закладок `#1` и `#2` и удаления `#1` следующей закладке нужно выдать номер `#3`, а не `#2` или `len(ids)+1`?
>
> Если вычислять номер как `len(ids)+1`, то после удаления `#1` останется одна запись с ID `#2`, и новая закладка тоже получит `1+1 = 2` — возникнут **две разные закладки с одинаковым ID `#2`**! Монотонно растущий счётчик `nextID` гарантирует уникальность идентификаторов.

## Практика

**Упражнение 1 (Базовое). Команда `count`.**  
Добавьте в `switch args[0]` новую команду `count`, которая не требует дополнительных аргументов (если `len(args) != 1` — возвращает `ErrInvalidArgs`) и печатает `Всего закладок: N`. Добавьте `{"count"}` в демонстрационный `script` и проверьте вывод.

> [!solution] Показать решение
> ```go
> case "count":
> 	if len(args) != 1 {
> 		return nextID, ids, titles, urls,
> 			fmt.Errorf("%w: команда count не принимает аргументов", ErrInvalidArgs)
> 	}
> 	fmt.Printf("Всего закладок: %d\n", len(ids))
> 	return nextID, ids, titles, urls, nil
> ```
> При добавлении `{"count"}` в конец `script` программа напечатает `Всего закладок: 1`.

**Упражнение 2 (Практическое). Команда `update <id> <новое название>`.**  
Добавьте в `execute` команду `update`, которая принимает ID и новое название закладки, проверяет валидность ID (положительное число) и непустоту нового названия (`ErrEmptyTitle`), находит запись по `ids[i] == targetID`, обновляет `titles[i]` и печатает `Закладка #ID обновлена`. Если запись не найдена — возвращает `fmt.Errorf("%w: #%d", ErrNotFound, targetID)`.

**Упражнение 3 (Со звёздочкой \*). Объясни почему и найди скрытый баг.**  
Представьте, что при удалении элемента в ветке `delete` разработчик случайно написал:
```go
ids = append(ids[:i], ids[i+1:]...)
titles = append(titles[:i], titles[i+1:]...)
// забыл строку для urls!
```
К чему приведёт эта опечатка при следующем вызове `list`, если в списке было 3 закладки и пользователь удалил `#1`?

> [!solution] Показать решение
> Программа **даже не упадёт** с ошибкой выхода за границы: цикл `for i := range len(ids)` пройдёт по `i = 0` и `i = 1`, и для обеих оставшихся закладок `titles[0]` и `titles[1]` распечатаются **чужие URL** (`urls[0]` от удалённой первой закладки и `urls[1]` от второй). Это тихая порча данных — самый опасный вид ошибок. Именно от таких багов нас избавит объединение полей одной закладки в единую структуру в следующем модуле.
