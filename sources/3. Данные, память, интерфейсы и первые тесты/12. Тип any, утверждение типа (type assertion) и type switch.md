*Как устроен пустой интерфейс `any`, почему `fmt.Println` принимает любые значения и как безопасно извлекать конкретный тип через утверждение типа и `type switch`.*

Взгляните на привычный вызов из предыдущих уроков:

```go
fmt.Println("Закладок:", 42, true, Bookmark{ID: 1, Title: "Go"})
```

В одну функцию попали `string`, `int`, `bool` и структура `Bookmark`. При этом Go — строго типизированный язык, где каждый параметр имеет один фиксированный тип. Как `fmt.Println` это удаётся?

## Пустой интерфейс `any`

Тип удовлетворяет интерфейсу, если реализует все перечисленные в нём методы. Что будет, если список методов **пуст**?

```go
interface{}
```

Требованию «ноль методов» удовлетворяет абсолютно любой тип в Go: число, строка, слайс, мапа, структура, указатель, функция. Такой тип называют **пустым интерфейсом**.

С Go 1.18 в язык добавили встроенный псевдоним:

```go
type any = interface{}
```

`any` и `interface{}` — один и тот же тип. В современном Go 1.24 всегда пишите `any`: короче и чище. Именно так объявлена `fmt.Println`:

```go
func Println(a ...any) (n int, err error)
```

## Цена универсальности

Попав в переменную типа `any`, значение теряет все свои операции для компилятора. Сложить два `any` или взять `len` не получится:

```go
var x any = 42
// n := x + 1 // compile error: invalid operation: x + 1 (mismatched types any and untyped int)
```

Чтобы снова работать с конкретным значением, нужно спросить программу во время выполнения, какой тип лежит внутри. Для этого служат **утверждение типа** и **`type switch`**.

## Утверждение типа (`type assertion`)

Запись `x.(T)` проверяет, хранится ли в интерфейсе `x` значение конкретного типа (или интерфейса) `T`. У неё две формы.

**Опасная форма** (одно значение):

```go
var x any = "bookmarkflow"
s := x.(string) // ОК: s == "bookmarkflow"

var y any = 100
bad := y.(string) // паника во время выполнения
```

Если внутри `y` не `string`, программа мгновенно падает с паникой:

```text
panic: interface conversion: interface {} is int, not string
```

**Безопасная форма** (*comma ok* — два значения):

```go
s, ok := y.(string)
if !ok {
	fmt.Println("ожидалась строка, пришло другое значение")
}
```

Безопасная форма никогда не паникует. При несовпадении типа `ok` равно `false`, а `s` получает нулевое значение типа `T` (для `string` — `""`).

Правило простое: **почти всегда используйте `v, ok := x.(T)`**. Однозначная форма оправдана лишь там, где тип гарантирован строкой выше.

## Выбор из нескольких типов: `type switch`

Когда в `any` ожидается один из нескольких вариантов (строка, число, флаг, `fmt.Stringer`, `nil`), цепочка `if _, ok := ...` быстро засоряет код. Вместо неё используют **`type switch`**:

```go
package main

import "fmt"

type PriceKop int64

func (p PriceKop) String() string {
	return fmt.Sprintf("%d.%02d RUB", p/100, p%100)
}

func describeField(val any) string {
	switch v := val.(type) {
	case nil:
		return "<пусто>"
	case string:
		return fmt.Sprintf("строка(%q)", v)
	case int:
		return fmt.Sprintf("целое(%d)", v)
	case bool:
		return fmt.Sprintf("флаг(%t)", v)
	case fmt.Stringer:
		return fmt.Sprintf("текст(%s)", v.String())
	default:
		return fmt.Sprintf("прочее(%T: %v)", v, v)
	}
}

func main() {
	samples := []any{"https://go.dev", 404, true, PriceKop(9950), nil, 3.14}
	for _, s := range samples {
		fmt.Println(describeField(s))
	}
}
```

Вывод:

```text
строка("https://go.dev")
целое(404)
флаг(true)
текст(99.50 RUB)
<пусто>
прочее(float64: 3.14)
```

Три детали `type switch`:
1. Конструкция `val.(type)` допустима **только** в заголовке `switch`.
2. В ветке с **одним** типом переменная `v` уже имеет этот конкретный тип (`string`, `int`, `fmt.Stringer`).
3. Если перечислить несколько типов через запятую (`case int, int64:`), компилятор не знает, какой именно сработал, поэтому `v` внутри ветки остаётся типа `any`.

## Когда `any` — зло

Привыкнув к Python или JavaScript, легко поддаться соблазну писать `map[string]any` и `func Handle(data any)` везде, «чтобы не возиться со структурами».

Не делайте так.

`any` отключает статическую проверку типов — главное преимущество Go. Опечатка в типе вместо мгновенной ошибки компилятора превращается в скрытый баг или панику в работе.

Держите `any` только на реальных границах, где тип заранее неизвестен: форматирование произвольных аргументов (`fmt.Println`) или диагностические атрибуты. В остальных случаях выбирайте конкретную структуру, узкий интерфейс или дженерики (урок 15).

> [!check] Проверь понимание
> Что выведет код ниже?
> ```go
> var x any
> n, ok := x.(int)
> fmt.Println(n, ok)
> ```
>
> `0 false`, без паники. В `x` лежит пустой `nil`-интерфейс; безопасное утверждение не находит там `int` и возвращает нулевое значение `0` и `false`.

## Практика

**Упражнение 1 (Базовое). Проследи вывод.**  
Определите вывод фрагмента ниже и объясните, почему сломается закомментированная строка.

```go
var a any = "go"
var b any = int64(7)
var c any

s, ok1 := a.(string)
n, ok2 := b.(int)
z, ok3 := c.(string)
fmt.Println(s, ok1, n, ok2, z, ok3)
// raw := b.(int)
```

> [!solution] Показать решение
> Вывод: `go true 0 false  false` (между двумя `false` пустая строка `z`).
>
> В `b` лежит `int64`, а не `int`: при утверждении типа неявного приведения нет, поэтому `ok2 == false`. Без `ok` строка `raw := b.(int)` упадёт с паникой `interface conversion: interface {} is int64, not int`.

**Упражнение 2 (Практическое). Сумматор целых.**  
Напишите `sumInts(items []any) (sum, skipped int)`, которая складывает все `int` из `items`, пропускает любые другие типы (включая `nil` и `int64`) и возвращает сумму и число пропущенных элементов.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func sumInts(items []any) (sum, skipped int) {
> 	for _, item := range items {
> 		n, ok := item.(int)
> 		if !ok {
> 			skipped++
> 			continue
> 		}
> 		sum += n
> 	}
> 	return sum, skipped
> }
>
> func main() {
> 	data := []any{10, "skip", 25, nil, true, 7, int64(100)}
> 	sum, skipped := sumInts(data)
> 	fmt.Printf("sum=%d skipped=%d\n", sum, skipped) // Вывод: sum=42 skipped=4
> }
> ```
> Форма `n, ok := item.(int)` безопасно отсеивает несовпадающие типы и `nil`.

**Упражнение 3 (Со звёздочкой \*). Форматирование метрик.**  
Напишите `formatMetric(name string, value any) string` через `type switch`, возвращающую `name=value`: для `int` — число, для `float64` — `%.2f`, для `bool` — `"on"`/`"off"`, для `fmt.Stringer` — `v.String()`, для `nil` — `"empty"`, для прочего — `fmt.Sprintf("%v", v)`. Почему ветка `case fmt.Stringer:` перехватит `type DurationMs int` со своим методом `String()`?

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> type DurationMs int
>
> func (d DurationMs) String() string { return fmt.Sprintf("%dms", int(d)) }
>
> func formatMetric(name string, value any) string {
> 	switch v := value.(type) {
> 	case nil:
> 		return name + "=empty"
> 	case int:
> 		return fmt.Sprintf("%s=%d", name, v)
> 	case float64:
> 		return fmt.Sprintf("%s=%.2f", name, v)
> 	case bool:
> 		if v {
> 			return name + "=on"
> 		}
> 		return name + "=off"
> 	case fmt.Stringer:
> 		return fmt.Sprintf("%s=%s", name, v.String())
> 	default:
> 		return fmt.Sprintf("%s=%v", name, v)
> 	}
> }
>
> func main() {
> 	fmt.Println(formatMetric("retries", 3), formatMetric("ratio", 0.876))
> 	fmt.Println(formatMetric("cache", true), formatMetric("latency", DurationMs(18)))
> 	fmt.Println(formatMetric("last_err", nil))
> }
> ```
> `DurationMs` — отдельный именованный тип, отличный от `int`, поэтому ветка `case int:` к нему не подходит, а ветка `case fmt.Stringer:` срабатывает благодаря методу `String() string`.
