*Как оператор `go` запускает независимые потоки исполнения с ценой старта 2 КБ, почему `main` обрывает их без предупреждения и чем опасен костыль `time.Sleep`.*

В прошлом уроке мы убедились: последовательный цикл проверки ссылок тратит 99% времени на ожидание ответов. Чтобы сдвинуть дело с мёртвой точки, программе нужно запустить несколько вызовов `checkBookmark` независимо друг от друга — не дожидаясь завершения первого, прежде чем стартует второй.

В Go для этого не нужно подключать сторонние библиотеки и заполнять громоздкие структуры конфигурации. Достаточно поставить перед вызовом функции два символа: `go`.

## Что делает оператор `go`

Любая программа на Go уже начинается с одной независимой ветки исполнения — функции `main()`. Когда программа встречает инструкцию `go f(x, y)`, происходят две вещи:

1. Аргументы `x` и `y` вычисляются **немедленно** в текущей ветке исполнения.
2. Сам вызов `f(x, y)` запускается в новой независимой ветке, а текущая функция сразу переходит к следующей строке — возвращаемые значения `f`, если они были, отбрасываются.

Такая независимая ветка исполнения в Go называется **горутиной** (*goroutine*). С точки зрения программиста она ведёт себя как очень лёгкий поток выполнения: имеет собственный стек вызовов и локальные переменные, но разделяет с остальными горутинами общую память программы.

## Горутина против потока ОС: честные масштабы

В классических серверных языках для конкурентной работы создают **потоки операционной системы** (*OS threads*). Поток ОС — штука основательная и тяжёлая.

Сравните порядок цифр:

| Характеристика | Поток ОС | Горутина Go |
|---|---|---|
| **Стартовый размер стека** | **1–8 МБ** (фиксированный резерв) | **2 КБ** (растёт и сжимается сам) |
| **Память под 10 000 задач** | 10–80 ГБ адресного пространства | Около **20 МБ** |
| **Кто переключает** | Ядро ОС | Среда выполнения (рантайм) Go |

Разница в стартовом стеке составляет сотни и тысячи раз. Запустить 100 000 потоков ОС на обычном ноутбуке невозможно — система упрётся в память и накладные расходы ядра. Запустить 100 000 горутин в Go — рядовая ситуация: им хватит пары сотен мегабайт памяти.

Среда выполнения Go сама распределяет тысячи горутин поверх небольшого числа потоков ОС (обычно по числу ядер процессора). Когда одна горутина засыпает в ожидании ответа сети или таймера, рантайм мгновенно отдаёт поток ОС другой готовой горутине. Как именно устроен планировщик Go внутри, на этом этапе знать не требуется — подробнее см. Том 5.

## Ловушка преждевременного выхода `main`

Попробуем перевести наш чекер закладок на горутины. Запустим проверку трёх ссылок с помощью `go`:

```go
package main

import (
	"fmt"
	"time"
)

func checkURL(url string, delay time.Duration) {
	time.Sleep(delay)
	fmt.Printf("OK %s (%v)\n", url, delay)
}

func main() {
	go checkURL("https://go.dev", 80*time.Millisecond)
	go checkURL("https://pkg.go.dev", 120*time.Millisecond)
	go checkURL("https://go.dev/blog", 60*time.Millisecond)
	fmt.Println("Проверки запущены")
}
```

Запустим программу и посмотрим в терминал:

```text
Проверки запущены
```

Ни одной строки `OK` нет! Программа отработала за миллисекунду и завершилась.

Причина кроется в жёстком правиле Go: **когда завершается функция `main()`, процесс останавливается немедленно**. Все остальные горутины обрываются на полуслове, даже не успев выполнить свои отложенные вызовы `defer`. Рантайм не ждёт фоновых горутин сам — ожидание нужно организовать явно.

## Почему `time.Sleep` — плохой костыль

Первая мысль — добавить в конец `main()` паузу `time.Sleep(200 * time.Millisecond)`, чтобы фоновые горутины успели отработать:

```go
package main

import (
	"fmt"
	"time"
)

func checkURL(url string, delay time.Duration) {
	time.Sleep(delay)
	fmt.Printf("OK %s (%v)\n", url, delay)
}

func main() {
	start := time.Now()
	go checkURL("https://go.dev", 80*time.Millisecond)
	go checkURL("https://pkg.go.dev", 120*time.Millisecond)
	go checkURL("https://go.dev/blog", 60*time.Millisecond)

	// NOTE: временный костыль — в следующем уроке заменим на каналы
	time.Sleep(180 * time.Millisecond)
	fmt.Printf("Готово за %v\n", time.Since(start).Round(time.Millisecond))
}
```

Вывод:

```text
OK https://go.dev/blog (60ms)
OK https://go.dev (80ms)
OK https://pkg.go.dev (120ms)
Готово за 180ms
```

Обратите внимание на порядок строк: первой финишировала самая быстрая ссылка (`60ms`), последней — самая медленная (`120ms`). Горутины действительно работали конкурентно.

Но `time.Sleep` в реальном коде — мина замедленного действия. Поставите слишком маленькую паузу — при малейшем скачке сетевой задержки часть проверок молча оборвётся. Поставите с запасом на 5 секунд — программа будет попусту ждать 4,8 секунды, когда все ответы уже получены. Угадывать длительность чужой работы таймером нельзя: горутина должна сама сообщить, что закончила.

## Захват переменной цикла и исправление в Go 1.22+

Часто горутины запускают в цикле через анонимную функцию. Посмотрим на такой код:

```go
urls := []string{"https://go.dev", "https://pkg.go.dev", "https://go.dev/blog"}
for _, url := range urls {
	go func() {
		checkURL(url, 50*time.Millisecond)
	}()
}
```

До выхода **Go 1.22** этот фрагмент скрывал самую известную ловушку языка. Переменная `url` создавалась **один раз** на весь цикл и перезаписывалась на каждом шаге. Пока горутины успевали стартовать, цикл уже добегал до конца, и все три горутины читали последнее значение — `"https://go.dev/blog"`. В старом коде поэтому часто встречается приём `url := url` или передача параметра в анонимную функцию `go func(u string) { ... }(url)`.

Начиная с **Go 1.22**, поведение цикла `for` исправили на уровне языка: **на каждой итерации создаётся собственная копия переменной цикла**. В Go 1.24 код выше работает корректно и проверяет все три разных адреса.

Однако будьте внимательны: исправление касается только переменных, объявленных **в заголовке самого `for`**. Если переменная объявлена *снаружи* цикла и перезаписывается в теле, все замыкания по-прежнему разделят одну и ту же переменную. В сомнительных местах явная передача аргумента `go func(u string) { ... }(current)` остаётся самым прозрачным способом зафиксировать значение на момент запуска.

> [!check] Проверь понимание
> Что выведет код `go fmt.Println(x)` при `x := 1`, если сразу на следующей строке написать `x = 2` и дать горутине завершиться?
>
> Выведет `1`. Аргументы вызова `go fmt.Println(x)` вычисляются **до** старта новой горутины, в момент выполнения инструкции `go`. Изменение `x` строкой ниже на уже переданную копию не повлияет.

## Практика

**Упражнение 1 (Базовое). Проследи вывод.**  
Перед вами программа. Какие варианты вывода возможны при её запуске и почему?

```go
package main

import "fmt"

func main() {
	go fmt.Println("проверка завершена")
	fmt.Println("старт")
}
```

> [!solution] Показать решение
> Возможны два варианта: либо напечатается только `старт`, либо (реже) `старт` и `проверка завершена` в любом порядке.
>
> Как только `main()` выводит `"старт"` и доходит до закрывающей скобки, весь процесс немедленно завершается — новая горутина чаще всего даже не успевает получить процессорное время.

**Упражнение 2 (Практическое). Конкурентный запуск списка проверок.**  
Напишите программу, которая запускает в горутинах проверку слайса из 4 закладок с задержками 40, 90, 50 и 70 мс. Напечатайте индекс и URL каждой закладки по мере завершения, используя синтаксис `for i, item := range items` из Go 1.24 (временно допустим `time.Sleep(150 * time.Millisecond)` в конце `main`).

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"time"
> )
>
> type BookmarkCheck struct {
> 	URL   string
> 	Delay time.Duration
> }
>
> func main() {
> 	items := []BookmarkCheck{
> 		{URL: "https://go.dev", Delay: 40 * time.Millisecond},
> 		{URL: "https://pkg.go.dev", Delay: 90 * time.Millisecond},
> 		{URL: "https://go.dev/doc", Delay: 50 * time.Millisecond},
> 		{URL: "https://go.dev/blog", Delay: 70 * time.Millisecond},
> 	}
>
> 	for i, item := range items {
> 		go func() {
> 			time.Sleep(item.Delay)
> 			fmt.Printf("[%d] OK %s (%v)\n", i, item.URL, item.Delay)
> 		}()
> 	}
>
> 	// NOTE: временная пауза до изучения каналов и sync.WaitGroup
> 	time.Sleep(150 * time.Millisecond)
> }
> ```
> В Go 1.22+ переменные `i` и `item` уникальны для каждой итерации, поэтому замыкания печатают все четыре разных адреса в порядке возрастания задержек (40 → 50 → 70 → 90 мс).

**Упражнение 3 (Со звёздочкой \*). Где Go 1.22+ не спасёт.**  
Почему в этом фрагменте (даже на Go 1.24) три горутины почти наверняка напечатают одну и ту же строку `"https://go.dev/blog"`? Исправьте код так, чтобы каждая горутина печатала свой адрес.

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	urls := []string{"https://go.dev", "https://pkg.go.dev", "https://go.dev/blog"}
	var current string
	for _, u := range urls {
		current = u
		go func() {
			fmt.Println(current)
		}()
	}
	time.Sleep(50 * time.Millisecond)
}
```

> [!solution] Показать решение
> Переменная `current` объявлена **вне** цикла `for`, поэтому правило Go 1.22 о копии на итерацию на неё не распространяется. Все три замыкания держат ссылку на одну переменную, которая к моменту их запуска уже хранит последний элемент слайса.
>
> Исправление — убрать лишнюю внешнюю переменную и использовать `u` напрямую либо передать значение параметром в замыкание:
> ```go
> for _, u := range urls {
> 	go func(addr string) {
> 		fmt.Println(addr)
> 	}(u)
> }
> ```
