*Защищаем сервер от гигантских тел запросов, отсекаем лишние поля JSON и разделяем синтаксический брак (`400`) и нарушения доменных правил (`422`).*

Если обработчик просто вызывает `json.NewDecoder(r.Body).Decode(&in)`, сервер остаётся беззащитным сразу перед тремя проблемами. Во-первых, клиент или злоумышленник может открыть `POST`-запрос и лить в него 10 ГБ нулей, пока процесс не исчерпает оперативную память и не упадёт. Во-вторых, опечатка клиента в имени поля (`"titl": "Go"`) тихо проигнорируется, и программа запишет пустое название. В-третьих, за корректным JSON-объектом может тянуться второй объект или произвольный мусор.

В `project/final/server.go` эти три угрозы закрывает единая функция `decodeJSONBody`, а проверку смысла данных берёт на себя `ValidateInput`.

## Защита входа: `decodeJSONBody` шаг за шагом

Посмотрите на полный код разбора входящего JSON из `project/final/server.go`:

```go
const maxBodyBytes = 1 << 20 // 1 МиБ — защита от бесконтрольно больших JSON-тел

func decodeJSONBody(w http.ResponseWriter, r *http.Request, dst any) bool {
	r.Body = http.MaxBytesReader(w, r.Body, maxBodyBytes)
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()

	if err := dec.Decode(dst); err != nil {
		var maxErr *http.MaxBytesError
		if errors.As(err, &maxErr) {
			writeJSONError(w, http.StatusRequestEntityTooLarge, "размер тела запроса превышает 1 МиБ")
			return false
		}
		writeJSONError(w, http.StatusBadRequest, "некорректный JSON в теле запроса")
		return false
	}
	if err := dec.Decode(&struct{}{}); !errors.Is(err, io.EOF) {
		writeJSONError(w, http.StatusBadRequest, "тело запроса должно содержать ровно один JSON-объект")
		return false
	}
	return true
}
```

Разберём четыре уровня обороны внутри этих 20 строк:

1. **Потолочный лимит `http.MaxBytesReader`.** Эта обёртка заменяет `r.Body` и считает каждый прочитанный байт. Как только поток перешагнул `1 << 20` (1 МиБ = 1 048 576 байт), чтение прерывается с типизированной ошибкой `*http.MaxBytesError`, а соединение помечается на закрытие. Проверять её удобно через `errors.As(err, &maxErr)`, чтобы отдать точный статус `413 Request Entity Too Large`.
2. **Запрет неизвестных полей `DisallowUnknownFields()`.** Если клиент прислал `{"title":"Go","url":"https://go.dev","extra":1}`, декодер не промолчит, а вернёт ошибку. Для клиента это сигнал опечатки в названии поля.
3. **Проверка хвостового мусора.** Один вызов `dec.Decode(dst)` читает из потока только первый JSON-объект и останавливается. Если клиент прислал `{"title":"A","url":"https://a.test"}{"hack":true}`, первый `Decode` вернёт `nil`. Второй вызов `dec.Decode(&struct{}{})` обязан завершиться ровно концом потока `io.EOF`. Любой иной исход означает лишние данные после объекта.
4. **Единая подпись `bool`.** Функция сама пишет HTTP-ошибку в `w`, поэтому обработчик остаётся предельно чистым: `if !decodeJSONBody(w, r, &in) { return }`.

## Два уровня проверки: синтаксис против смысла

Успешный разбор JSON гарантирует только одно: клиент прислал валидный JSON-документ с правильными типами полей. Но строка `"ftp://go.dev"` или пустой заголовок `"   "` с точки зрения JSON вполне корректны! Поэтому следом в дело вступает функция `ValidateInput` из `project/final/store.go`:

```go
func ValidateInput(title, rawURL string, tags []string) (string, string, []string, error) {
	cleanTitle := strings.TrimSpace(title)
	if cleanTitle == "" {
		return "", "", nil, fmt.Errorf("%w: поле title обязательно", ErrValidation)
	}
	if len([]rune(cleanTitle)) > 200 {
		return "", "", nil, fmt.Errorf("%w: поле title не должно превышать 200 символов", ErrValidation)
	}

	cleanURL := strings.TrimSpace(rawURL)
	parsed, err := url.Parse(cleanURL)
	if err != nil || (parsed.Scheme != "http" && parsed.Scheme != "https") || parsed.Host == "" {
		return "", "", nil, fmt.Errorf("%w: укажите корректный http(s) URL", ErrValidation)
	}

	cleanTags := normalizeTags(tags)
	return cleanTitle, cleanURL, cleanTags, nil
}
```

Обратите внимание на три важные инженерные детали:

- **Нормализация вместе с валидацией.** Функция не просто отвечает «да/нет», а возвращает очищенные данные: обрезает пробелы вокруг `title` и `url`, а теги в `normalizeTags` приводит к нижнему регистру, убирает пустые, удаляет дубли и сортирует. В результате `"Go"` и `"go"` не плодят два разных тега.
- **Подсчёт длины в рунах `len([]rune(cleanTitle))`.** В Модуле 2 мы выяснили, что `len(s)` в Go считает байты UTF-8, а не символы. Русская строка из 150 букв занимает ~300 байт: проверка через `len(cleanTitle) > 200` несправедливо отвергала бы кириллицу.
- **Проверка схемы и хоста в `url.Parse`.** Разбор `url.Parse("https://")` не вернёт ошибку `err`, но поле `parsed.Host` окажется пустым. А схема проверяется белым списком (`http` или `https`), чтобы в базу закладок не просочились ссылки вроде `javascript:alert(1)` или `ftp://...`.

Ошибки `ValidateInput` оборачивают сентинел `ErrValidation` — дальше `Server` поймает их через `errors.Is(err, ErrValidation)` и превратит в статус `422 Unprocessable Entity`.

## Подводный камень: ловушка `io.ReadAll(r.Body)`

Новички часто пишут `body, err := io.ReadAll(r.Body)` до `json.Unmarshal`. Без `http.MaxBytesReader` такой вызов сперва загрузит весь огромный поток байтов в срез в оперативной памяти — и только потом вы узнаете его размер. Потоковый `json.NewDecoder` поверх `http.MaxBytesReader` останавливает чтение на первом байтe сверх лимита `1 МиБ`, не выделяя лишней памяти.

>
> Первый `dec.Decode(&in)` прочитает объект `Bookmark`, а второй `dec.Decode(&struct{}{})` встретит токен `123` вместо `io.EOF`. Сервер ответит статусом `400 Bad Request` и текстом `"тело запроса должно содержать ровно один JSON-объект"`.

**Упражнение 3 (Со звёздочкой \*). Пустое тело запроса.**  
Что вернёт `decodeJSONBody`, если клиент пришлёт `POST /api/v1/bookmarks` вообще с **пустым** телом (0 байт)? Объясните почему и предложите понятное сообщение об ошибке.

> [!solution] Показать решение
> На пустом теле самый первый вызов `dec.Decode(dst)` вернёт `io.EOF` (это не `nil`, поэтому `decodeJSONBody` пойдёт в ветку `err != nil` и вернёт `400 Bad Request` с общим текстом `"некорректный JSON в теле запроса"`).
