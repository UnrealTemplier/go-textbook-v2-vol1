*Почему склейка строк оператором `+` в цикле сжигает память, как собирать текст через `strings.Builder` и чем `bytes.Buffer` отличается при работе с потоками.*

Нужно собрать CSV-отчёт из 10 000 закладок `BookmarkFlow` в одну строку. Первый порыв — написать цикл с обычным сложением:

```go
var report string
for _, title := range titles {
	report += title + "\n"
}
```

На десяти элементах цикл отработает мгновенно. На десяти тысячах — начнёт заметно тормозить и выделит сотни мегабайт временной памяти. Проблема не в самом цикле, а в том, как устроены строки в Go.

## Честная модель: почему `+=` в цикле копирует всё заново

Строка (`string`) в Go **неизменяема** (*immutable*). Изменить байт внутри существующей строки нельзя. Когда вы пишете `report += part`, рантайм Go обязан выделить в памяти новый участок размером `len(report) + len(part)`, скопировать туда **всю** старую строку, дописать в конец `part` и выбросить прежний буфер.

Посмотрим на числа. Допустим, мы склеиваем в цикле 1 000 фрагментов по 10 байтов. Итоговая строка займёт всего 10 КБ. Но на шаге 1 скопируется 10 байтов, на шаге 2 — 20 байтов, на шаге 3 — 30 байтов, и так далее:

```text
Шаг 1:   [10 Б]
Шаг 2:   [10 Б][10 Б]                     (скопировано 20 Б)
Шаг 3:   [10 Б][10 Б][10 Б]               (скопировано 30 Б)
...
Шаг 1000: итого скопировано 10 * (1 + 2 + ... + 1000) ≈ 5 000 000 Б (5 МБ!)
```

Объём копируемой памяти растёт пропорционально **квадрату** числа шагов: в 10 раз больше строк — примерно в 100 раз больше скопированных байтов. На 100 000 коротких строк такой цикл перегонит через память гигабайты мусора.

## `strings.Builder` и метод `Grow`

Пакет `strings` предлагает для сборки строк `strings.Builder`. Внутри него живёт растущий байтовый слайс `[]byte`, который расширяется редко, а в конце `String()` отдаёт готовую строку без лишнего копирования. `strings.Builder` реализует `io.Writer` и готов к работе из нулевого значения:

```go
var b strings.Builder
b.Grow(estimatedBytes) // заранее выделяем ёмкость одним куском
for _, title := range titles {
	b.WriteString(title)
	b.WriteByte('\n')
}
report := b.String()
```

Вызов `b.Grow(n)` полезен, когда примерный итоговый размер известен заранее: буфер выделится один раз вместо серии перевыделений.

> [!warning] Не копируйте `strings.Builder` после первой записи
> Передавайте непустой `Builder` только по указателю `*strings.Builder`: запись в копию структуры вызовет панику `strings: illegal use of non-zero Builder copied by value`.

## Повседневные инструменты `strings`

* `strings.Cut(s, sep)` — делит строку по **первому** `sep` на `(before, after, found)` без выделения слайса. Идеально для пар `"ключ=значение"`.
* `strings.Split(s, sep)` и `strings.Join(elems, sep)` — разбиение по разделителю и обратная склейка.
* `strings.Fields(s)` — режет по любым пробельным символам, отбрасывая пустые фрагменты.
* `strings.TrimSpace`, `HasPrefix`, `Contains` — очистка и проверки без лишних копий.
* `strings.NewReplacer(old1, new1, ...)` — один раз готовит набор замен и применяет его через `Replace(s)` или напрямую в `io.Writer`.

## Пакет `bytes` и `bytes.Buffer`

Если данные уже лежат в `[]byte`, преобразование `string(b)` создаёт копию. Пакет `bytes` повторяет функции `strings` напрямую для байтовых слайсов: `bytes.Equal(a, b)` (слайсы в Go нельзя сравнить через `==`), `bytes.Contains`, `bytes.Cut`, `bytes.TrimSpace`.

Тип `bytes.Buffer` — изменяемый буфер в памяти, реализующий сразу **`io.Reader` и `io.Writer`**. Правило выбора простое: нужна только итоговая `string` — берите `strings.Builder`; нужно записать байты и затем отдать их как `io.Reader` — берите `bytes.Buffer`.

Посмотрим оба инструмента вместе:

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"strings"
)

var slugReplacer = strings.NewReplacer(" ", "-", "_", "-", "/", "-")

func formatCatalog(entries []string) string {
	var b strings.Builder
	b.Grow(len(entries) * 32)

	for _, raw := range entries {
		key, val, ok := strings.Cut(raw, "=")
		if !ok {
			continue
		}
		tags := strings.Fields(val)
		slug := slugReplacer.Replace(strings.ToLower(strings.TrimSpace(key)))

		b.WriteString(slug)
		b.WriteString(": ")
		b.WriteString(strings.Join(tags, ", "))
		b.WriteByte('\n')
	}
	return b.String()
}

func main() {
	entries := []string{
		" Go Docs = docs   stdlib   reference ",
		"BrokenLineWithoutEquals",
		"Effective_Go = style idioms",
	}

	out := formatCatalog(entries)

	var buf bytes.Buffer
	buf.WriteString(out)

	raw, _ := io.ReadAll(&buf)
	fmt.Print(string(raw))
	fmt.Println("Содержит stdlib:", bytes.Contains(raw, []byte("stdlib")))
	fmt.Println("Равно эталону:", bytes.Equal(raw, []byte(out)))
}
```

Вывод терминала:

```text
go-docs: docs, stdlib, reference
effective-go: style, idioms
Содержит stdlib: true
Равно эталону: true
```

Здесь `strings.Cut` аккуратно отбрасывает битую строку без `=`, `strings.Fields` схлопывает лишние пробелы, `slugReplacer` создан один раз на уровне пакета, а `&buf` служит сначала приёмником (`WriteString`), а затем источником для `io.ReadAll`.

## Подводные камни

**Ловушка 1. `strings.Split` на пустой строке.**  
Вызов `strings.Split("", ",")` возвращает слайс длины **1**: `[]string{""}`, а не пустой слайс. В коде с тегами это приводит к фантомному пустому тегу `""`. Для разбора слов по пробелам берите `strings.Fields("")` (он вернёт пустой слайс длиной 0), а перед `strings.Split` проверяйте `if s == ""`.

**Ловушка 2. Игнорирование `bytes.Equal` при сравнении слайсов.**  
Попытка написать `if a == b` для двух `[]byte` не скомпилируется:

```text
// compile error: invalid operation: a == b (slice can only be compared to nil)
```

Всегда сравнивайте содержимое байтовых слайсов через `bytes.Equal(a, b)`.

> [!check] Проверь понимание
> Что вернёт `len(strings.Split("", ","))` и что вернёт `len(strings.Fields("   \t\n "))`?
>
> `1` и `0`. `Split` на пустой строке отдаёт один пустой элемент `[""]`, а `Fields` пропускает любые пробельные символы и при их отсутствии возвращает пустой слайс `[]string{}`.

## Практика

**Упражнение 1 (Базовое). Разбор пары `ключ: значение` через `strings.Cut`.**  
Напишите функцию `ParseHeader(line string) (name, value string, ok bool)`, которая делит строку по первому двоеточию `":"`, убирает лишние пробелы вокруг обеих частей и возвращает `ok == false`, если двоеточия нет или имя пустое. Убедитесь, что строка `"URL: https://go.dev"` не ломается из-за второго двоеточия в `https://`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"strings"
> )
>
> func ParseHeader(line string) (name, value string, ok bool) {
> 	k, v, found := strings.Cut(line, ":")
> 	if !found {
> 		return "", "", false
> 	}
> 	k = strings.TrimSpace(k)
> 	v = strings.TrimSpace(v)
> 	if k == "" {
> 		return "", "", false
> 	}
> 	return k, v, true
> }
>
> func main() {
> 	fmt.Println(ParseHeader("URL: https://go.dev")) // Вывод: URL https://go.dev true
> 	fmt.Println(ParseHeader(": value"))             // Вывод:   false
> }
> ```
> `strings.Cut` останавливается ровно на первом `":"`, поэтому `https://go.dev` целиком остаётся в `value`.

**Упражнение 2 (Практическое). Быстрая сборка строки повторов.**  
Напишите функцию `JoinNumbers(prefix string, count int) string`, которая с помощью `strings.Builder` и предварительного `Grow` собирает строку вида `"item-1, item-2, item-3"` для `count == 3` (и пустую строку для `count <= 0`). Не используйте `+=` в цикле.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"strings"
> )
>
> func JoinNumbers(prefix string, count int) string {
> 	if count <= 0 {
> 		return ""
> 	}
> 	var b strings.Builder
> 	b.Grow(count * (len(prefix) + 6))
> 	for i := 1; i <= count; i++ {
> 		if i > 1 {
> 			b.WriteString(", ")
> 		}
> 		fmt.Fprintf(&b, "%s-%d", prefix, i)
> 	}
> 	return b.String()
> }
>
> func main() {
> 	fmt.Println(JoinNumbers("item", 3)) // Вывод: item-1, item-2, item-3
> 	fmt.Println(JoinNumbers("item", 0)) // Вывод:
> }
> ```
> Передавая `&b` в `fmt.Fprintf`, мы пишем напрямую в буфер `strings.Builder` без промежуточных строк.

**Упражнение 3 (Со звёздочкой \*). Двойное чтение через `bytes.Buffer`.**  
Напишите функцию `MirrorToUpper(r io.Reader) ([]byte, error)`, которая читает байты из `r` в `bytes.Buffer`, переводит их в верхний регистр через `bytes.ToUpper` и возвращает результат. Проверьте, почему после первого `io.ReadAll(&buf)` повторный вызов `buf.Bytes()` вернёт пустой слайс.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"bytes"
> 	"fmt"
> 	"io"
> 	"strings"
> )
>
> func MirrorToUpper(r io.Reader) ([]byte, error) {
> 	var buf bytes.Buffer
> 	if _, err := io.Copy(&buf, r); err != nil {
> 		return nil, err
> 	}
> 	return bytes.ToUpper(buf.Bytes()), nil
> }
>
> func main() {
> 	res, err := MirrorToUpper(strings.NewReader("bookmark flow"))
> 	fmt.Println(string(res), err) // Вывод: BOOKMARK FLOW <nil>
>
> 	var b bytes.Buffer
> 	b.WriteString("go")
> 	_, _ = io.ReadAll(&b)
> 	fmt.Println("после ReadAll:", len(b.Bytes())) // Вывод: после ReadAll: 0
> }
> ```
> `bytes.Buffer` хранит внутреннюю позицию чтения. Каждый `Read` (в том числе внутри `io.ReadAll`) сдвигает этот указатель вперёд, пока непрочитанных байтов не останется — после чего `b.Bytes()` возвращает пустой срез.
