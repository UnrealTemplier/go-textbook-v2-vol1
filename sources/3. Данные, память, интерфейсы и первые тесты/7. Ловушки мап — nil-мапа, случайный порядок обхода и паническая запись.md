*Четыре сюрприза мап в Go: почему запись в неинициализированную мапу роняет программу, зачем порядок обхода перемешивается и почему нельзя взять адрес элемента.*

> «Не у каждого значения есть адрес, но у каждой переменной он есть.»  
> — Алан Донован и Брайан Керниган, *The Go Programming Language*

На прошлом уроке мапы выглядели безобидно. Но стоит по привычке написать `var counts map[string]int` (как `var tags []string`) и записать первую пару — программа мгновенно падает с паникой. А цикл `for range` каждый раз печатает ключи в новом порядке.

За каждым из четырёх сюрпризов стоит конкретное правило устройства мап в Go. Разберём их все.

## Ловушка 1. `nil`-мапа: читать можно, писать — паника

Нулевое значение переменной типа `map[K]V` — **`nil`**: переменная не указывает ни на какое хранилище.

```go
var counts map[string]int // counts == nil

fmt.Println(len(counts))  // 0 — безопасно
fmt.Println(counts["go"]) // 0 — безопасно
delete(counts, "go")      // безопасно
clear(counts)             // безопасно

counts["go"] = 1          // паника во время выполнения!
```

В терминале последняя строка остановит программу:

```text
panic: assignment to entry in nil map
```

У `nil`-слайса `append` выделяет массив и возвращает новый заголовок. У мапы запись `m[k] = v` не переприсваивает `m`, поэтому класть пару в `nil` некуда.

| Операция | `var m map[string]int` (`nil`) | `m := make(map[string]int)` (пустая) |
|---|---|---|
| `m == nil` | `true` | `false` |
| `len(m)` / чтение `v, ok := m["go"]` | `0` / `0, false` | `0` / `0, false` |
| `for k, v := range m` | 0 итераций | 0 итераций |
| `delete(m, "go")` / `clear(m)` | безопасно | безопасно |
| `m["go"] = 1` | **`panic`** | добавляет пару |

Правило простое: **перед записью всегда инициализируйте мапу через `make` или `map[K]V{}`**.

## Ловушка 2. Намеренно случайный порядок обхода

При каждом запуске `for tag, n := range counts` ключи выходят в разном порядке. Это **намеренная защита** рантайма Go: авторы языка специально перемешивают старт обхода, чтобы код не завязывался на внутреннее расположение элементов.

Нужен стабильный порядок для отчёта или теста — отсортируйте ключи явно. В Go 1.23–1.24 это пишется в одну строку через `slices.Sorted(maps.Keys(m))` (классический вариант — собрать ключи в слайс и вызвать `slices.Sort(keys)`):

```go
package main

import (
	"fmt"
	"maps"
	"slices"
)

func main() {
	tagCounts := map[string]int{
		"go":   4,
		"cli":  2,
		"docs": 3,
	}

	// Стабильный алфавитный обход через slices.Sorted и maps.Keys
	for _, tag := range slices.Sorted(maps.Keys(tagCounts)) {
		fmt.Printf("%-6s -> %d\n", tag, tagCounts[tag])
	}
}
```

Вывод гарантированно одинаков при каждом запуске:

```text
cli    -> 2
docs   -> 3
go     -> 4
```

## Ловушка 3. Элементы мапы неадресуемы (`&m[k]`)

Вы уже знаете, что можно взять адрес элемента слайса: `p := &tags[0]`. Попробуем проделать то же самое с мапой:

```go
counts := map[string]int{"go": 4}
p := &counts["go"]
// compile error: invalid operation: cannot take address of counts["go"] (map index expression of type int)
```

Компилятор наотрез отказывается. Причина — в устройстве памяти: по мере добавления новых ключей мапа расширяется и переносит свои пары в другую область памяти. Если бы Go позволил сохранить указатель на `counts["go"]`, то после очередной записи в ту же мапу указатель `p` внезапно стал бы смотреть в устаревшую ячейку.

Чтобы не допустить тихой порчи памяти, Go запрещает брать адрес элемента мапы на этапе компиляции. У этого запрета два практических следствия:

- Если нужно изменить составное значение в мапе, прочитайте его в переменную, измените и запишите обратно: `v := m[k]; ...; m[k] = v`.
- Либо сразу храните указатели в качестве значений (`map[int]*int`, а позже — `map[int]*Bookmark`): сам указатель можно скопировать при чтении, а указывает он на стабильный адрес вне мапы.

## Ловушка 4. Передача мапы в функцию и скрытые мутации

На втором уроке этого модуля мы видели, что обычные переменные передаются в функцию по значению (копируется само значение). С мапой ситуация тоньше. Переменная типа `map[K]V` — это не вся коллекция целиком, а небольшой **дескриптор-ссылка** на внутреннее хранилище в памяти:

```text
  main: counts ──────┐
                     ├──▶ [ внутреннее хранилище: "go": 4, "cli": 2 ]
  func: m      ──────┘
```

При вызове `addTag(counts, "docs")` копируется только этот дескриптор, поэтому обе переменные указывают на **одно и то же** хранилище:

```go
package main

import (
	"fmt"
	"maps"
)

func addTag(m map[string]int, tag string) {
	m[tag]++
}

func resetLocal(m map[string]int) {
	m = make(map[string]int) // меняется только локальная копия дескриптора
	m["temp"] = 99
}

func main() {
	counts := map[string]int{"go": 1}
	addTag(counts, "cli")
	resetLocal(counts)

	backup := maps.Clone(counts)
	backup["go"] = 100

	fmt.Println("counts:", counts)
	fmt.Println("backup:", backup)
}
```

Вывод (порядок пар внутри `fmt.Println` для мапы всегда отсортирован самим пакетом `fmt`):

```text
counts: map[cli:1 go:1]
backup: map[cli:1 go:100]
```

Посмотрите на три факта в этом примере:

1. `addTag` изменил исходную мапу `counts` без всякого `*map[...]`.
2. `resetLocal` переприсвоил локальный параметр `m` новой мапе, и `counts` в `main` этого не заметил. По той же причине нельзя передать `nil`-мапу в функцию, проинициализировать её там через `m = make(...)` и ждать, что снаружи она перестанет быть `nil`.
3. Если нужно защитить исходную мапу от чужих правок, создайте поверхностную копию через `maps.Clone(counts)`.

> [!check] Проверь понимание
> Что произойдёт при выполнении этого кода?
> ```go
> func initCounts(m map[string]int) {
> 	m = make(map[string]int)
> 	m["go"] = 1
> }
>
> var counts map[string]int
> initCounts(counts)
> fmt.Println(len(counts), counts == nil)
> ```
>
> Напечатает `0 true`. В `initCounts` передалась копия `nil`-дескриптора. Строка `m = make(...)` записала новый дескриптор только в локальную переменную `m`, а `counts` в вызывающем коде так и осталась `nil`.

## Практика

**Упражнение 1 (Базовое). Почини панику.**  
Код ниже должен сохранить коды ответа для двух ссылок и удалить устаревшую запись, но падает при запуске. Найдите строку, которая вызывает панику, объясните, почему `delete` строкой выше не падает, и исправьте программу.

```go
package main

import "fmt"

func main() {
	var status map[string]int
	delete(status, "https://old.example")
	status["https://go.dev"] = 200
	fmt.Println(status)
}
```

> [!solution] Показать решение
> Панику вызывает строка `status["https://go.dev"] = 200` (`panic: assignment to entry in nil map`), потому что `status` объявлена через `var` и равна `nil`. Вызов `delete` на `nil`-мапе по спецификации Go безопасен и просто ничего не делает.
>
> Исправление — инициализировать мапу через `make` или пустой литерал:
> ```go
> status := make(map[string]int)
> delete(status, "https://old.example")
> status["https://go.dev"] = 200
> fmt.Println(status)
> ```

**Упражнение 2 (Практическое). Стабильный отчёт по тегам.**  
Напишите функцию `formatTagReport(counts map[string]int) string`, которая возвращает многострочный отчёт вида `cli: 2\ndocs: 3\ngo: 4\n` с ключами строго в алфавитном порядке. Для `nil` или пустой мапы функция должна возвращать пустую строку `""`. Используйте `slices.Sorted(maps.Keys(counts))`.

> [!solution] Показать решение
> ```go
> func formatTagReport(counts map[string]int) string {
> 	if len(counts) == 0 {
> 		return ""
> 	}
> 	var out string
> 	for _, tag := range slices.Sorted(maps.Keys(counts)) {
> 		out += fmt.Sprintf("%s: %d\n", tag, counts[tag])
> 	}
> 	return out
> }
> ```
> Проверка `len(counts) == 0` одновременно закрывает и пустую, и `nil`-мапу. Обход через `slices.Sorted(maps.Keys(counts))` гарантирует одинаковый порядок строк при каждом запуске.

**Упражнение 3 (Со звёздочкой \*). Проследи вывод.**  
Что напечатает программа ниже и почему?

```go
package main

import "fmt"

func mutate(m map[string]int) {
	m["a"] = 10
	m = map[string]int{"b": 20}
	m["c"] = 30
}

func main() {
	data := map[string]int{"a": 1}
	mutate(data)
	fmt.Println(data)
}
```

> [!solution] Показать решение
> Программа напечатает `map[a:10]`.
>
> Первая строка `m["a"] = 10` меняет общую с `data` мапу, поэтому `"a"` становится `10`. Затем `m = map[string]int{"b": 20}` перенаправляет локальный параметр `m` на совершенно новую мапу в памяти — дальнейшая запись `m["c"] = 30` меняет уже её и никак не влияет на `data` в `main`.
