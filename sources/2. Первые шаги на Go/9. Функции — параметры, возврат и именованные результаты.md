*Как разбивать код на небольшие функции, почему Go всегда передаёт аргументы по значению и когда именованные результаты помогают, а когда мешают.*

> «Пишите ясно — не умничайте.»  
> — Брайан Керниган, *UNIX: A History and a Memoir*

Пока все примеры помещались в 15 строк внутри `func main()`. Но стоит программе научиться одновременно проверять URL, обрезать длинные названия и форматировать строки таблицы, как `main` превращается в простыню, в которой невозможно найти ошибку.

Функции в Go устроены предельно прямолинейно: никаких перегрузок по имени (как в C++ и Java), никаких значений параметров по умолчанию (как в Python). За счёт этих ограничений каждый вызов функции читается однозначно.

## Объявление функции и группировка параметров

Функция начинается с ключевого слова `func`, затем идут имя, список параметров в круглых скобках и тип возвращаемого значения:

```go
package main

import "fmt"

// formatLine собирает читаемую строку закладки.
func formatLine(id int, title, rawURL string) string {
	return fmt.Sprintf("#%d | %s -> %s", id, title, rawURL)
}

func main() {
	line := formatLine(1, "Документация Go", "https://go.dev/doc")
	fmt.Println(line)
}
```

Вывод:

```text
#1 | Документация Go -> https://go.dev/doc
```

Обратите внимание на две детали сигнатуры:
1. Если несколько подряд идущих параметров имеют одинаковый тип (`title string, rawURL string`), тип можно указать один раз в конце: `title, rawURL string`.
2. Если функция ничего не возвращает (например, только печатает шапку таблицы), после скобок с параметрами сразу ставится `{`.

В отличие от Python или JavaScript, в Go **нет аргументов по умолчанию** и **нет перегрузки функций** (двух функций с одним именем и разным набором параметров). Если нужны два варианта поведения — дают два честных имени, например `truncateRunes(s, limit)` и `truncateDefault(s)`. Читателю не приходится гадать, какая именно версия функции вызовется.

## Главный закон передачи аргументов: всегда по значению

Запомните правило, которое в Модуле 3 сэкономит вам часы отладки: **в Go все аргументы всегда передаются по значению (*pass by value*)**.

Когда вы вызываете `bump(visits)`, Go **копирует** значение переменной `visits` в отдельный параметр функции. Изменение параметра внутри функции никак не затрагивает исходную переменную вызывающего кода:

```go
package main

import "fmt"

func tryIncrement(counter int) {
	counter++
	fmt.Println("Внутри функции:", counter)
}

func incremented(counter int) int {
	return counter + 1
}

func main() {
	visits := 10

	tryIncrement(visits)
	fmt.Println("После tryIncrement:", visits) // Всё ещё 10!

	visits = incremented(visits)
	fmt.Println("После incremented:", visits) // Теперь 11
}
```

Вывод:

```text
Внутри функции: 11
После tryIncrement: 10
После incremented: 11
```

Вот что происходит в памяти во время вызова `tryIncrement(visits)`:

```text
Память main()             Память tryIncrement()
+--------------+          +---------------+
| visits = 10  | --копия->| counter = 10  | -> становится 11, затем исчезает
+--------------+          +---------------+
```

Хотите получить обновлённое значение — верните его через `return` и присвойте обратно (`visits = incremented(visits)`). Позже, в Модуле 3, мы увидим, как передавать в функцию адрес переменной, но даже тогда сам адрес всё равно передаётся по значению.

## Именованные возвращаемые значения и ловушка «голого `return`»

В Go возвращаемому значению можно дать имя прямо в сигнатуре функции. Тогда оно автоматически создаётся как локальная переменная с нулевым значением:

```go
// splitKopecks раскладывает сумму в копейках на рубли и остаток копеек.
func splitKopecks(total int64) (rub, kop int64) {
	rub = total / 100
	kop = total % 100
	return // «голый» return возвращает текущие значения rub и kop
}
```

На первый взгляд удобно, но у этой возможности есть **острая грань**:
* **Когда именованные результаты полезны:** когда функция возвращает два значения одного типа (как `rub, kop int64` или `lat, lon float64`) — имена в заголовке работают как документация, сразу объясняя, что идёт первым, а что вторым.
* **Когда они вредят:** «голый `return`» (*naked return*) в функции длиннее 5–7 строк заставляет читателя листать вверх к заголовку, чтобы понять, что именно возвращается. Профессиональные Go-разработчики либо пишут явный `return rub, kop` даже при именованных результатах, либо используют голый `return` только в совсем крошечных функциях.

## Рекурсия в два слова (и почему осторожнее с ней)

Функция в Go может вызывать сама себя — это называется **рекурсией**. Любая рекурсия обязана иметь базовый случай (условие остановки), иначе вызовы будут бесконечно накапливаться в памяти, пока рантайм не остановит программу с ошибкой переполнения стека (`stack overflow`). В обычном коде Go чаще выбирают простой и понятный цикл `for`, а к рекурсии возвращаются там, где данные сами устроены как дерево (подробнее — в Модуле 6).

> [!check] Проверь понимание
> Что выведет программа?
> ```go
> func normalize(s string) {
> 	s = strings.TrimSpace(s)
> }
> func main() {
> 	title := "  Go  "
> 	normalize(title)
> 	fmt.Printf("%q\n", title)
> }
> ```
>
> Выведет `"  Go  "` с пробелами! Аргумент `title` передан в `normalize` по значению; переприсваивание локальной копии `s` внутри `normalize` не меняет `title` в `main`. Функция должна возвращать `string`, а вызывающий код — сохранять результат: `title = normalize(title)`.

## Практика

**Упражнение 1 (Базовое). Функция форматирования цены.**  
Напишите функцию `formatPrice(kopecks int64) string`, которая принимает сумму в копейках (например, `5405`) и возвращает строку `"54.05 руб."`. Проверьте её на `0`, `5`, `1990` и `5405`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func formatPrice(kopecks int64) string {
> 	rub := kopecks / 100
> 	kop := kopecks % 100
> 	return fmt.Sprintf("%d.%02d руб.", rub, kop)
> }
>
> func main() {
> 	fmt.Println(formatPrice(0))    // 0.00 руб.
> 	fmt.Println(formatPrice(5))    // 0.05 руб.
> 	fmt.Println(formatPrice(1990)) // 19.90 руб.
> 	fmt.Println(formatPrice(5405)) // 54.05 руб.
> }
> ```
> Выделение форматирования в чистую функцию избавляет от дублирования арифметики `/ 100` и `% 100` по всему коду.

**Упражнение 2 (Практическое). Безопасное усечение строки функцией.**  
Оформите решение из Упражнения 2 прошлого урока в переиспользуемую функцию `truncate(s string, maxRunes int) string`. Если `maxRunes <= 0`, возвращайте `""`; если в `s` не больше `maxRunes` рун — возвращайте `s` без изменений; иначе — первые `maxRunes` рун плюс `"..."`. Проверьте на `"Go"`, `"Документация по Go"` (`maxRunes = 10`) и `""`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func truncate(s string, maxRunes int) string {
> 	if maxRunes <= 0 {
> 		return ""
> 	}
> 	count := 0
> 	for byteIdx := range s {
> 		if count == maxRunes {
> 			return s[:byteIdx] + "..."
> 		}
> 		count++
> 	}
> 	return s
> }
>
> func main() {
> 	fmt.Println(truncate("Go", 10))                 // Go
> 	fmt.Println(truncate("Документация по Go", 10)) // Документац...
> 	fmt.Println(truncate("", 5))                    // (пусто)
> }
> ```
> Заметьте, как ранний `return` прямо внутри цикла избавил от лишней переменной `cutAt` и флагов.

**Упражнение 3 (Со звёздочкой \*). Что сломается?**  
Найдите две ошибки компиляции в этом коде и объясните их причины:

```go
package main

import "fmt"

func clamp(val, minVal, maxVal int) int {
	if val < minVal {
		return minVal
	}
	if val > maxVal {
		return maxVal
	}
}

func main() {
	fmt.Println(clamp(15, 0, 10))
}
```
И второй вопрос: почему Go не позволит рядом объявить вторую функцию `func clamp(val, minVal, maxVal float64) float64`?

> [!solution] Показать решение
> 1. В `clamp` не все ветки выполнения заканчиваются `return`: если `minVal <= val && val <= maxVal`, функция доходит до закрывающей `}` без возврата значения (`missing return`). Нужно дописать `return val` в конце.
> 2. В Go нет перегрузки функций по типам аргументов: два объявления с одинаковым именем `clamp` в одном пакете вызовут ошибку `clamp redeclared in this block`. В Go им дают разные имена (`clampInt` и `clampFloat`) либо — начиная с Go 1.18 — пишут обобщённую функцию (мы изучим это в Модуле 3).
