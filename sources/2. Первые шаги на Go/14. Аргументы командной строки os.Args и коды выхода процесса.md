*Как читать команды и параметры, переданные программе из терминала через `os.Args`, куда правильно печатать ошибки и почему `os.Exit` не выполняет `defer`.*

> «Часть этой философии — использование текстовых файлов как общего знаменателя. Множество небольших консольных программ UNIX (утилит) читают текстовый файл, что-то с ним делают и записывают результат в другой текстовый файл. Эти утилиты можно выстраивать в цепочки, по-разному обрабатывая текст.»  
> — Чарльз Петцольд, *Code (2nd ed.)*

До сих пор, чтобы проверить программу на новом вводе, вам приходилось открывать `main.go`, менять строку в коде и снова запускать `go run .`. Настоящая консольная утилита так не работает: пользователь передаёт команду и аргументы прямо при запуске из терминала — например, `bookmark add "Go Doc" https://go.dev/doc` — а при ошибке программа не просто печатает текст, но и сообщает операционной системе ненулевой **код завершения**.

В этом уроке соберём каркас настоящей CLI-программы на пакете `os`.

## Как устроен `os.Args`

Когда операционная система запускает процесс, она передаёт ему список строковых аргументов, на которые терминал разбил командную строку по пробелам (учитывая кавычки). В Go этот список доступен в переменной **`os.Args`** типа `[]string` (динамический список строк — подробно о том, как устроены такие списки в памяти, мы поговорим в Модуле 3; сейчас достаточно знать два действия: длину `len(os.Args)` и доступ по индексу `os.Args[i]`).

Самая частая неожиданность для новичка — что лежит под нулевым индексом:

```text
Команда в терминале:
  ./bookmark   add   "Go Doc"   https://go.dev/doc
       │        │       │              │
  os.Args[0]   [1]     [2]            [3]
  (имя прогр.) (команда и её аргументы: os.Args[1:])
```

* **`os.Args[0]`** — путь или имя самой запущенной программы (при `go run .` там окажется путь к временному бинарнику вроде `/tmp/go-build.../exe/hello`).
* **`os.Args[1]`**, **`os.Args[2]`** и далее — аргументы, которые передал пользователь.
* **`os.Args[1:]`** — удобная запись «все элементы списка, начиная с индекса 1».
* **`len(os.Args)`** — общее количество элементов, **включая** `os.Args[0]`. Если пользователь запустил программу вообще без аргументов, `len(os.Args)` равно **`1`**, а не `0`.

Попытка прочитать `os.Args[1]` без проверки длины приведёт к немедленному аварийному падению программы (*panic*):

```text
panic: runtime error: index out of range [1] with length 1
```

Поэтому правило железное: **всегда проверяйте `len(os.Args)` перед обращением к элементам по индексу**.

## Стандартный вывод (`stdout`) против потока ошибок (`stderr`)

В [[6. Зачем нужна операционная система]] мы упоминали, что у каждого консольного процесса есть отдельные потоки вывода:
* **`os.Stdout`** (стандартный вывод) — сюда печатают `fmt.Println` и `fmt.Printf`. Это **полезный результат** работы утилиты, который можно перенаправить в файл (`./bookmark list > out.txt`) или в другую программу.
* **`os.Stderr`** (поток ошибок) — сюда пишут сообщения об ошибках и диагностику: `fmt.Fprintln(os.Stderr, "Ошибка:", err)`.

Зачем разделять эти два потока? Если пользователь сохраняет список закладок в файл командой `./bookmark list > list.txt`, а программа завершилась с ошибкой, сообщение об ошибке уйдёт в `os.Stderr` и появится на экране терминала, **не испортив** содержимое файла `list.txt`.

## Коды выхода процесса (`os.Exit`) и паттерн функции `run`

Каждая программа при завершении отдаёт операционной системе одно целое число — **код выхода** (*exit code*):
* **`0`** — успех (именно `0` возвращает Go, когда `main()` завершается штатно).
* **Ненулевое число** (обычно `1` или `2`) — ошибка. Благодаря этому скрипты и цепочки команд вроде `go build . && ./app` знают, что предыдущий шаг упал, и останавливаются.

В Go код выхода задаётся вызовом `os.Exit(1)`. Но у `os.Exit` есть критическая особенность, о которой нужно помнить всегда:

**`os.Exit` обрывает процесс немедленно и НЕ выполняет ни один отложенный `defer`!**

Поэтому в профессиональном Go `main()` оставляют крошечной оболочкой в 5 строк, а всю настоящую работу выносят в функцию `run(args []string) error`:

```go
package main

import (
	"errors"
	"fmt"
	"os"
	"strconv"
)

var (
	ErrNoArgs      = errors.New("укажите команду: sum <a> <b> или echo <текст>")
	ErrUnknownCmd  = errors.New("неизвестная команда")
	ErrBadArgument = errors.New("некорректный аргумент")
)

func run(args []string) error {
	// Любой defer внутри run() гарантированно выполнится до os.Exit в main!
	if len(args) == 0 {
		return ErrNoArgs
	}

	switch args[0] {
	case "echo":
		if len(args) != 2 {
			return fmt.Errorf("%w: формат echo <текст>", ErrBadArgument)
		}
		fmt.Println(args[1])
		return nil

	case "sum":
		if len(args) != 3 {
			return fmt.Errorf("%w: формат sum <a> <b>", ErrBadArgument)
		}
		a, err := strconv.Atoi(args[1])
		if err != nil {
			return fmt.Errorf("%w: %q не число", ErrBadArgument, args[1])
		}
		b, err := strconv.Atoi(args[2])
		if err != nil {
			return fmt.Errorf("%w: %q не число", ErrBadArgument, args[2])
		}
		fmt.Println(a + b)
		return nil

	default:
		return fmt.Errorf("%w: %q", ErrUnknownCmd, args[0])
	}
}

func main() {
	if err := run(os.Args[1:]); err != nil {
		fmt.Fprintln(os.Stderr, "Ошибка:", err)
		os.Exit(1)
	}
}
```

Проверьте программу в терминале вместе с выводом кода завершения (`echo $?` на Linux/macOS):

```bash
go run . sum 17 25
# 42
echo $?
# 0

go run . sum 17 abc
# Ошибка: некорректный аргумент: "abc" не число
# exit status 1
```

Посмотрите, сколько плюсов дал паттерн `main() → run(os.Args[1:])`:
1. Внутри `run` можно спокойно пользоваться `return err` и `defer` — все отложенные вызовы выполнятся **до** возврата в `main` и вызова `os.Exit(1)`.
2. `run` не завязана на глобальную `os.Args` напрямую — ей передают список аргументов параметром, а значит, её легко вызывать из других функций и проверять на разных наборах команд.
3. Все ошибки выводятся в одном месте (`os.Stderr`) с единым оформлением и честным кодом выхода `1`.

> [!check] Проверь понимание
> Пользователь запустил программу командой `./app add "Go" https://go.dev`. Чему равны `len(os.Args)`, `os.Args[0]` и `os.Args[2]`?
>
> `len(os.Args)` равно `4`, `os.Args[0]` равно `"./app"`, а `os.Args[2]` — `"Go"` (терминал передал текст внутри кавычек как один аргумент без самих кавычек).

## Практика

**Упражнение 1 (Базовое). Проследи поведение и найди панику.**  
Что произойдёт, если запустить программу ниже командой `go run .` без аргументов? Как исправить код?

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	defer fmt.Println("До свидания!")
	cmd := os.Args[1]
	if cmd == "fail" {
		os.Exit(1)
	}
	fmt.Println("Команда:", cmd)
}
```
И второй вопрос: если запустить её как `go run . fail`, напечатается ли `"До свидания!"`?

> [!solution] Показать решение
> 1. Без аргументов `len(os.Args) == 1`, поэтому `os.Args[1]` вызовет панику `index out of range [1] with length 1` (правда, при панике `defer` всё же выполнится перед выводом стека). Нужно проверять `if len(os.Args) < 2`.
> 2. При `go run . fail` строка `"До свидания!"` **не напечатается**, потому что `os.Exit(1)` обрывает процесс мгновенно, минуя `defer`. Исправление — вынести логику в `run(os.Args[1:]) error` и вызывать `os.Exit(1)` только в `main()`.

**Упражнение 2 (Практическое). Утилита проверки порта из терминала.**  
Возьмите вашу функцию `parsePort` из прошлого урока и оберните её в паттерн `main() → run(os.Args[1:]) error`. Программа должна принимать один аргумент — номер порта (`go run . 8080`). Если аргументов не 1, возвращайте ошибку с подсказкой формата. При успехе печатайте `"Порт <n> корректен"` в `stdout` и выходите с кодом `0`; при ошибке — сообщение в `os.Stderr` и код `1`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"errors"
> 	"fmt"
> 	"os"
> 	"strconv"
> 	"strings"
> )
>
> var (
> 	ErrUsage     = errors.New("использование: checkport <1..65535>")
> 	ErrNotNumber = errors.New("порт должен быть целым числом")
> 	ErrPortRange = errors.New("порт вне диапазона 1..65535")
> )
>
> func parsePort(raw string) (int, error) {
> 	port, err := strconv.Atoi(strings.TrimSpace(raw))
> 	if err != nil {
> 		return 0, fmt.Errorf("%w: %q", ErrNotNumber, raw)
> 	}
> 	if port < 1 || port > 65535 {
> 		return 0, fmt.Errorf("%w: %d", ErrPortRange, port)
> 	}
> 	return port, nil
> }
>
> func run(args []string) error {
> 	if len(args) != 1 {
> 		return ErrUsage
> 	}
> 	port, err := parsePort(args[0])
> 	if err != nil {
> 		return err
> 	}
> 	fmt.Printf("Порт %d корректен\n", port)
> 	return nil
> }
>
> func main() {
> 	if err := run(os.Args[1:]); err != nil {
> 		fmt.Fprintln(os.Stderr, "Ошибка:", err)
> 		os.Exit(1)
> 	}
> }
> ```
