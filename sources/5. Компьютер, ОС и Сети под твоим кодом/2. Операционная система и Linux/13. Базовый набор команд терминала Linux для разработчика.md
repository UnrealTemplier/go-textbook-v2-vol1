Сервис на Linux начал возвращать ошибки. У вас открыто окно терминала и файл лога на сто мегабайт. Никакого графического интерфейса, никакой IDE — только командная строка. Чтобы за десять секунд выяснить, какая именно ошибка сыплется чаще всего, кто занял порт и хватает ли места на диске, не нужно учить сотни утилит. Достаточно пятнадцати команд и символа конвейера `|`.

## Четыре группы команд на каждый день

В седьмом уроке мы увидели, почему конвейеры Unix работают так слаженно: каждая маленькая утилита читает текст из `stdin`, делает ровно одну простую вещь и отдаёт результат в `stdout`. Сведём рабочий минимум бэкенд-разработчика в четыре компактные группы.

### 1. Навигация и файлы

| Команда | Что делает | Рабочий пример |
|---|---|---|
| `ls -la` | Показывает все файлы (включая скрытые `.env`), права, владельца и размер | `ls -la /var/log/bookmarkflow` |
| `find` | Рекурсивно ищет файлы по имени, типу или времени изменения | `find . -name "*.go" -mtime -1` |
| `du -sh` | Показывает суммарный объём каталогов в читаемых единицах (`K`, `M`, `G`) | `du -sh ./*` |

Когда на сервере внезапно заканчивается место (`ENOSPC`), связка `du -sh /*` и `find /var/log -size +100M` за пару секунд находит раздувшийся лог.

### 2. Чтение и анализ логов

| Команда | Что делает | Рабочий пример |
|---|---|---|
| `grep -rn` | Ищет строки по шаблону рекурсивно с номерами строк | `grep -rn "WriteFileAtomic" ./project` |
| `head` / `tail` | Показывает первые или последние `N` строк; `tail -f` следит за файлом вживую | `tail -n 50 -f app.log` |
| `wc -l` | Считает количество строк во входе | `wc -l app.log` |
| `cut` | Вырезает нужные колонки по разделителю (`-d`) и номеру поля (`-f`) | `cut -d' ' -f3 app.log` |
| `sort` | Сортирует строки (флаг `-n` — как числа, `-r` — по убыванию) | `sort -rn` |
| `uniq -c` | Схлопывает **соседние** одинаковые строки и пишет их счётчик | `sort \| uniq -c` |

### 3. Процессы и сетевые порты

| Команда | Что делает | Рабочий пример |
|---|---|---|
| `ps aux` | Список всех процессов с `PID`, `%CPU`, `RSS` и командной строкой | `ps aux \| grep bookmarkflow` |
| `kill` | Отправляет сигнал процессу (по умолчанию мягкий `SIGTERM`, с `-9` — `SIGKILL`) | `kill -TERM 4821` |
| `ss` | Показывает открытые сетевые сокеты и слушающие порты | `ss -tulpn` |

Флаги `ss -tulpn` расшифровываются просто: **t**cp, **u**dp, **l**istening (только слушающие порты), **p**rocesses (какой `PID` держит порт), **n**umeric (числа вместо имён вроде `http`). Если ваш Go-сервер падает с `address already in use`, именно `ss -tulpn` покажет, кто занял порт.

### 4. Права доступа

| Команда | Что делает | Рабочий пример |
|---|---|---|
| `chmod` | Меняет биты прав доступа к файлу или каталогу | `chmod 600 secrets.env`, `chmod +x ./app` |

Запомните две самые частые комбинации: `chmod 600` (чтение и запись только владельцу — для файлов с секретами и ключами) и `chmod +x` (добавить право запуска скомпилированному бинарнику или скрипту).

## Собираем конвейеры для логов Go-программы

Посмотрим, как эти кубики складываются на реальном выводе сервиса. Пусть небольшая программа на Go генерирует лог обращений к `BookmarkFlow` с полями `level`, `cmd` и `status`:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	entries := []struct {
		level  string
		cmd    string
		status string
	}{
		{"INFO", "LIST", "ok"},
		{"ERROR", "GET", "not_found"},
		{"INFO", "PING", "ok"},
		{"ERROR", "ADD", "disk_full"},
		{"ERROR", "GET", "not_found"},
		{"ERROR", "GET", "not_found"},
		{"ERROR", "ADD", "invalid_url"},
		{"INFO", "COUNT", "ok"},
	}

	for i, e := range entries {
		fmt.Fprintf(os.Stdout, "2026-11-23T12:00:0%dZ level=%s cmd=%s status=%s\n",
			i, e.level, e.cmd, e.status)
	}
}
```

Сохраним вывод программы в файл (`go run main.go > app.log`) и пропустим его через три типовых конвейера разработчика:

```bash
# 1. Сколько всего ошибок в файле?
grep "level=ERROR" app.log | wc -l
# Вывод: 5

# 2. Топ причин ошибок по убыванию частоты:
grep "level=ERROR" app.log | cut -d' ' -f4 | sort | uniq -c | sort -rn
# Вывод:
#       3 status=not_found
#       1 status=invalid_url
#       1 status=disk_full

# 3. Следить за ошибками в работающем сервисе в реальном времени:
tail -f app.log | grep --line-buffered "level=ERROR"
```

Разберём второй конвейер по шагам, потому что он встречается в работе чуть ли не каждый день:

1. `grep "level=ERROR" app.log` оставляет только строки с ошибками.
2. `cut -d' ' -f4` режет каждую строку по пробелу и забирает четвёртое поле (`status=...`).
3. `sort` ставит одинаковые статусы рядом друг с другом.
4. `uniq -c` схлопывает группы одинаковых строк и дописывает слева их количество.
5. `sort -rn` сортирует полученный список численно (`-n`) в обратном порядке (`-r`), поднимая самую частую проблему на первую строку.

Никакого отдельного скрипта на сто строк — пять коротких команд, соединённых каналом ядра.

## Подводные камни

**Ловушка 1. Вызывать `uniq` без предварительного `sort`.**  
Утилита `uniq` не хранит в памяти все встреченные строки — она сравнивает только текущую строку с предыдущей. Если одинаковые ошибки разбросаны по логу, `uniq -c` посчитает их по отдельности. Всегда пишите пару `sort | uniq -c`.

**Ловушка 2. Буферизация `grep` внутри длинного конвейера с `tail -f`.**  
Когда `grep` пишет не в терминал, а в следующий конвейер (например, `tail -f app.log | grep ERROR | cut -d' ' -f4`), он начинает копить вывод в буфер на 4 КБ и подолгу молчит. Флаг `--line-buffered` заставляет `grep` сбрасывать каждую найденную строку немедленно.

**Ловушка 3. Бить процессы командой `kill -9` по привычке.**  
Сигнал `SIGKILL` (`-9`) не даёт Go-программе выполнить `defer`, сбросить буферы и завершить атомарную запись. Начинайте с обычного `kill <PID>` (`SIGTERM`), а к `-9` прибегайте лишь тогда, когда процесс намертво завис.

> [!check] Проверь понимание
> В файле `events.log` строки идут в порядке: `timeout`, `ok`, `timeout`. Что выведет команда `uniq -c events.log` и почему?
>
> Она выведет три отдельные строки с единицами (`1 timeout`, `1 ok`, `1 timeout`), а не `2 timeout`, потому что `uniq` объединяет только соседние дубликаты. Чтобы получить точный подсчёт, нужна связка `sort events.log | uniq -c`.

## Практика

**Упражнение 1 (Базовое). Расшифровка конвейера.**  
Объясните, что делает команда `ps aux | grep bookmarkflow | wc -l`, и почему она иногда выводит `1`, даже когда процесс `bookmarkflow` вообще не запущен.

> [!solution] Показать решение
> Команда берёт список всех процессов (`ps aux`), отбирает строки со словом `bookmarkflow` и считает их количество (`wc -l`).  
> Лишняя единица возникает из-за того, что в выводе `ps aux` присутствует сам запущенный процесс `grep bookmarkflow` — его командная строка тоже содержит искомую подстроку. На практике этого избегают, используя `pgrep -c bookmarkflow` или шаблон `grep "[b]ookmarkflow"`.

**Упражнение 2 (Практическое). Анализ лога одной строкой.**  
Дан файл `service.log`, где каждая строка имеет формат `<время> <уровень> <команда> <статус>` (разделитель — один пробел). Напишите конвейер терминала, который выведет **2 самые частые команды** (третье поле) среди строк, содержащих `ERROR`.

> [!solution] Показать решение
> ```bash
> grep "ERROR" service.log | cut -d' ' -f3 | sort | uniq -c | sort -rn | head -n 2
> ```
> Сначала `grep` отфильтровывает строки с ошибками, `cut` вырезает третье поле (команду), `sort | uniq -c` считает повторы каждой команды, `sort -rn` ставит лидеров наверх, а `head -n 2` оставляет две первые строки.

**Упражнение 3 (Со звёздочкой \*). Мини-аналог `cut | sort | uniq -c | sort -rn` на Go.**  
Напишите программу `package main`, которая читает строки из `os.Stdin`, извлекает из каждой строки `N`-е поле (номер с 1 передаётся флагом `-f`, по умолчанию `1`, разделитель — любые пробелы через `strings.Fields`), считает частоту каждого значения и печатает результат от самых частых к редким.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"bufio"
> 	"cmp"
> 	"flag"
> 	"fmt"
> 	"os"
> 	"slices"
> 	"strings"
> )
>
> type item struct {
> 	val   string
> 	count int
> }
>
> func main() {
> 	field := flag.Int("f", 1, "номер поля (начиная с 1)")
> 	flag.Parse()
> 	if *field < 1 {
> 		fmt.Fprintln(os.Stderr, "номер поля должен быть >= 1")
> 		os.Exit(1)
> 	}
>
> 	counts := make(map[string]int)
> 	scanner := bufio.NewScanner(os.Stdin)
> 	for scanner.Scan() {
> 		parts := strings.Fields(scanner.Text())
> 		if len(parts) < *field {
> 			continue
> 		}
> 		counts[parts[*field-1]]++
> 	}
> 	if err := scanner.Err(); err != nil {
> 		fmt.Fprintln(os.Stderr, err)
> 		os.Exit(1)
> 	}
>
> 	result := make([]item, 0, len(counts))
> 	for val, count := range counts {
> 		result = append(result, item{val: val, count: count})
> 	}
> 	slices.SortFunc(result, func(a, b item) int {
> 		if c := cmp.Compare(b.count, a.count); c != 0 {
> 			return c
> 		}
> 		return cmp.Compare(a.val, b.val)
> 	})
>
> 	for _, it := range result {
> 		fmt.Printf("%6d %s\n", it.count, it.val)
> 	}
> }
> ```
> Такая утилита сама становится полноценным участником конвейера Unix: её можно вызвать как `grep "level=ERROR" app.log | go run main.go -f 4`.
