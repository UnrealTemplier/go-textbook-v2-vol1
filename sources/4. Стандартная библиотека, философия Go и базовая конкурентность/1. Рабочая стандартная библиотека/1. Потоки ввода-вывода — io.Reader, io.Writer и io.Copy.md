*Как два однометодных интерфейса — `io.Reader` и `io.Writer` — превращают файлы, строки, буферы и вывод в терминал в единые взаимозаменяемые потоки байтов.*

> «Файл в Unix — это просто последовательность байтов. Любую структуру и организацию его содержимого определяют лишь программы, которые с ним работают; самой файловой системе безразлично, что лежит внутри. А значит, любая программа может читать и записывать любой файл.»  
> — Брайан Керниган, *UNIX: A History and a Memoir*

Представьте, что в `BookmarkFlow` нужно посчитать строки в экспортированных закладках. Сегодня данные лежат в файле на диске, завтра в тесте это строка из памяти, послезавтра — стандартный ввод `os.Stdin`.

Функция, принимающая имя файла `path string`, намертво привязана к диску и мешает тестам. Функция, принимающая `[]byte`, упадёт на многогигабайтном файле из-за нехватки ОЗУ. Стандартная библиотека Go решает обе проблемы через два однометодных интерфейса из пакета `io`.

## Честная модель: поток порций байтов

Данные не нужно грузить целиком — их перекачивают порциями фиксированного размера, например по 32 КБ:

```text
Источник (io.Reader)         Буфер []byte         Приёмник (io.Writer)
[файл / строка / stdin] --Read(buf)--> [32 КБ] --Write(buf[:n])--> [файл / stdout / буфер]
```

Аналогия с переливанием воды кружкой верна лишь в одном: объём буфера не зависит от размера источника. На этом сходство кончается — каждая порция может оказаться меньше буфера, а в конце источник явно сигнализирует, что байты иссякли.

В 1970-х годах архитекторы Unix свели файлы и устройства к единой модели потока байтов, чтобы стыковать утилиты в конвейеры. В Go эту идею перенесли на уровень интерфейсов.

## Контракты `io.Reader` и `io.Writer`

В пакете `io` объявлены два контракта ровно из одного метода:

```go
type Reader interface {
	Read(p []byte) (n int, err error)
}

type Writer interface {
	Write(p []byte) (n int, err error)
}
```

**Контракт `Read`:** вызывающий код передаёт буфер `p`; `Read` заполняет до `len(p)` байтов и возвращает их число `n` (`0 <= n <= len(p)`) и ошибку `err`. Конец потока обозначается сигналом `io.EOF`. **Критическое правило:** `Read` вправе вернуть **одновременно** `n > 0` и `err == io.EOF` — последнюю порцию плюс признак конца. Поэтому всегда **сначала обрабатывайте `p[:n]`**, и лишь потом проверяйте `err`.

**Контракт `Write`:** записывает байты из `p` и возвращает `n`. Если записалось меньше `len(p)`, метод обязан вернуть `err != nil`. Изменять переданный слайс `p` запрещено.

Благодаря неявной реализации под эти контракты автоматически подходят `*os.File`, `os.Stdin`, `os.Stdout`, `*strings.Reader`, `*bytes.Buffer` — функция с параметром `io.Reader` работает с любым из них.

## Рабочий код: `io.Copy`, `io.LimitReader`, `io.MultiWriter` и `CountingWriter`

Готовые комбинаторы пакета `io` избавляют от ручных циклов:

* `io.Copy(dst, src)` — перекачивает поток порциями до `io.EOF` и возвращает `(copied, nil)` (`io.EOF` не считается ошибкой).
* `io.ReadAll(r)` — читает поток целиком в `[]byte` (опасно без лимита).
* `io.LimitReader(r, limit)` — ограничивает чтение максимум `limit` байтами, после чего отдаёт `io.EOF`.
* `io.MultiWriter(w1, w2, ...)` — дублирует каждую запись во все приёмники.

Соберём конвейер с собственной обёрткой `CountingWriter`:

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"os"
	"strings"
)

type countingWriter struct {
	dst   io.Writer
	count int64
}

func (c *countingWriter) Write(p []byte) (int, error) {
	n, err := c.dst.Write(p)
	c.count += int64(n)
	return n, err
}

func CountingWriter(w io.Writer) (io.Writer, *int64) {
	cw := &countingWriter{dst: w}
	return cw, &cw.count
}

func main() {
	src := strings.NewReader("go.dev\npkg.go.dev\ngithub.com/golang/go\n")
	limited := io.LimitReader(src, 18)

	var backup bytes.Buffer
	tee := io.MultiWriter(os.Stdout, &backup)
	counted, written := CountingWriter(tee)

	copied, err := io.Copy(counted, limited)
	if err != nil {
		fmt.Fprintln(os.Stderr, "ошибка копирования:", err)
		return
	}

	fmt.Printf("\nСкопировано: %d Б, счётчик обёртки: %d Б, в буфере: %q\n",
		copied, *written, backup.String())
}
```

Запуск программы печатает:

```text
go.dev
pkg.go.dev

Скопировано: 18 Б, счётчик обёртки: 18 Б, в буфере: "go.dev\npkg.go.dev\n"
```

Посмотрите, как состыковались четыре независимых элемента: `strings.Reader` → `io.LimitReader` → `io.Copy` → `CountingWriter` → `io.MultiWriter` → `os.Stdout` и `bytes.Buffer`. Ни один из них не знает, откуда пришли байты и куда они уходят дальше. Обратите внимание на деталь в `countingWriter.Write`: к счётчику прибавляется именно `n`, а не `len(p)`, потому что при частичной записи и ошибке `Write` мог успеть записать только первые `n` байтов.

## Подводные камни

**Ловушка 1. Игнорирование `n > 0` при `err == io.EOF`.**  
Если вы пишете собственный цикл чтения поверх `r.Read(buf)`, нельзя проверять ошибку раньше обработки данных:

```go
// ОШИБКА: если Read вернул (12, io.EOF), эти 12 байтов потеряются.
n, err := r.Read(buf)
if err != nil {
	break
}
process(buf[:n])
```

Правильный порядок всегда один:

```go
for {
	n, err := r.Read(buf)
	if n > 0 {
		process(buf[:n])
	}
	if err == io.EOF {
		break
	}
	if err != nil {
		return err
	}
}
```

**Ловушка 2. Бесконтрольный `io.ReadAll`.**  
Вызов `io.ReadAll(r)` на входном потоке неизвестного размера способен выделить гигабайты памяти и аварийно завершить процесс. Всегда ставьте сверху защитный предел через `io.LimitReader(r, maxBytes)` или обрабатывайте данные потоком.

> [!check] Проверь понимание
> Что вернёт `io.Copy(io.Discard, strings.NewReader("hello"))` — вернёт ли он ошибку `io.EOF`?
>
> Нет: `io.Copy` вернёт `(5, nil)`. Для `io.Copy` сигнал `io.EOF` — штатный признак завершения копирования, а не ошибка. `io.Discard` — встроенный приёмник, который отбрасывает все байты и всегда сообщает об успехе.

## Практика

**Упражнение 1 (Базовое). Проследи вывод с `io.LimitReader`.**  
Что напечатает фрагмент ниже и почему в выводе именно столько байтов?

```go
r := strings.NewReader("BookmarkFlow")
lim := io.LimitReader(r, 8)
data, err := io.ReadAll(lim)
fmt.Printf("%q %d %v\n", string(data), len(data), err)
```

> [!solution] Показать решение
> Вывод: `"Bookmark" 8 <nil>`.  
> `io.LimitReader` выдаёт ровно первые 8 байтов (в ASCII это 8 символов `"Bookmark"`), после чего возвращает `io.EOF`. Функция `io.ReadAll`, как и `io.Copy`, считает `io.EOF` нормальным концом потока и возвращает `err == nil`.

**Упражнение 2 (Практическое). Фильтр пустых байтов `UpperReader`.**  
Напишите обёртку `NewUpperReader(r io.Reader) io.Reader`, которая читает байты из `r` и переводит все строчные латинские буквы (`'a'..'z'`) в заглавные прямо в буфере `p[:n]`. Проверьте её через `io.Copy(os.Stdout, NewUpperReader(strings.NewReader("go 1.24\n")))`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"io"
> 	"os"
> 	"strings"
> )
>
> type upperReader struct {
> 	src io.Reader
> }
>
> func NewUpperReader(r io.Reader) io.Reader {
> 	return &upperReader{src: r}
> }
>
> func (u *upperReader) Read(p []byte) (int, error) {
> 	n, err := u.src.Read(p)
> 	for i := range n {
> 		if p[i] >= 'a' && p[i] <= 'z' {
> 			p[i] -= 'a' - 'A'
> 		}
> 	}
> 	return n, err
> }
>
> func main() {
> 	_, _ = io.Copy(os.Stdout, NewUpperReader(strings.NewReader("go 1.24\n")))
> 	// Вывод: GO 1.24
> }
> ```
> Цикл пробегает строго `range n`, а не `len(p)`, чтобы не трогать незаполненный хвост буфера, и преобразует `p[:n]` даже тогда, когда `err == io.EOF`.

**Упражнение 3 (Со звёздочкой \*). Проверка превышения лимита.**  
`io.LimitReader(r, limit)` тихо обрезает поток по границе `limit`. Напишите функцию `ReadBounded(r io.Reader, maxBytes int64) ([]byte, error)`, которая читает весь поток, но если в `r` оказалось хотя бы на 1 байт больше `maxBytes`, возвращает ошибку `"размер входа превысил лимит"` вместо молчаливой обрезки.

> [!solution] Показать решение
> Хитрость стандартной библиотеки: читаем через `io.LimitReader(r, maxBytes+1)`. Если в итоге прочиталось больше `maxBytes`, значит поток не поместился в лимит:
> ```go
> package main
>
> import (
> 	"errors"
> 	"fmt"
> 	"io"
> 	"strings"
> )
>
> var ErrTooLarge = errors.New("размер входа превысил лимит")
>
> func ReadBounded(r io.Reader, maxBytes int64) ([]byte, error) {
> 	data, err := io.ReadAll(io.LimitReader(r, maxBytes+1))
> 	if err != nil {
> 		return nil, err
> 	}
> 	if int64(len(data)) > maxBytes {
> 		return nil, ErrTooLarge
> 	}
> 	return data, nil
> }
>
> func main() {
> 	okData, err := ReadBounded(strings.NewReader("go.dev"), 6)
> 	fmt.Println(string(okData), err) // Вывод: go.dev <nil>
>
> 	_, err = ReadBounded(strings.NewReader("go.dev!"), 6)
> 	fmt.Println(err) // Вывод: размер входа превысил лимит
> }
> ```
> Приём с `maxBytes+1` гарантирует ограниченное потребление памяти и одновременно точно отличает «ровно `maxBytes`» от «больше `maxBytes`».

---

Интерфейсы `io.Reader` и `io.Writer` дают чистую модель потока сырых байтов, но в реальных задачах мы почти всегда читаем текст построчно и пишем десятки мелких фрагментов. Если делать на каждый байт или короткую строку отдельный вызов к файлу, программа резко замедлится. В следующем уроке добавим поверх потоков буферизацию — [[2.
