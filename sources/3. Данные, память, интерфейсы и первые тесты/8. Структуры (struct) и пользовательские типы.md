*Как объединить разрозненные поля одной сущности в структуру, работать с ней через указатели и отличать собственные типы от псевдонимов.*

Вспомните финал Модуля 2 — вторую версию `BookmarkFlow`. Чтобы хранить закладки, мы таскали три параллельных слайса `ids`, `titles` и `urls`, а `execute` принимала пять параметров и возвращала пять результатов. Стоило забыть одну строчку при удалении из `urls` — и ссылки тихо съезжали к чужим названиям.

Поля одной закладки — **единая сущность**, а не три разрозненных списка. В Go для этого служат **структуры**.

## Что такое структура в памяти

Вместо трёх отдельных списков каждая закладка получает собственный блок, где все её поля лежат рядом:

```text
  Bookmark (единая запись)
  ┌──────┬────────────────────┬───────────────────────────┬──────────────────┐
  │ ID:1 │ Title:"Go Spec"    │ URL:"https://go.dev/..."  │ Tags:["go","ref"]│
  └──────┴────────────────────┴───────────────────────────┴──────────────────┘
```

Такой составной тип называется **структурой (`struct`)**. Список закладок становится одним слайсом `[]Bookmark`: удалить запись означает убрать ровно один элемент, и сдвинуть поля относительно друг друга больше невозможно.

```go
type Bookmark struct {
	ID    int
	Title string
	URL   string
	Tags  []string
}
```

К полям обращаются через точку: `b.Title`, `b.URL`. Поля с заглавной буквы видны снаружи пакета, со строчной — только внутри (подробнее на уроке 14).

## Создание, нулевые значения и хрупкость позиционных литералов

Создавайте структуры литералом с **именованными полями**:

```go
b := Bookmark{
	ID:    1,
	Title: "Go Spec",
	URL:   "https://go.dev/ref/spec",
}
```

Неуказанное поле `Tags` получило нулевое значение `nil`, а `var empty Bookmark` сразу даёт готовую структуру с `0`, `""` и `nil`. Позиционный литерал `Bookmark{1, "Go Spec", "https://go.dev/ref/spec", nil}` тоже компилируется, но он хрупок: добавили в середину новое поле — и сломали все вызовы, а перепутали два соседних `string` — компилятор молча запишет ссылку в `Title`. Не делайте так.

## Указатель на структуру и авто-разыменование

В функцию структура передаётся по значению — копируется целиком. Чтобы менять поля оригинала, передавайте `*Bookmark`. Компилятор сам разыменовывает указатель при записи `p.Title` вместо громоздкого `(*p).Title`, а `&Bookmark{...}` создаёт структуру и сразу возвращает указатель:

```go
p := &Bookmark{
	ID:    2,
	Title: "Go Standard Library",
	URL:   "https://pkg.go.dev/std",
}
p.Title = "Go stdlib" // то же, что (*p).Title = "Go stdlib"
```

Граница очевидна: если `p == nil`, обращение `p.Title` вызовет панику.

## Сравнение структур через `==`

Две структуры одного типа сравниваются через `==` и `!=`, если **сравнимы все их поля**. Поэтому структуру `TagKey` можно даже сделать ключом мапы `map[TagKey]int`:

```go
type TagKey struct {
	Domain string
	Tag    string
}
```

А вот две `Bookmark` через `==` сравнить нельзя: внутри есть слайс `Tags []string`, а слайсы несравнимы:

```go
var a, b Bookmark
_ = (a == b)
// compile error: invalid operation: a == b (struct containing []string cannot be compared)
```

Такие структуры сравнивают по полям, проверяя слайс через `slices.Equal(a.Tags, b.Tags)`.

## Теги полей: метаданные для внешних форматов

В Go поля называют в стиле `Title` и `URL`, а в формате JSON принято писать `"title"` и `"url"`. Чтобы сообщить имя поля внешним кодировщикам, к полю прикрепляют **тег** — строковый литерал в обратных кавычках:

```go
type Bookmark struct {
	ID    int      `json:"id"`
	Title string   `json:"title"`
	URL   string   `json:"url"`
	Tags  []string `json:"tags,omitempty"`
}
```

Компилятор Go теги не исполняет — он лишь сохраняет их как метаданные поля. Как стандартные пакеты читают их при сохранении JSON-файлов, разберём в Модуле 4.

## Пользовательские типы против псевдонимов

Через `type` объявляют и **именованные типы** поверх базовых — `type UserID int`, `type BookmarkID int`, `type Kopeks int64`. Это страховка компилятора от перепутанных аргументов:

```go
type UserID int
type BookmarkID int

var uid UserID = 7
var bid BookmarkID = 42
uid = bid // compile error: cannot use bid (variable of type BookmarkID) as UserID value in assignment
```

`UserID` и `BookmarkID` — **разные типы**; перевести один в другой можно только явным `UserID(bid)`. Не путайте их с **псевдонимом типа** (*type alias*) со знаком `=`:

```go
type Count = int // псевдоним: Count и int — один и тот же тип
```

Псевдоним лишь даёт второе имя существующему типу (так в Go устроены `byte = uint8` и `rune = int32`). Для защиты домена всегда объявляйте новый тип **без `=`**.

## Рабочий пример

Соберём структуры, указатель, сравнимый ключ мапы и пользовательский тип `BookmarkID` в одной программе:

```go
package main

import (
	"fmt"
	"slices"
)

type BookmarkID int

type TagKey struct {
	Domain string
	Tag    string
}

type Bookmark struct {
	ID    BookmarkID `json:"id"`
	Title string     `json:"title"`
	URL   string     `json:"url"`
	Tags  []string   `json:"tags,omitempty"`
}

func rename(b *Bookmark, newTitle string) {
	b.Title = newTitle
}

func equalBookmarks(a, b Bookmark) bool {
	return a.ID == b.ID &&
		a.Title == b.Title &&
		a.URL == b.URL &&
		slices.Equal(a.Tags, b.Tags)
}

func main() {
	b1 := Bookmark{
		ID:    BookmarkID(1),
		Title: "Go Spec",
		URL:   "https://go.dev/ref/spec",
		Tags:  []string{"go", "docs"},
	}
	rename(&b1, "The Go Specification")

	b2 := Bookmark{
		ID:    1, // нетипизированная константа 1 подходит к BookmarkID
		Title: "The Go Specification",
		URL:   "https://go.dev/ref/spec",
		Tags:  []string{"go", "docs"},
	}

	tagStats := map[TagKey]int{
		{Domain: "go.dev", Tag: "docs"}: 1,
	}

	fmt.Printf("#%d %s (совпадают: %t)\n", b1.ID, b1.Title, equalBookmarks(b1, b2))
	fmt.Println("Счётчик go.dev/docs:", tagStats[TagKey{Domain: "go.dev", Tag: "docs"}])
}
```

Вывод:

```text
#1 The Go Specification (совпадают: true)
Счётчик go.dev/docs: 1
```

Заметьте приятную деталь в инициализации `b2`: нетипизированную константу `1` можно присвоить `BookmarkID` напрямую, но переменную `var raw int = 1` — уже только через явное `BookmarkID(raw)`.

> [!check] Проверь понимание
> Скомпилируется ли этот фрагмент?
> ```go
> type UserID int
> type Count = int
>
> var n int = 5
> var c Count = n
> var u UserID = n
> ```
>
> Нет. Строка `var c Count = n` корректна, потому что `Count` — псевдоним `int` (один и тот же тип). А строка `var u UserID = n` не скомпилируется: `UserID` — отдельный тип, нужно явное преобразование `UserID(n)`.

## Практика

**Упражнение 1 (Базовое). Создание и правка закладки по указателю.**  
Объявите структуру `Bookmark` с полями `ID int`, `Title string`, `URL string`, `Archived bool`. Создайте закладку с именованными полями (не указывая `Archived`), напишите функцию `archive(b *Bookmark)` и убедитесь, что после её вызова `b.Archived` стало `true`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> type Bookmark struct {
> 	ID       int
> 	Title    string
> 	URL      string
> 	Archived bool
> }
>
> func archive(b *Bookmark) {
> 	b.Archived = true
> }
>
> func main() {
> 	b := Bookmark{
> 		ID:    1,
> 		Title: "Go Blog",
> 		URL:   "https://go.dev/blog",
> 	}
> 	archive(&b)
> 	fmt.Printf("%+v\n", b)
> }
> ```
> Спецификатор `%+v` печатает имена полей структуры вместе со значениями: `{ID:1 Title:Go Blog URL:https://go.dev/blog Archived:true}`.

**Упражнение 2 (Практическое). Деньги в копейках без путаницы с обычными `int`.**  
Объявите `type Kopeks int64` и структуру `LineItem` с полями `Name string`, `UnitPrice Kopeks`, `Qty int`. Напишите функцию `totalKopeks(items []LineItem) Kopeks`, которая считает итоговую сумму заказа (помните о явном приведении `Kopeks(it.Qty)`).

> [!solution] Показать решение
> ```go
> type Kopeks int64
>
> type LineItem struct {
> 	Name      string
> 	UnitPrice Kopeks
> 	Qty       int
> }
>
> func totalKopeks(items []LineItem) Kopeks {
> 	var sum Kopeks
> 	for _, it := range items {
> 		sum += it.UnitPrice * Kopeks(it.Qty)
> 	}
> 	return sum
> }
> ```
> Компилятор не даст случайно умножить `Kopeks` на `int` без явного `Kopeks(it.Qty)` и не позволит сложить копейки с простым счётчиком штук.

**Упражнение 3 (Со звёздочкой \*). Что сломается?**  
У вас есть две структуры:
```go
type Endpoint struct {
	Host string
	Port int
}

type Bookmark struct {
	ID    int
	Title string
	Tags  []string
}
```
Почему `seen := make(map[Endpoint]bool)` компилируется, а `cache := make(map[Bookmark]bool)` выдаёт ошибку компилятора? Как сравнить два значения `Bookmark`, если нужно проверить их равенство?

> [!solution] Показать решение
> Все поля `Endpoint` (`string` и `int`) поддерживают `==`, поэтому вся структура `Endpoint` сравнима и подходит на роль ключа мапы. В `Bookmark` есть поле `Tags []string` — слайсы несравнимы через `==`, что делает несравнимой и всю структуру целиком (`invalid map key type Bookmark`).
>
> Для сравнения двух `Bookmark` напишите вспомогательную функцию, которая сверяет скалярные поля через `==`, а слайс `Tags` — через `slices.Equal(a.Tags, b.Tags)`.

---

Структуры навсегда избавили нас от хрупких параллельных слайсов, а именованные типы защитили от перепутанных аргументов. Но операции над закладкой пока живут отдельно от неё — в виде функций `rename(&b, ...)` и `equalBookmarks(a, b)`. В следующей главе привяжем поведение напрямую к самому типу через методы: [[9. Методы — получатель-значение против получателя-указателя]].
