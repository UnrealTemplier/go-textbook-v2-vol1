*Как устроен заголовок слайса `(ptr, len, cap)` в памяти, почему `append` иногда переезжает в новый массив и чем `nil`-слайс отличается от пустого `[]T{}`.*

В конце Модуля 2 мы уже пользовались списками `ids []int` и функцией `append` в `BookmarkFlow`, не заглядывая внутрь. А в прошлом уроке увидели, почему массив `[N]T` с жёсткой длиной не подходит для коллекций, размер которых меняется по ходу работы.

Go объединяет скорость непрерывного массива с гибкостью растущего списка без всякой «магии за кулисами» — с помощью крошечного заголовка из трёх полей поверх обычного массива.

## Окно поверх массива: заголовок `(ptr, len, cap)`

Представьте полоску киноплёнки (фиксированный массив в RAM) и скользящую поверх неё рамку-видоискатель. Рамка не хранит кадры: она знает только начало видимого участка, число открытых кадров и запас до правого края плёнки. Граница аналогии: когда кадры упёрлись в край, Go не растягивает старую полоску — он создаёт новую длинную плёнку в другом месте памяти, копирует кадры туда и переставляет рамку.

Эту конструкцию в Go называют **слайс** (*slice*; в русскоязычной литературе также встречается слово «срез», далее в учебнике мы используем единый термин *слайс*). Тип пишется без числа в скобках: `[]string`, `[]int`.

Заголовок слайса в памяти занимает 24 байта (на 64-битной системе) и состоит из трёх полей:
* **`ptr`** — указатель на первый элемент слайса в базовом массиве;
* **`len`** — длина (`len(s)`), число элементов по индексам `0..len-1`;
* **`cap`** — ёмкость (`cap(s)`), сколько элементов помещается от `ptr` до конца базового массива без новой аллокации.

Вот так выглядит `tags := make([]string, 2, 4)` с двумя элементами `"go"` и `"cli"`:

```text
Заголовок tags (24 байта)        Базовый массив [4]string
+-----------------+              0       1       2      3
| ptr ------------+----------> +------+-------+------+------+
| len |    2      |            | "go" | "cli" |  ""  |  ""  |
| cap |    4      |            +------+-------+------+------+
+-----------------+            |<--- len=2 -->|
                               |<--------- cap=4 ---------->|
```

Ячейки `[2]` и `[3]` уже выделены, но скрыты за границей `len`: чтение `tags[2]` вызовет панику выхода за границы, зато этим запасом сразу пользуется `append`.

## Механика `append`

Работа `append(s, elem)` сводится к выбору между двумя ветками:
* **`len < cap`** — место в базовом массиве есть. `append` записывает элемент в ячейку `s[len]` **того же** массива и возвращает заголовок с прежним `ptr` и `len + 1`.
* **`len == cap`** — массив заполнен. `append` выделяет **новый** массив большего размера (для малых слайсов ёмкость удваивается), копирует туда старые элементы, дописывает новый и возвращает заголовок с **новым `ptr`**, увеличенными `len` и `cap`.

*(Точную формулу роста ёмкости больших слайсов и работу аллокатора рантайма мы разберём в Томе 5.)*

Отсюда железное правило Go: **результат `append` всегда присваивают обратно** (`tags = append(tags, "test")`). Заголовок передаётся в `append` по значению, и вы заранее не знаете, переехал ли базовый массив на новый адрес. Компилятор даже страхует вас: вызов `append(tags, "test")` без присваивания не скомпилируется (`append(tags, "test") (value of type []string) is not used`).

## Создание слайсов: `nil`-слайс против `[]T{}`

```go
var a []string             // nil-слайс: ptr=nil, len=0, cap=0, a == nil (true)
b := []string{}            // пустой не-nil слайс: len=0, cap=0, b == nil (false)
c := []string{"go", "cli"} // литерал: len=2, cap=2
d := make([]string, 0, 8)  // len=0, cap=8: место под 8 элементов заранее
```

Оба пустых варианта — `var a []string` и `b := []string{}` — одинаково работают с `len`, `cap`, `for range` и `append`. В идиоматичном Go предпочитают `var a []string`: нулевое значение сразу готово к работе. Разница важна редко — например, в формате JSON `nil`-слайс превращается в `null`, а `[]string{}` в `[]`.

Сравнивать два слайса через `==` нельзя: `a == b` не скомпилируется (`invalid operation: a == b (slice can only be compared to nil)`). Слайс сравнивают только с `nil`, а содержимое — через `slices.Equal(a, b)` из стандартной библиотеки Go 1.21+.

## Рабочий код: наблюдаем переезд массива вживую

Проследим за `len`, `cap` и адресом `&tags[0]` при добавлении тегов закладок:

```go
package main

import (
	"fmt"
	"slices"
)

func main() {
	var tags []string
	fmt.Printf("старт: len=%d cap=%d nil=%v\n", len(tags), cap(tags), tags == nil)

	incoming := []string{"go", "cli", "memory", "tests", "tools"}
	for _, t := range incoming {
		tags = append(tags, t)
		fmt.Printf("+%-6s -> len=%d cap=%d &tags[0]=%p\n", t, len(tags), cap(tags), &tags[0])
	}

	prealloc := make([]string, 0, len(incoming))
	for _, t := range incoming {
		prealloc = append(prealloc, t)
	}
	fmt.Println("совпадают:", slices.Equal(tags, prealloc))
}
```

Вывод терминала (адреса меняются от запуска к запуску, важен момент смены):

```text
старт: len=0 cap=0 nil=true
+go     -> len=1 cap=1 &tags[0]=0xc000014070
+cli    -> len=2 cap=2 &tags[0]=0xc000024020
+memory -> len=3 cap=4 &tags[0]=0xc000020080
+tests  -> len=4 cap=4 &tags[0]=0xc000020080
+tools  -> len=5 cap=8 &tags[0]=0xc000080000
совпадают: true
```

На шаге `+tests` адрес `&tags[0]` не изменился (`len=3 < cap=4`). На шаге `+tools` массив заполнился — ёмкость выросла до `8`, и адрес перескочил в новый блок памяти. А `prealloc` выделил память один раз.

## Подводные камни

1. **`make([]T, n)` вместо `make([]T, 0, n)`.** Код `ids := make([]int, 3); ids = append(ids, 10)` даст `[0 0 0 10]` длины `4`: три нуля уже лежали в начале. Под наполнение через `append` пишите `make([]int, 0, 3)`.
2. **Потерянный `append` внутри функции.** Функция `func addTag(tags []string, t string)` получает копию заголовка `(ptr, len, cap)`. Внутренний `tags = append(tags, t)` обновит лишь её локальную копию — вызывающий код новый элемент не увидит. Возвращайте обновлённый слайс: `func addTag(tags []string, t string) []string`.

> [!check] Проверь понимание
> Что выведет код?
> ```go
> ids := make([]int, 2, 4)
> ids = append(ids, 101)
> fmt.Println(len(ids), cap(ids), ids)
> ```
>
> Выведет `3 4 [0 0 101]`: `make([]int, 2, 4)` создал два начальных нуля, и `append` положил `101` третьим элементом в запас ёмкости `4`.

## Практика

**Упражнение 1 (Базовое). Проследи `len`, `cap` и переезд.**  
```go
s := make([]int, 1, 2)
s[0] = 10
s = append(s, 20)
s = append(s, 30)
```
Чему равны `len(s)` и `cap(s)` после каждого `append` и на каком шаге изменится `&s[0]`?

> [!solution] Показать решение
> После `append(s, 20)`: `len=2, cap=2`, `&s[0]` **не меняется** (`1 < 2`). После `append(s, 30)`: `len=3, cap=4`, `&s[0]` **меняется**, так как `len == cap` вызвал выделение нового массива.

**Упражнение 2 (Практическое). Фильтрация положительных чисел.**  
Напишите `filterPositive(nums []int) []int`, возвращающую новый слайс только с элементами `> 0` (или `nil`, если таких нет). Проверьте результат через `slices.Equal`.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"slices"
> )
>
> func filterPositive(nums []int) []int {
> 	var out []int
> 	for _, n := range nums {
> 		if n > 0 {
> 			if out == nil {
> 				out = make([]int, 0, len(nums))
> 			}
> 			out = append(out, n)
> 		}
> 	}
> 	return out
> }
>
> func main() {
> 	got := filterPositive([]int{-3, 0, 5, -1, 12})
> 	fmt.Println(got, slices.Equal(got, []int{5, 12}))
> 	fmt.Println("пустой:", filterPositive([]int{-2, -5}) == nil)
> }
> ```
> Ленивое выделение `make([]int, 0, len(nums))` сохраняет `nil` на пустом результате и избавляет от лишних переаллокаций.

**Упражнение 3 (Со звёздочкой \*). Почини `addUniqueTag`.**  
Почему код ниже печатает `[go cli]` вместо `[go cli tests]`? Объясните через `(ptr, len, cap)` и исправьте:

```go
package main

import (
	"fmt"
	"slices"
)

func addUniqueTag(tags []string, tag string) {
	if !slices.Contains(tags, tag) {
		tags = append(tags, tag)
	}
}

func main() {
	tags := []string{"go", "cli"}
	addUniqueTag(tags, "tests")
	fmt.Println(tags)
}
```

> [!solution] Показать решение
> Заголовок `tags` передался по значению: `append` обновил только локальный заголовок функции, а у `tags` в `main` остались старые `ptr` и `len=2`.
> ```go
> func addUniqueTag(tags []string, tag string) []string {
> 	if !slices.Contains(tags, tag) {
> 		tags = append(tags, tag)
> 	}
> 	return tags
> }
> // В main: tags = addUniqueTag(tags, "tests")
> ```
