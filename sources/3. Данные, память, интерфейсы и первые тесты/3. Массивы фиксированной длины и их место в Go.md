*Как в Go устроен массив `[N]T`, почему его длина входит в тип и в каких задачах массивы полезны, а в каких бессильны.*

Представьте, что ваша утилита проверяет доступность сервиса и сохраняет последние четыре HTTP-кода ответа: `200`, `200`, `503`, `200`. Держать их в отдельных переменных `code0, code1, code2, code3` нелепо — по ним даже цикл `for` не запустишь. Нужна конструкция, которая укладывает несколько одинаковых значений в памяти строго подряд.

В Go базовым строительным блоком для такой раскладки служит **массив**. И устроен он заметно строже, чем в большинстве других языков.

## Непрерывный блок памяти без лишних байтов

Если объявить массив из четырёх чисел типа `int` (`var codes [4]int`), компилятор выделяет один сплошной участок памяти ровно на `4 × 8 = 32` байта (на 64-битной системе). Никакого скрытого заголовка, никаких указателей и никаких зазоров между элементами:

```text
Массив codes [4]int в RAM (базовый адрес 0xc00001a000):

Индекс:      0          1          2          3
Адрес:    +0 байт    +8 байт    +16 байт   +24 байт
         +----------+----------+----------+----------+
Значение:|   200    |   200    |   503    |   200    |
         +----------+----------+----------+----------+
```

Такая раскладка даёт мгновенный доступ к любому элементу по индексу. Чтобы прочесть `codes[2]`, процессору не нужно перебирать элементы с начала — достаточно вычислить `базовый_адрес + 2 × 8` и взять 8 байтов по полученному адресу.

## Длина — часть типа

В Go тип массива записывается как **`[N]T`**, где `N` — константная длина, известная на этапе компиляции, а `T` — тип элементов. Главное правило, которое отличает Go от многих других языков: **размер массива входит в его тип**.

Типы `[3]int` и `[4]int` для компилятора столь же разные, как `int` и `string`. Нельзя присвоить `[3]int` в переменную типа `[4]int` и нельзя передать `[4]int` в функцию, ожидающую `[3]int`:

```go
small := [3]int{200, 200, 404}
var big [4]int = small // compile error: cannot use small (variable of type [3]int) as [4]int value in variable declaration
```

Есть четыре удобных способа объявить массив:

```go
var empty [4]int                      // [0 0 0 0] — заполнен нулевыми значениями
codes := [4]int{200, 200, 503, 200}   // явная длина и все элементы
ports := [...]int{80, 443, 8080}      // компилятор сам посчитает длину: тип [3]int
labels := [4]string{0: "ok", 3: "err"} // по индексам; [1] и [2] останутся ""
```

Обратите внимание на запись `[...]int{...}`: троеточие не делает массив «динамическим». Компилятор просто считает элементы в фигурных скобках и фиксирует тип `[3]int` навсегда.

## Массив в Go — это значение, а не скрытый указатель

Если вы раньше сталкивались с Си или C++, запомните важное отличие: **в Go массив — полноценное значение**. Когда вы пишете `backup := codes` или передаёте `codes` в функцию, Go **копирует все элементы целиком**.

У такого подхода есть приятный бонус: массивы одинакового типа (если их элементы можно сравнивать) поддерживают операторы `==` и `!=`. Сравнение проверяет все элементы по порядку.

Посмотрим на копирование, сравнение и изменение через указатель `*[4]int` в одной рабочей программе:

```go
package main

import "fmt"

func overwriteCopy(buf [4]int) {
	buf[0] = 500 // меняем только локальную копию
}

func resetAll(buf *[4]int) {
	for i := range len(buf) {
		buf[i] = 0 // Go позволяет писать buf[i] вместо (*buf)[i]
	}
}

func main() {
	codes := [4]int{200, 200, 503, 200}
	snapshot := codes // полная копия всех 4 чисел
	snapshot[2] = 200

	fmt.Println("codes:   ", codes)
	fmt.Println("snapshot:", snapshot)
	fmt.Println("равны?:  ", codes == snapshot)

	overwriteCopy(codes)
	fmt.Println("после overwriteCopy:", codes)

	resetAll(&codes)
	fmt.Println("после resetAll:     ", codes)
}
```

Вывод терминала:

```text
codes:    [200 200 503 200]
snapshot: [200 200 200 200]
равны?:   false
после overwriteCopy: [200 200 503 200]
после resetAll:      [0 0 0 0]
```

Заметьте удобную мелочь в `resetAll`: когда у вас есть указатель на массив `buf *[4]int`, Go разрешает писать коротко `buf[i]` и `len(buf)` вместо громоздкого `(*buf)[i]`.

## Где массивы реально нужны (и почему их не хватает)

Из-за жёсткой длины в прикладном Go массивы напрямую пишут редко — но есть задачи, где фиксированный размер как раз защищает от ошибок:

* **Криптографические хеши и бинарные метки:** контрольная сумма SHA-256 всегда занимает ровно `[32]byte`, ни байтом больше и ни байтом меньше. Тип `[32]byte` гарантирует правильный размер прямо на этапе компиляции и позволяет сравнивать хеши через `==`.
* **Фиксированные буферы и палитры:** цвет RGB — это всегда `[3]uint8`, координаты на плоскости — `[2]float64`, матрица преобразования — `[3][3]float64`.
* **Фундамент под динамическими списками:** именно на обычных массивах в памяти строятся слайсы, о которых пойдёт речь в следующем уроке.

А вот для `BookmarkFlow` массив не подходит в принципе. Программа не знает заранее, добавит ли пользователь 3 закладки или 3 000. Нельзя написать одну функцию `printTitles(titles [10]string)` и передать в неё список из 3 или 15 закладок — компилятор отклонит вызов из-за несовпадения типов.

## Подводные камни

1. **Выход за границы массива.** Если индекс — константа (`codes[4]`), компилятор остановит сборку ошибкой `invalid argument: index 4 out of bounds [0:4]`. Если индекс лежит в переменной (`i := 4; codes[i]`), программа скомпилируется, но упадёт в рантайме с паникой:
   ```text
   panic: runtime error: index out of range [4] with length 4
   ```
   В отличие от Си, Go проверяет границы при каждом обращении и никогда не позволит тихо прочитать чужую память за концом массива.
2. **Случайное копирование крупного массива.** Функция `func parse(buf [4096]byte)` при каждом вызове копирует 4 килобайта. Если размер действительно велик и менять тип на слайс нельзя, передавайте указатель `*[4096]byte`.

> [!check] Проверь понимание
> Что напечатает этот фрагмент?
> ```go
> a := [...]int{10, 20, 30}
> b := a
> b[1] = 99
> fmt.Println(a[1], a == b)
> ```
>
> Выведет `20 false`. Массив `b` получил независимую копию элементов `a`: правка `b[1]` не затронула `a[1]`, и после изменения поэлементное сравнение `a == b` возвращает `false`.

## Практика

**Упражнение 1 (Базовое). Проследи вывод.**  
Определите без запуска, что напечатает программа, и объясните почему:

```go
package main

import "fmt"

func bumpFirst(a [3]int) {
	a[0] += 100
}

func bumpLast(a *[3]int) {
	a[2] += 100
}

func main() {
	ports := [...]int{80, 443, 8080}
	bumpFirst(ports)
	bumpLast(&ports)
	fmt.Println(ports)
}
```

> [!solution] Показать решение
> Программа выведет `[80 443 8180]`.
>
> `bumpFirst` принимает массив `[3]int` по значению и изменяет лишь его локальную копию, поэтому `ports[0]` остаётся `80`. `bumpLast` получает указатель `*[3]int` на исходный массив и увеличивает `ports[2]` с `8080` до `8180`.

**Упражнение 2 (Практическое). Поиск максимальной задержки.**  
Напишите функцию `maxLatency(samples [5]int) (int, int)`, которая принимает 5 замеров времени ответа сервера (в миллисекундах) и возвращает максимальную задержку и индекс её первого появления (`0..4`). Проверьте на `[5]int{12, 45, 19, 45, 8}` (ожидаемый вывод: `45 1`).

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func maxLatency(samples [5]int) (int, int) {
> 	bestVal := samples[0]
> 	bestIdx := 0
> 	for i := 1; i < len(samples); i++ {
> 		if samples[i] > bestVal {
> 			bestVal = samples[i]
> 			bestIdx = i
> 		}
> 	}
> 	return bestVal, bestIdx
> }
>
> func main() {
> 	val, idx := maxLatency([5]int{12, 45, 19, 45, 8})
> 	fmt.Println(val, idx) // 45 1
> }
> ```
> Стартуем с `samples[0]`, а не с `0`, чтобы функция оставалась корректной даже на отрицательных числах. Строгое неравенство `>` гарантирует сохранение первого индекса при совпадении максимумов.

**Упражнение 3 (Со звёздочкой \*). Разворот массива на месте.**  
Напишите функцию `reverseInPlace(a *[6]int)`, которая разворачивает элементы массива в обратном порядке **без создания второго массива**, двигаясь двумя индексами с краёв к центру. Проверьте на `[6]int{10, 20, 30, 40, 50, 60}`.

> [!solution] Показать решение
> ```go
> package main
>
> import "fmt"
>
> func reverseInPlace(a *[6]int) {
> 	if a == nil {
> 		return
> 	}
> 	for left, right := 0, len(a)-1; left < right; left, right = left+1, right-1 {
> 		a[left], a[right] = a[right], a[left]
> 	}
> }
>
> func main() {
> 	nums := [6]int{10, 20, 30, 40, 50, 60}
> 	reverseInPlace(&nums)
> 	fmt.Println(nums) // [60 50 40 30 20 10]
> }
> ```
> Условие `left < right` останавливает цикл ровно на середине (3 обмена для 6 элементов). Проверка `a == nil` защищает от паники, если вызывающий код передаст пустой указатель.

---

Массив `[N]T` даёт компактную непрерывную раскладку в памяти, но его фиксированный размер не позволяет растить список закладок на лету. В следующем уроке [[4. Слайсы — заголовок (ptr, len, cap) и механика append]] мы увидим, как Go строит поверх обычного массива гибкий динамический список с помощью крошечного заголовка из трёх полей.
