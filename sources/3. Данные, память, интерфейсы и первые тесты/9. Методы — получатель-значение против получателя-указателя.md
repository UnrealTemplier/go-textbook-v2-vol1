*Как привязать поведение напрямую к типу, выбрать между получателем-значением и получателем-указателем и не попасться на скрытое копирование.*

На прошлом уроке мы собрали поля закладки в `Bookmark`, но операции над ней остались разрозненными функциями: `rename(&b, ...)`, `validateBookmark(&b)`, `formatBookmark(b)`. Чем больше типов в проекте, тем длиннее становятся имена таких функций и тем труднее с ходу понять, что именно «умеет» конкретный тип.

В Go поведение привязывают прямо к типу с помощью **методов** — и запись превращается в чистое `b.Validate()` или `b.Summary()`.

## Что такое метод и получатель (*receiver*)

Метод в Go — это обычная функция, у которой между ключевым словом `func` и именем стоит дополнительный параметр в скобках. Его называют **получателем** (*receiver*):

```go
// Получатель-значение (b Bookmark): метод получает копию закладки
func (b Bookmark) Summary() string {
	return fmt.Sprintf("#%d %s (%s)", b.ID, b.Title, b.URL)
}

// Получатель-указатель (b *Bookmark): метод получает адрес исходной закладки
func (b *Bookmark) Validate() error {
	b.Title = strings.TrimSpace(b.Title)
	b.URL = strings.TrimSpace(b.URL)
	if b.Title == "" {
		return ErrEmptyTitle
	}
	if !strings.HasPrefix(b.URL, "http://") && !strings.HasPrefix(b.URL, "https://") {
		return fmt.Errorf("%w: %q", ErrInvalidURL, b.URL)
	}
	return nil
}
```

Обратите внимание на две детали идиоматичного Go:

1. **Имя получателя — 1–2 буквы от имени типа** (`b` для `Bookmark`, `k` для `Kopeks`), а не `this` или `self`. В Go получатель — такой же обычный параметр, как и остальные.
2. **Методы можно объявлять на любом пользовательском типе** в том же пакете — не только на структурах. Например, на `type Kopeks int64` удобно повесить метод `func (k Kopeks) Format() string`.

## Главная разница: копия против оригинала

Разницу между двумя видами получателя проще всего увидеть в памяти:

```text
  получатель-значение:   func (b Bookmark) ...   ──▶ внутри метода КОПИЯ b
  получатель-указатель:  func (b *Bookmark) ...  ──▶ внутри метода АДРЕС исходного b
```

Если написать `func (b Bookmark) AddTag(tag string)` с получателем-значением, метод честно допишет тег в поле `b.Tags` **своей локальной копии** — а после возврата из метода эта копия исчезнет, и исходная закладка останется без нового тега. Чтобы правки сохранялись, нужен **получатель-указатель** `(b *Bookmark)`.

## Авто-взятие адреса и авто-разыменование

При вызове метода компилятор сам подставляет `&` или `*`:

```go
b := Bookmark{ID: 1, Title: "  Go Spec  ", URL: "https://go.dev/ref/spec"}
p := &b

_ = b.Validate() // компилятор подставит (&b).Validate()
_ = p.Summary()  // компилятор подставит (*p).Summary()
```

Граница одна: для авто-взятия адреса значение должно быть **адресуемым** (переменная, элемент слайса или поле адресуемой структуры). У временного литерала и элемента мапы адреса нет:

```go
_ = Bookmark{Title: "Go"}.Validate()
// compile error: cannot call pointer method Validate on Bookmark
```

## Три правила выбора: `*T` против `T`

Выбор получателя опирается на три чётких правила:

1. **Метод изменяет состояние получателя** → строго **получатель-указатель** `*T`, иначе правки пропадут в копии.
2. **Структура крупная или не должна копироваться** → **получатель-указатель** `*T`, чтобы не гонять лишние копии при каждом вызове.
3. **Тип маленький и неизменяемый** (`Kopeks`, `Point`, метка времени) → **получатель-значение** `T`.

Плюс **правило единообразия**: если хотя бы один метод структуры требует получателя-указателя `*T`, переведите на `*T` **все** методы этой структуры, включая читающие. Смешивание `T` и `*T` путает читателя и ломает предсказуемость при работе с интерфейсами (увидим на уроке 11).

## Вызов метода на `nil`-указателе

Во многих языках вызов метода на пустой ссылке сразу роняет программу. В Go получатель — просто первый аргумент функции, поэтому вызов на `nil`-указателе законен. Паника возникнет только при попытке прочитать или записать поле (`b.Title`). Если проверить `if b == nil`, метод безопасно вернёт запасное значение:

```go
func (b *Bookmark) Summary() string {
	if b == nil {
		return "<пустая закладка>"
	}
	return fmt.Sprintf("#%d %s (%s)", b.ID, b.Title, b.URL)
}
```

## Рабочий пример

Проверим оба вида получателей, нормализацию и безопасный вызов на `nil`-указателе в одной программе:

```go
package main

import (
	"errors"
	"fmt"
	"slices"
	"strings"
)

var (
	ErrEmptyTitle = errors.New("название закладки не может быть пустым")
	ErrInvalidURL = errors.New("ссылка должна начинаться с http:// или https://")
)

type Kopeks int64

func (k Kopeks) Format() string {
	sign := ""
	v := int64(k)
	if v < 0 {
		sign = "-"
		v = -v
	}
	return fmt.Sprintf("%s%d руб. %02d коп.", sign, v/100, v%100)
}

type Bookmark struct {
	ID    int
	Title string
	URL   string
	Tags  []string
}

func (b *Bookmark) Validate() error {
	b.Title = strings.TrimSpace(b.Title)
	b.URL = strings.TrimSpace(b.URL)
	if b.Title == "" {
		return ErrEmptyTitle
	}
	if !strings.HasPrefix(b.URL, "http://") && !strings.HasPrefix(b.URL, "https://") {
		return fmt.Errorf("%w: %q", ErrInvalidURL, b.URL)
	}
	return nil
}

func (b *Bookmark) AddTag(raw string) {
	tag := strings.ToLower(strings.TrimSpace(raw))
	if tag == "" || slices.Contains(b.Tags, tag) {
		return
	}
	b.Tags = append(b.Tags, tag)
}

func (b *Bookmark) Summary() string {
	if b == nil {
		return "<пустая закладка>"
	}
	return fmt.Sprintf("#%d %s [%s]", b.ID, b.Title, strings.Join(b.Tags, ", "))
}

func main() {
	b := Bookmark{ID: 1, Title: "  Go Docs  ", URL: " https://go.dev/doc "}
	if err := b.Validate(); err != nil {
		fmt.Println("Ошибка:", err)
		return
	}
	b.AddTag("Go")
	b.AddTag("docs")
	b.AddTag(" go ")

	var empty *Bookmark
	price := Kopeks(1590)

	fmt.Println(b.Summary())
	fmt.Println(empty.Summary())
	fmt.Println("Подписка:", price.Format())
}
```

Вывод программы:

```text
#1 Go Docs [go, docs]
<пустая закладка>
Подписка: 15 руб. 90 коп.
```

Обратите внимание, как чисто читается `main`: у `Bookmark` все методы единообразно на `*Bookmark` (потому что `Validate` и `AddTag` меняют поля), а маленький числовой тип `Kopeks` использует получатель-значение.

> [!check] Проверь понимание
> Разработчик написал метод с получателем-значением:
> ```go
> func (b Bookmark) ResetTags() {
> 	b.Tags = nil
> }
> ```
> Он вызывает `b.ResetTags()`, а затем печатает `len(b.Tags)`. Что напечатает программа, если до вызова в `b.Tags` было два тега?
>
> Напечатает `2`. Внутри `ResetTags` обнулилось поле `Tags` у локальной копии структуры `b`, а заголовок слайса в исходной переменной не изменился. Чтобы очистить теги по-настоящему, нужен получатель-указатель `(b *Bookmark)`.

## Практика

**Упражнение 1 (Базовое). Метод на именованном типе.**  
Объявите `type Minutes int` и напишите метод `(m Minutes) Format() string` с получателем-значением, который для `135` возвращает `"2ч 15м"`, для `45` — `"45м"`, а для `0` — `"0м"`.

> [!solution] Показать решение
> ```go
> type Minutes int
>
> func (m Minutes) Format() string {
> 	h := int(m) / 60
> 	min := int(m) % 60
> 	if h == 0 {
> 		return fmt.Sprintf("%dм", min)
> 	}
> 	return fmt.Sprintf("%dч %dм", h, min)
> }
> ```
> Тип `Minutes` — одно целое число, которое метод не изменяет, поэтому получатель-значение подходит идеально.

**Упражнение 2 (Практическое). Безопасные методы `HasTag` и `RemoveTag`.**  
Добавьте к `Bookmark` два метода с получателем-указателем `*Bookmark`:
- `HasTag(raw string) bool` — возвращает `false`, если `b == nil`, иначе проверяет наличие нормализованного тега;
- `RemoveTag(raw string) bool` — удаляет нормализованный тег из `b.Tags` через `slices.Index` и `slices.Delete`, возвращая `true`, если тег был найден и удалён (для `b == nil` безопасно возвращает `false`).

> [!solution] Показать решение
> ```go
> func (b *Bookmark) HasTag(raw string) bool {
> 	if b == nil {
> 		return false
> 	}
> 	tag := strings.ToLower(strings.TrimSpace(raw))
> 	return slices.Contains(b.Tags, tag)
> }
>
> func (b *Bookmark) RemoveTag(raw string) bool {
> 	if b == nil {
> 		return false
> 	}
> 	tag := strings.ToLower(strings.TrimSpace(raw))
> 	idx := slices.Index(b.Tags, tag)
> 	if idx == -1 {
> 		return false
> 	}
> 	b.Tags = slices.Delete(b.Tags, idx, idx+1)
> 	return true
> }
> ```
> Оба метода держат единый стиль `*Bookmark` и корректно обрабатывают `nil`-указатель без паники.

**Упражнение 3 (Со звёздочкой \*). Что сломается?**  
Почему следующий код не компилируется, и какими двумя способами его можно исправить?
```go
items := map[int]Bookmark{
	1: {ID: 1, Title: "  Go  ", URL: "https://go.dev"},
}
_ = items[1].Validate()
```

> [!solution] Показать решение
> Ошибка компилятора: `cannot call pointer method Validate on Bookmark`. Выражение `items[1]` неадресуемо (элементы мапы нельзя брать по адресу), поэтому компилятор не может подставить `(&items[1]).Validate()`.
>
> Два правильных исправления:
> 1. Хранить указатели в мапе: `items := map[int]*Bookmark{1: {ID: 1, Title: "  Go  ", URL: "https://go.dev"}}` — тогда `items[1]` уже имеет тип `*Bookmark`, и `items[1].Validate()` работает напрямую.
> 2. Скопировать значение в переменную, вызвать метод и записать обратно:
> ```go
> bm := items[1]
> _ = bm.Validate()
> items[1] = bm
> ```
