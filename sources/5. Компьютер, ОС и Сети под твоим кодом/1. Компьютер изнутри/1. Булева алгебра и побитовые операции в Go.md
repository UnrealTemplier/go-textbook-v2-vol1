*Как упаковать восемь независимых флагов в один байт и почему в Go появился собственный оператор сброса битов `&^`.*

Представьте, что в `BookmarkFlow` у каждой закладки нужно хранить набор прав доступа и служебных признаков: можно ли её читать, редактировать, удалять, открывать публично, архивировать и закреплять в списке. Наивное решение — завести шесть отдельных полей `bool` в структуре или передавать в функцию шесть булевых аргументов подряд: `OpenFile(path, true, false, true, false, true)`.

Такой код невозможно читать без документации, а шесть булевых полей занимают шесть байтов, хотя несут всего шесть битов информации. В операционных системах, сетевых заголовках и стандартной библиотеке Go (`os.O_CREATE | os.O_WRONLY`) эту задачу полвека решают иначе: каждый флаг — это отдельный бит внутри одного целого числа.

## Интуиция: восемь тумблеров в одном байте

Вспомним из Модуля 1: один байт (`uint8`) — это восемь битов, каждый из которых равен `0` или `1`. Можно представить его как панель из восьми независимых тумблеров, пронумерованных справа налево от `0` до `7`:

```text
Бит:       7   6   5   4   3   2   1   0
Вес (2^n): 128 64  32  16  8   4   2   1
Значение:  0   0   0   0   0   1   0   1   = 4 + 1 = 5
```

Аналогия с панелью тумблеров бьёт ровно в одно свойство: переключение бита №2 не затрагивает соседние биты. На этом аналогия заканчивается — в процессоре над всеми битами числа операции выполняются **одновременно за один такт** на уровне логических вентилей. Это и есть **побитовые операции** (*bitwise operations*): одна машинная команда обрабатывает сразу 8, 32 или 64 бита.

## Шесть побитовых операторов Go

В Go определены шесть побитовых операторов для целых типов. Четыре из них действуют поразрядно (каждая пара битов в одной позиции вычисляется независимо):

| Оператор | Название | Правило для пары битов | Главная задача |
|---|---|---|---|
| `&` | Побитовое И (*AND*) | `1`, только если оба `1` | Проверить или выделить биты по маске |
| `\|` | Побитовое ИЛИ (*OR*) | `1`, если хотя бы один `1` | Включить (установить в `1`) нужные биты |
| `^` | Исключающее ИЛИ (*XOR*) | `1`, если биты разные | Инвертировать (переключить) выбранные биты |
| `&^` | И-НЕ (*AND NOT*, bit clear) | `1`, если левый `1`, а правый `0` | Сбросить в `0` биты, заданные маской |

Отдельно стоит унарный `^x` — побитовое НЕ (*NOT*), которое переворачивает все биты числа (`0` в `1`, `1` в `0`). В Си для этого используется тильда `~x`, но авторы Go отказались от отдельного символа и перегрузили `^`.

Оператор `&^` (*bit clear*) — фирменная особенность Go. В Си, чтобы сбросить флаг `Write`, пишут `perm & ^Write` (или `perm & ~Write`), легко забывая скобки или ошибаясь с шириной типа. В Go `perm &^ Write` читается буквально: «оставь биты из `perm`, но выключи те, что равны `1` в `Write`». Проверим на 4 битах:

```text
  perm  = 0111 (Read | Write | Exec)
  Write = 0010
  ------------
  &^    = 0101 (Read | Exec)
```

Ещё два оператора — **битовые сдвиги** (*bit shifts*):

* `x << n` — сдвиг влево на `n` позиций; справа дописываются нули. Для неотрицательных чисел без переполнения это равносильно умножению на $2^n$. Именно так строят маски: `1 << 0` даёт `0001` (1), `1 << 1` — `0010` (2), `1 << 2` — `0100` (4).
* `x >> n` — сдвиг вправо на `n` позиций; для беззнаковых чисел слева приходят нули (деление нацело на $2^n$). Для знаковых отрицательных чисел слева копируется знаковый бит — это называется *арифметическим сдвигом*, и его смысл мы разберём в следующем уроке.

## Рабочий код: битовые маски прав через `1 << iota`

Идиоматичный способ задать флаги в Go — объявить собственный беззнаковый тип и сгенерировать степени двойки с помощью `1 << iota`. Посмотрим на примере прав доступа к коллекции закладок (по тому же принципу устроены права файлов в Unix и флаги пакета `os`):

```go
package main

import (
	"fmt"
	"strings"
)

type Perm uint8

const (
	PermRead  Perm = 1 << iota // 0001 (1)
	PermWrite                  // 0010 (2)
	PermExec                   // 0100 (4)
	PermShare                  // 1000 (8)
)

func (p Perm) Has(flag Perm) bool {
	return p&flag == flag
}

func (p Perm) String() string {
	var parts []string
	if p.Has(PermRead) {
		parts = append(parts, "r")
	}
	if p.Has(PermWrite) {
		parts = append(parts, "w")
	}
	if p.Has(PermExec) {
		parts = append(parts, "x")
	}
	if p.Has(PermShare) {
		parts = append(parts, "s")
	}
	if len(parts) == 0 {
		return "-"
	}
	return strings.Join(parts, "")
}

func main() {
	// Собираем маску через ИЛИ: чтение + запись + расшаривание.
	user := PermRead | PermWrite | PermShare
	fmt.Printf("старт:    %04b (%s)\n", user, user)

	// Сбрасываем право записи оператором &^.
	user &^= PermWrite
	fmt.Printf("без w:    %04b (%s)\n", user, user)

	// Переключаем право исполнения через XOR.
	user ^= PermExec
	fmt.Printf("после ^x: %04b (%s)\n", user, user)

	// Проверяем составную маску: есть ли сразу и чтение, и исполнение.
	need := PermRead | PermExec
	fmt.Println("есть r и x:", user.Has(need))
}
```

Запуск программы печатает:

```text
старт:    1011 (rws)
без w:    1001 (rs)
после ^x: 1101 (rxs)
есть r и x: true
```

Обратите внимание на метод `Has(flag Perm)`: он сравнивает `p&flag == flag`, а не `p&flag != 0`. Разница критична, когда `flag` составной (например, `PermRead | PermExec`): сравнение `!= 0` вернуло бы `true`, даже если из двух прав включено только одно. Равенство `p&flag == flag` гарантирует, что выставлены **все** биты маски.

## Подводные камни

**Ловушка 1. Приоритет побитовых операторов и `==`.**  
В отличие от Си, в Go оператор `&` имеет **более высокий** приоритет, чем `==` и `!=`, поэтому запись `p&flag == flag` безопасна даже без скобок. Но оператор `|` стоит на одном уровне с `+` и `-`, а сдвиги `<<` и `>>` — на одном уровне с `*` и `/`. В составных выражениях вроде `(a | b) & c` или `1<<n - 1` всегда ставьте скобки, если есть хоть малейшее сомнение в читаемости.

**Ловушка 2. Сдвиг на число, большее или равное ширине типа.**  
Если сдвинуть `uint8(1)` на 8 позиций влево (`uint8(1) << 8`), единица полностью уйдёт за пределы байта, и результат станет `0`:

```go
var b uint8 = 1
fmt.Println(b << 8) // Вывод: 0
```

А попытка сдвинуть на отрицательное число в Go и вовсе не пройдёт компиляцию для константы или вызовет панику во время выполнения:

```go
shift := -1
_ = 1 << shift // panic: runtime error: negative shift amount
```

> [!check] Проверь понимание
> Что окажется в переменной `mask` после выполнения двух строк?
> ```go
> mask := PermRead | PermWrite | PermExec // 0111
> mask = (mask &^ PermWrite) ^ PermRead
> ```
>
> Сначала `mask &^ PermWrite` сбросит бит записи: `0111 &^ 0010 = 0101` (`PermRead | PermExec`). Затем `^ PermRead` переключит бит чтения: `0101 ^ 0001 = 0100`. Останется только `PermExec`.

## Практика

**Упражнение 1 (Базовое). Проследи вывод побитовых операций.**  
Не запуская код, определите, что напечатает программа в двоичном виде (`%04b`) и в десятичном:

```go
a := uint8(0b1100)
b := uint8(0b1010)
fmt.Printf("AND:    %04b (%d)\n", a&b, a&b)
fmt.Printf("OR:     %04b (%d)\n", a|b, a|b)
fmt.Printf("XOR:    %04b (%d)\n", a^b, a^b)
fmt.Printf("ANDNOT: %04b (%d)\n", a&^b, a&^b)
```

> [!solution] Показать решение
> Разбираем поразрядно каждую из четырёх позиций `a = 1100` и `b = 1010`:
> ```text
> AND:    1000 (8)
> OR:     1110 (14)
> XOR:    0110 (6)
> ANDNOT: 0100 (4)
> ```
> В `a&^b` единица остаётся только во втором бите слева (вес 4), где в `a` стоит `1`, а в `b` стоит `0`.

**Упражнение 2 (Практическое). Упаковка и распаковка RGB-цвета.**  
Цвет в формате RGB задаётся тремя байтами `r, g, b uint8`. Напишите две функции:
* `PackRGB(r, g, b uint8) uint32` — упаковывает три байта в одно число `0x00RRGGBB`;
* `UnpackRGB(rgb uint32) (r, g, b uint8)` — извлекает их обратно.

Проверьте на цвете `(0x1A, 0x7F, 0xE2)`.

> [!solution] Показать решение
> Сдвигаем старшие каналы влево на 16 и 8 битов и объединяем через `|`. При распаковке сдвигаем вправо и берём младший байт маской `0xFF` (или приведением к `uint8`):
> ```go
> package main
>
> import "fmt"
>
> func PackRGB(r, g, b uint8) uint32 {
> 	return uint32(r)<<16 | uint32(g)<<8 | uint32(b)
> }
>
> func UnpackRGB(rgb uint32) (r, g, b uint8) {
> 	r = uint8((rgb >> 16) & 0xFF)
> 	g = uint8((rgb >> 8) & 0xFF)
> 	b = uint8(rgb & 0xFF)
> 	return r, g, b
> }
>
> func main() {
> 	packed := PackRGB(0x1A, 0x7F, 0xE2)
> 	r, g, b := UnpackRGB(packed)
> 	fmt.Printf("0x%06X -> (%#02X, %#02X, %#02X)\n", packed, r, g, b)
> 	// Вывод: 0x1A7FE2 -> (0x1A, 0x7F, 0xE2)
> }
> ```
> Обратите внимание: перед сдвигом `r` и `g` обязательно приводим к `uint32`, иначе сдвиг `uint8` на 8 или 16 битов обнулит значение.

**Упражнение 3 (Со звёздочкой \*). Проверка степени двойки без цикла.**  
Напишите функцию `IsPowerOfTwo(n uint64) bool`, которая за одну побитовую операцию проверяет, является ли `n` точной степенью двойки (`1, 2, 4, 8, ...`). Проследите граничный случай `n == 0`.

> [!solution] Показать решение
> У степени двойки в двоичной записи ровно одна единица (например, `8 = 1000`). У числа `n - 1` эта единица обнуляется, а все младшие биты становятся единицами (`7 = 0111`). Их побитовое И равно нулю только у степеней двойки — и у самого нуля, который нужно исключить отдельно:
> ```go
> package main
>
> import "fmt"
>
> func IsPowerOfTwo(n uint64) bool {
> 	return n > 0 && (n&(n-1)) == 0
> }
>
> func main() {
> 	for _, v := range []uint64{0, 1, 2, 3, 4, 15, 16, 64} {
> 		fmt.Printf("%2d: %v\n", v, IsPowerOfTwo(v))
> 	}
> }
> ```
> Проверка `n > 0` защищает от ложного срабатывания на нуле и от беззнакового переполнения при `0 - 1`.

---

С беззнаковыми байтами и битовыми масками всё прозрачно: каждый бит несёт положительный вес $2^n$. Но как процессор хранит отрицательные числа вроде `-1` или `-128`, если внутри памяти есть только нули и единицы без знака «минус»? В следующем уроке разберём изящное решение этой задачи — [[2.
