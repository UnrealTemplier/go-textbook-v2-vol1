*Как устроены 32-битные и 128-битные адреса, зачем нужны маски подсетей CIDR и почему сервер на `127.0.0.1` недоступен снаружи.*

Вы запускаете свой сервис `BookmarkFlow` на удалённом сервере Linux, указав адрес `127.0.0.1:8080`. Проверка прямо с того же сервера проходит успешно. Но как только коллега пытается подключиться с соседней машины по IP-адресу сервера, он мгновенно получает `connection refused`. Процесс жив, порт верный, сеть работает — почему же пакеты отвергаются?

Ответ кроется в том, как устроены IP-адреса, подсети и сетевые интерфейсы операционной системы.

## IPv4 и нотация подсетей CIDR

Адрес **IPv4** — это одно 32-битное целое число без знака. Для удобства людей его делят на четыре байта (октета) от `0` до `255` через точку: например, `192.168.1.42`. Всего существует $2^{32} = 4\,294\,967\,296$ таких адресов.

Маршрутизатору невыгодно хранить в таблице отдельную строку для каждого из четырёх миллиардов компьютеров. Вместо этого адреса объединяют в **подсети** (*subnets*) с общим двоичным префиксом. Запись вида **`192.168.1.0/24`** называется нотацией **CIDR** (*Classless Inter-Domain Routing*). Число после слэша показывает, сколько старших битов слева задают номер самой сети, а оставшиеся биты справа отданы конкретным устройствам (хостам):

```text
Адрес:   192.168.1.42  =  11000000.10101000.00000001 | 00101010
Префикс: /24           =  <--- 24 бита сети --------> | <8 бит>
                          одинаковы у всех в подсети   хост № 42
```

В подсети `/24` под номера устройств остаётся $32 - 24 = 8$ битов, то есть $2^8 = 256$ адресов (`192.168.1.0` … `192.168.1.255`). Первый адрес (`.0`) обозначает саму сеть, последний (`.255`) — широковещательную рассылку внутри неё, поэтому устройствам выдают 254 адреса. Чем больше число после слэша, тем меньше подсеть: `/16` вмещает 65 536 адресов, `/24` — 256, а `/32` указывает ровно на один конкретный IPv4-адрес.

## Приватные сети и IPv6

Четыре миллиарда публичных IPv4-адресов закончились задолго до появления миллиардов смартфонов и облачных машин. Проблему решают двумя способами.

Первый — **приватные диапазоны** (стандарт RFC 1918), которые зарезервированы для внутренних сетей и не маршрутизируются в публичном Интернете:

* `10.0.0.0/8` — 16,7 млн адресов (крупные офисы и дата-центры);
* `172.16.0.0/12` — около 1 млн адресов (внутренние корпоративные и виртуальные сети);
* `192.168.0.0/16` — 65 536 адресов (домашние и небольшие локальные сети).

Миллионы квартир одновременно используют один и тот же адрес `192.168.1.10`, и они не мешают друг другу, потому что наружу такие пакеты не выпускаются напрямую.

Второй, стратегический путь — **IPv6**, принятый ещё в 1990-х годах. Его адрес занимает **128 битов** (16 байтов) и записывается восемью шестнадцатеричными группами по 16 битов через двоеточие: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`. Подряд идущие нулевые группы сжимают двойным двоеточием `::` (один раз на адрес). Запас адресов составляет $2^{128} \approx 3{,}4 \times 10^{38}$ — его хватит с огромным запасом даже для каждого устройства на планете.

## Критическая разница: `127.0.0.1` против `0.0.0.0`

У любой машины с ОС есть не один IP-адрес, а список **сетевых интерфейсов**, и у каждого свой адрес. На типичном сервере одновременно живут как минимум два интерфейса:

1. **Петлевой интерфейс (`lo`, *loopback*)** с адресом **`127.0.0.1`** (в IPv6 — **`::1`**), к которому привязано имя `localhost`. Весь трафик на этот интерфейс крутится строго внутри ядра ОС и никогда не выходит в сетевую карту.
2. **Внешний или локальный интерфейс** (например, `eth0` с адресом `10.0.1.15` или публичным `203.0.113.10`), через который приходят пакеты от других машин.

Теперь причина сбоя из начала урока очевидна:

```text
Слушаем 127.0.0.1:8080                Слушаем 0.0.0.0:8080
  lo   (127.0.0.1)  <-- [ПРИНЯТО]       lo   (127.0.0.1)  <-- [ПРИНЯТО]
  eth0 (10.0.1.15)  <-- [ОТКАЗ]         eth0 (10.0.1.15)  <-- [ПРИНЯТО]
```

* Привязка к **`127.0.0.1:8080`** говорит ядру: «принимай соединения **только** с моей собственной машины». Это безопасный выбор для локальной разработки и тестов — никто из внешней Wi-Fi сети не достучится до вашего отладочного сервера.
* Привязка к **`0.0.0.0:8080`** (в IPv6 — **`[::]:8080`**, а в Go короткая запись `":8080"` слушает все доступные интерфейсы) говорит ядру: «принимай соединения, пришедшие на **любой** сетевой интерфейс этой машины».

Запомните важное ограничение: `0.0.0.0` — это специальный адрес **привязки** для сервера (*unspecified address*), а не адрес назначения. В качестве цели клиент всегда указывает конкретный IP машины (`127.0.0.1`, `10.0.1.15` или публичный IP).

## Современный пакет `net/netip` в Go

В ранних версиях Go IP-адрес представляли типом `net.IP`, который является слайсом `[]byte`. У слайса три неудобных свойства для сетевого кода: его нельзя использовать как ключ в мапе, его легко случайно изменить по ссылке, а один и тот же адрес мог храниться и в 4 байтах, и в 16.

Начиная с Go 1.18, в стандартной библиотеке появился пакет **`net/netip`**. Его типы `netip.Addr` (адрес) и `netip.Prefix` (подсеть CIDR) — это компактные неизменяемые структуры-значения: они сравниваются через `==`, годятся как ключи в `map` и не создают лишних выделений в куче.

Напишем проверку доступа к административной части `BookmarkFlow` по списку доверенных подсетей:

```go
package main

import (
	"fmt"
	"net/netip"
)

func main() {
	officeNet := netip.MustParsePrefix("10.20.0.0/16")
	homeNet := netip.MustParsePrefix("192.168.1.0/24")

	candidates := []string{
		"127.0.0.1",
		"::1",
		"0.0.0.0",
		"10.20.5.14",
		"192.168.1.50",
		"203.0.113.7",
		"192.168.1.300", // некорректный октет
	}

	for _, raw := range candidates {
		addr, err := netip.ParseAddr(raw)
		if err != nil {
			fmt.Printf("%-15s -> ошибка разбора: %v\n", raw, err)
			continue
		}

		allowed := addr.IsLoopback() || officeNet.Contains(addr) || homeNet.Contains(addr)
		fmt.Printf("%-15s -> v6=%-5t loopback=%-5t private=%-5t unspec=%-5t доступ=%t\n",
			addr, addr.Is6(), addr.IsLoopback(), addr.IsPrivate(), addr.IsUnspecified(), allowed)
	}
}
```

Вывод терминала сразу показывает классификацию каждого адреса и реальную диагностику ошибки парсинга:

```text
127.0.0.1       -> v6=false loopback=true  private=false unspec=false доступ=true
::1             -> v6=true  loopback=true  private=false unspec=false доступ=true
0.0.0.0         -> v6=false loopback=false private=false unspec=true  доступ=false
10.20.5.14      -> v6=false loopback=false private=true  unspec=false доступ=true
192.168.1.50    -> v6=false loopback=false private=true  unspec=false доступ=true
203.0.113.7     -> v6=false loopback=false private=false unspec=false доступ=false
192.168.1.300   -> ошибка разбора: ParseAddr("192.168.1.300"): IPv4 field has value >255
```

Обратите внимание на две детали: для пользовательского ввода мы вызываем `netip.ParseAddr` с проверкой `err`, а `MustParsePrefix` оставляем только для жёстко зашитых в коде констант (при ошибке она вызывает панику). Метод `Contains` сам корректно сопоставляет префикс с адресом и не перепутает IPv4 с IPv6.

## Подводные камни

**Ловушка 1. `0.0.0.0` на сервере с публичным IP.**  
Запустив тестовый сервис на `0.0.0.0:8080` на машине, смотрящей напрямую в Интернет, вы мгновенно открываете его для всех сканеров мира. Если сервис предназначен только для локальных инструментов на той же машине, привязывайтесь строго к `127.0.0.1`.

**Ловушка 2. Путаница между `localhost` и `127.0.0.1` при IPv6.**  
На современных ОС имя `localhost` часто разрешается сначала в IPv6-адрес `::1`, а уже затем в `127.0.0.1`. Если сервер слушает только IPv4 (`127.0.0.1:8080`), а клиент пошёл на `::1:8080`, подключение получит отказ.

> [!check] Проверь понимание
> Входит ли адрес `192.168.2.10` в подсеть `192.168.1.0/24`? А в подсеть `192.168.0.0/16`?
>
> В `192.168.1.0/24` **не входит**: маска `/24` фиксирует первые три октета (`192.168.1`), а третий октет адреса равен `2`. В `192.168.0.0/16` **входит**: маска `/16` фиксирует только первые два октета (`192.168`).

## Практика

**Упражнение 1 (Базовое). Расчёт размера подсети.**  
Сколько всего IPv4-адресов охватывает подсеть `10.0.4.0/28`, и какой в ней последний адрес диапазона?

> [!solution] Показать решение
> Под номер хоста остаётся $32 - 28 = 4$ бита, что даёт $2^4 = 16$ адресов: от `10.0.4.0` до `10.0.4.15` включительно. Из них `10.0.4.0` — адрес сети, `10.0.4.15` — широковещательный, а `10.0.4.1`–`10.0.4.14` (14 адресов) доступны устройствам.

**Упражнение 2 (Практическое). Классификатор адресов на `net/netip`.**  
Напишите функцию `ClassifyAddr(raw string) (string, error)`, которая разбирает строку через `netip.ParseAddr` и возвращает одну из меток: `"loopback"`, `"unspecified"`, `"private"` или `"public"`. При неверной строке функция возвращает ошибку.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"net/netip"
> )
>
> func ClassifyAddr(raw string) (string, error) {
> 	addr, err := netip.ParseAddr(raw)
> 	if err != nil {
> 		return "", err
> 	}
> 	switch {
> 	case addr.IsLoopback():
> 		return "loopback", nil
> 	case addr.IsUnspecified():
> 		return "unspecified", nil
> 	case addr.IsPrivate():
> 		return "private", nil
> 	default:
> 		return "public", nil
> 	}
> }
>
> func main() {
> 	for _, s := range []string{"127.0.0.1", "::", "172.16.5.1", "8.8.8.8"} {
> 		kind, err := ClassifyAddr(s)
> 		fmt.Printf("%-12s -> %s (err=%v)\n", s, kind, err)
> 	}
> }
> ```
> Порядок веток важен: `IsLoopback` и `IsUnspecified` проверяем до общего ветвления, а для обоих семейств IPv4 и IPv6 методы `netip.Addr` работают единообразно.

**Упражнение 3 (Со звёздочкой \*). Проверка по списку CIDR-подсетей.**  
Напишите функцию `IsAllowed(rawIP string, cidrs []string) (bool, error)`, которая принимает строковый IP и слайс CIDR-строк (например, `[]string{"10.0.0.0/8", "2001:db8::/32"}`). Если некорректен сам IP или любая строка из `cidrs`, верните ошибку с пояснением.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"net/netip"
> )
>
> func IsAllowed(rawIP string, cidrs []string) (bool, error) {
> 	addr, err := netip.ParseAddr(rawIP)
> 	if err != nil {
> 		return false, fmt.Errorf("некорректный IP %q: %w", rawIP, err)
> 	}
> 	for _, rawPrefix := range cidrs {
> 		prefix, err := netip.ParsePrefix(rawPrefix)
> 		if err != nil {
> 			return false, fmt.Errorf("некорректная подсеть %q: %w", rawPrefix, err)
> 		}
> 		if prefix.Contains(addr) {
> 			return true, nil
> 		}
> 	}
> 	return false, nil
> }
>
> func main() {
> 	rules := []string{"10.0.0.0/8", "2001:db8::/32"}
> 	fmt.Println(IsAllowed("10.42.0.7", rules))     // Вывод: true <nil>
> 	fmt.Println(IsAllowed("2001:db8::1", rules))   // Вывод: true <nil>
> 	fmt.Println(IsAllowed("198.51.100.2", rules))  // Вывод: false <nil>
> }
> ```
> В реальном сервисе список `[]netip.Prefix` стоит распарсить один раз при старте программы, а не на каждый входящий запрос.
