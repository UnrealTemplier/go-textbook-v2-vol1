*Когда читать файл целиком через `os.ReadFile`, а когда потоком через `os.Open`, почему пути собирают через `filepath.Join` и зачем в Go появился интерфейс `io/fs`.*

Представьте, что вы написали для `BookmarkFlow` сохранение резервных копий и склеили путь вручную: `dir + "/" + name`. На Linux и macOS код работает безупречно. Коллега запускает бинарник на Windows — и получает смесь слэшей `C:\Users\dev/backups/2026.json` или ошибку, если путь содержал лишние разделители и `..`. А при попытке прочитать через `os.ReadFile` экспортированный архив на 2 гигабайта программа внезапно съедает всю свободную память.

Стандартная библиотека Go делит работу с диском на три чистых слоя: пакет `os` отвечает за сами файлы и каталоги, `path/filepath` — за переносимую работу с путями текущей ОС, а `io/fs` — за абстрактную файловую систему только для чтения.

## Файлы целиком против потоков: пакет `os`

Для небольших конфигов и файлов закладок подходят функции верхнего уровня:

* `data, err := os.ReadFile(path)` — читает файл целиком в `[]byte` и закрывает его.
* `err := os.WriteFile(path, data, 0o644)` — записывает весь срез байтов с правами `0o644` (чтение/запись для владельца, чтение для остальных).

Большие файлы (сотни мегабайт) читают и пишут потоком, чтобы не загружать всё в ОЗУ:

* `os.Open(path)` — открывает существующий файл на чтение (`io.Reader`, `io.Closer`).
* `os.Create(path)` — создаёт или очищает файл на запись (`io.Writer`, `io.Closer`).
* `os.MkdirAll(dir, 0o755)` — создаёт каталог вместе с родителями (если уже есть — без ошибки).
* `os.RemoveAll(path)` — удаляет файл или каталог со всем содержимым.

Любой открытый `*os.File` необходимо закрыть. Для чтения достаточно `defer f.Close()` сразу после проверки ошибки открытия. При **записи** часть данных может сброситься на диск только внутри `f.Close()`, поэтому ошибку закрытия проверяют явно.

## Переносимые пути: `path/filepath`

Linux и macOS разделяют каталоги через `/`, Windows — через `\`. Пакет `path/filepath` учитывает правила текущей ОС (тогда как пакет `path` работает только с прямым слэшем `/` для URL и виртуальных путей):

* `filepath.Join("data", "backups", "2026.json")` — соединяет сегменты с нужным разделителем и очищает лишние слэши;
* `filepath.Base(p)`, `filepath.Dir(p)`, `filepath.Ext(p)` — имя файла, родительский каталог и расширение с точкой;
* `filepath.Clean(p)` — приводит путь к каноническому виду (`"a//b/../c"` → `"a/c"`);
* `filepath.WalkDir(root, fn)` — рекурсивно обходит дерево каталогов, передавая облегчённую запись `fs.DirEntry`.

Соберём пример: создадим временный каталог, запишем файлы потоком и обойдём их через `filepath.WalkDir`:

```go
package main

import (
	"bufio"
	"fmt"
	"io/fs"
	"os"
	"path/filepath"
)

func writeLines(path string, lines []string) (err error) {
	if err := os.MkdirAll(filepath.Dir(path), 0o755); err != nil {
		return err
	}
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	defer func() {
		if cerr := f.Close(); cerr != nil && err == nil {
			err = cerr
		}
	}()

	bw := bufio.NewWriter(f)
	for _, line := range lines {
		if _, err := bw.WriteString(line + "\n"); err != nil {
			return err
		}
	}
	return bw.Flush()
}

func main() {
	root, err := os.MkdirTemp("", "bookmarkflow-*")
	if err != nil {
		fmt.Println("ошибка:", err)
		return
	}
	defer os.RemoveAll(root)

	p1 := filepath.Join(root, "2026", "go.txt")
	p2 := filepath.Join(root, "2026", "notes.md")
	if err := writeLines(p1, []string{"https://go.dev"}); err != nil {
		fmt.Println("ошибка:", err)
		return
	}
	if err := writeLines(p2, []string{"# заметки"}); err != nil {
		fmt.Println("ошибка:", err)
		return
	}

	err = filepath.WalkDir(root, func(p string, d fs.DirEntry, walkErr error) error {
		if walkErr != nil {
			return walkErr
		}
		if !d.IsDir() && filepath.Ext(p) == ".txt" {
			fmt.Println("найден файл:", filepath.Base(p))
		}
		return nil
	})
	if err != nil {
		fmt.Println("ошибка обхода:", err)
	}
}
```

Запуск печатает:

```text
найден файл: go.txt
```

Посмотрите на `defer` в `writeLines`: мы сначала сбрасываем буфер `bw.Flush()`, а затем отложенная функция закрывает файл и сохраняет ошибку `f.Close()`, если до этого всё шло без сбоев. Это надёжный шаблон потоковой записи в файл.

## Абстракция файловой системы: `io/fs`

Точно так же, как `io.Reader` отвязал код от конкретного источника байтов, пакет `io/fs` (появившийся в Go 1.16) отвязывает код от реального жёсткого диска.

Интерфейс `fs.FS` состоит ровно из одного метода:

```go
type FS interface {
	Open(name string) (File, error)
}
```

Если функция поиска конфигов принимает `fsys fs.FS` и вызывает `fs.WalkDir(fsys, ".", ...)`, ей совершенно неважно, что передано на вход:

* реальный каталог на диске через `os.DirFS("/etc/bookmarkflow")`;
* виртуальная файловая система в памяти в unit-тесте (`testing/fstest.MapFS`) — тесты работают без создания единого файла на диске;
* файлы, вшитые прямо внутрь бинарника через `embed.FS` (о них пойдёт речь уже в следующем уроке).

Заметьте тонкость: внутри `io/fs` пути **всегда** используют прямой слэш `/` и никогда не начинаются с `/` (даже на Windows), поэтому для работы с путями внутри `fs.FS` применяют пакет `path`, а для путей реальной ОС — `path/filepath`.

## Подводные камни

**Ловушка 1. Вызов `defer f.Close()` до проверки `err != nil`.**  
Если `os.Open` вернул ошибку, `f` равен `nil`. Отложенный `f.Close()` вызовется при возврате, но лучше не полагаться на поведение `nil`-получателя — всегда ставьте `defer f.Close()` **после** `if err != nil { return err }`.

**Ловушка 2. Пропуск аргумента `walkErr` в `filepath.WalkDir`.**  
Если при обходе каталога не хватит прав доступа к вложенной папке, `WalkDir` вызовет ваш колбэк с ненулевой `walkErr` и `d == nil`. Если не проверить `if walkErr != nil` первой строкой и сразу обратиться к `d.IsDir()`, программа упадёт с паникой.

> [!check] Проверь понимание
> В чём разница между `os.Mkdir("a/b/c", 0o755)` и `os.MkdirAll("a/b/c", 0o755)`?
>
> `os.Mkdir` создаёт только последний каталог `c` и вернёт ошибку, если `a` или `a/b` ещё не существуют (или если `a/b/c` уже есть). `os.MkdirAll` создаст всю цепочку `a`, `a/b`, `a/b/c` и спокойно вернёт `nil`, если каталог уже создан.

## Практика

**Упражнение 1 (Базовое). Разбор пути через `path/filepath`.**  
Что вернут функции `filepath.Dir`, `filepath.Base`, `filepath.Ext` и `filepath.Clean` для строки `"data//2026/../exports/links.json"` на Linux?

> [!solution] Показать решение
> * `filepath.Clean` → `"data/exports/links.json"` (схлопнула `//` и отменила `2026/..`);
> * `filepath.Dir` → `"data/exports"`;
> * `filepath.Base` → `"links.json"`;
> * `filepath.Ext` → `".json"`.

**Упражнение 2 (Практическое). Поиск файлов по расширению через `io/fs`.**  
Напишите функцию `FindByExt(fsys fs.FS, ext string) ([]string, error)`, которая с помощью `fs.WalkDir` находит все обычные файлы в `fsys` с указанным расширением (например, `".json"`) и возвращает их пути. Проверьте её на `fstest.MapFS` без создания реальных файлов на диске.

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"fmt"
> 	"io/fs"
> 	"path"
> 	"testing/fstest"
> )
>
> func FindByExt(fsys fs.FS, ext string) ([]string, error) {
> 	var found []string
> 	err := fs.WalkDir(fsys, ".", func(p string, d fs.DirEntry, err error) error {
> 		if err != nil {
> 			return err
> 		}
> 		if !d.IsDir() && path.Ext(p) == ext {
> 			found = append(found, p)
> 		}
> 		return nil
> 	})
> 	return found, err
> }
>
> func main() {
> 	memFS := fstest.MapFS{
> 		"bookmarks.json":     {Data: []byte("[]")},
> 		"sub/archive.json":   {Data: []byte("[]")},
> 		"sub/readme.md":      {Data: []byte("# doc")},
> 	}
> 	files, err := FindByExt(memFS, ".json")
> 	fmt.Println(files, err) // Вывод: [bookmarks.json sub/archive.json] <nil>
> }
> ```
> Использование `path.Ext` (а не `filepath.Ext`) здесь канонично: в `io/fs` разделителем всегда служит `/`.

**Упражнение 3 (Со звёздочкой \*). Защита от выхода за пределы каталога.**  
При приёме имени файла от пользователя строка вроде `"../../etc/passwd"` способна увести `filepath.Join(baseDir, userPath)` за пределы `baseDir`. Напишите функцию `SafeJoin(baseDir, rel string) (string, error)`, которая соединяет пути и возвращает ошибку, если итоговый путь выходит за рамки `baseDir` (подсказка: посмотрите на `filepath.Rel`).

> [!solution] Показать решение
> ```go
> package main
>
> import (
> 	"errors"
> 	"fmt"
> 	"path/filepath"
> 	"strings"
> )
>
> var ErrPathEscape = errors.New("путь выходит за пределы базового каталога")
>
> func SafeJoin(baseDir, rel string) (string, error) {
> 	baseClean := filepath.Clean(baseDir)
> 	target := filepath.Join(baseClean, rel)
>
> 	diff, err := filepath.Rel(baseClean, target)
> 	if err != nil {
> 		return "", err
> 	}
> 	if diff == ".." || strings.HasPrefix(diff, ".."+string(filepath.Separator)) {
> 		return "", ErrPathEscape
> 	}
> 	return target, nil
> }
>
> func main() {
> 	fmt.Println(SafeJoin("/tmp/bookmarks", "2026/a.json"))    // Вывод: /tmp/bookmarks/2026/a.json <nil>
> 	fmt.Println(SafeJoin("/tmp/bookmarks", "../../etc/hosts")) // Вывод:  путь выходит за пределы базового каталога
> }
> ```
> Проверка через `filepath.Rel` надёжнее простого `strings.HasPrefix`, потому что корректно различает `/tmp/bookmarks` и соседний каталог `/tmp/bookmarks-evil`.
