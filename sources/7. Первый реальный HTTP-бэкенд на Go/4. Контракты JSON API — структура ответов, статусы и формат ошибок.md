JSON API — это публичный контракт: клиент должен по HTTP-статусу и единой схеме JSON мгновенно понимать, что произошло.

## Карта HTTP-статусов `BookmarkFlow`

Из Модуля 5 вы помните, что первые цифры статуса делят ответы на классы: `2xx` (успех), `4xx` (ошибка на стороне клиента) и `5xx` (сбой внутри сервера). Для нашего API мы фиксируем чёткую таблицу кодов:

| Код | Константа в `net/http` | Когда возвращаем в `BookmarkFlow` |
|---|---|---|
| `200` | `http.StatusOK` | Успешное чтение, список, обновление (`PUT`), проверка ссылок, `/healthz` |
| `201` | `http.StatusCreated` | Новая закладка создана (`POST /api/v1/bookmarks`) |
| `204` | `http.StatusNoContent` | Закладка удалена (`DELETE`), тело ответа строго пустое |
| `400` | `http.StatusBadRequest` | Битый синтаксис JSON, лишние поля или нечисловой `id` в пути |
| `404` | `http.StatusNotFound` | Закладки с таким `id` нет или маршрут не найден |
| `405` | `http.StatusMethodNotAllowed` | Метод не разрешён для данного пути (отдаёт `ServeMux`) |
| `413` | `http.StatusRequestEntityTooLarge` | Тело запроса превышает лимит в 1 МиБ |
| `422` | `http.StatusUnprocessableEntity` | JSON синтаксически корректен, но нарушены правила (пустой `title`, не `http(s)` URL) |
| `500` | `http.StatusInternalServerError` | Непредвиденный сбой диска или перехваченная паника |

Различие между `400` и `422` особенно полезно: `400` говорит клиенту «мы даже не смогли разобрать ваш JSON или число в URL», а `422` — «JSON прочитан, но данные не прошли проверку бизнес-правил».

## Единый формат успеха и ошибки

Чтобы не повторять установку заголовков и сериализацию в каждом обработчике, в `project/final/server.go` заведены две вспомогательные функции:

```go
func writeJSON(w http.ResponseWriter, status int, payload any) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(payload)
}

func writeJSONError(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, map[string]string{"error": msg})
}
```

Все ошибки сервиса имеют предсказуемый формат `{"error": "текст причины"}`. А для списка закладок в `handleList` используется обёртка-конверт (*envelope*):

```json
{
  "count": 1,
  "items": [
    {
      "id": 1,
      "title": "Go Docs",
      "url": "https://go.dev/doc",
      "tags": ["docs", "go"],
      "created_at": "2026-11-23T16:03:57Z",
      "updated_at": "2026-11-23T16:03:57Z"
    }
  ]
}
```

Зачем заворачивать массив в объект `{"items": [...], "count": N}`, вместо того чтобы отдавать голый JSON-массив `[...]`? Во-первых, в объект легко добавить новые поля (например, общее число записей или маркер следующей страницы) без поломки старых клиентов. Во-вторых, посмотрите на инициализацию слайса в `FileStore.List`:

```go
out := make([]Bookmark, 0, len(f.items))
```

Мы сознательно создаём пустой не-`nil` слайс `make([]Bookmark, 0, ...)`, а не `var out []Bookmark`. Вспомните особенность `encoding/json` из Модуля 4: `nil`-слайс сериализуется в JSON как `null`, а пустой выделенный слайс — как `[]`. Клиентский парсер на фронтенде или в мобильном приложении всегда получит массив, по которому безопасно итерироваться, даже если закладок ноль.

## Ловушки `http.ResponseWriter`

С работой `writeJSON` связаны два классических подвоха, с которыми сталкивается почти каждый разработчик на Go.

**Ловушка 1: заголовки после `WriteHeader` или `Write` игнорируются.** В протоколе HTTP заголовки идут строго **до** тела ответа. Как только вы вызвали `w.WriteHeader(status)` или начали писать тело (например, через `json.NewEncoder(w).Encode(...)`), пакет `net/http` отправляет заголовки в сокет. Попытка вызвать `w.Header().Set(...)` после этого не даст ошибки компиляции, но и в ответ к клиенту заголовок не попадёт.

**Ловушка 2: повторный `WriteHeader` вызывает предупреждение в лог.** Если вызвать `w.WriteHeader` дважды (например, забыв `return` после `writeJSONError`), второй вызов не изменит отправленный статус, а стандартный сервер напечатает в журнал: `http: superfluous response.WriteHeader call`.

**Ловушка 3: ошибка `Encode` после отправки заголовков.** Заметьте, что `writeJSON` сначала ставит статус `200`/`201`, и только потом запускает `json.NewEncoder(w).Encode(payload)`. Если переданную структуру невозможно превратить в JSON (например, туда случайно попало поле типа `chan int` или `func()`), заголовок `200 OK` уже ушёл клиенту, а тело оборвётся! Поэтому для критичных ответов иногда сначала сериализуют данные в память через `json.Marshal` и только при успехе отправляют статус. Для плоских структур вроде `Bookmark` потоковый `Encode` безопасен, если следить за типами полей.

> [!check] Проверь понимание
> Что вернёт этот фрагмент кода клиенту (статус и заголовки)?
> ```go
> w.WriteHeader(http.StatusCreated)
> w.Header().Set("Content-Type", "application/json")
> _, _ = w.Write([]byte(`{"id":1}`))
> ```
>
> Клиент получит статус `201 Created` и тело `{"id":1}`, но заголовок `Content-Type: application/json` **не попадёт** в ответ, так как заголовки были зафиксированы в момент вызова `w.WriteHeader`.

> [!solution] Показать решение
> Сейчас ответ будет `{"tags":null}`, потому что нулевое значение слайса `tags` равно `nil`, а `encoding/json` кодирует `nil`-слайс в `null`. Чтобы получить `{"tags":[]}`, нужно явно инициализировать пустой слайс: `tags := make([]string, 0)` (или `tags := []string{}`).

**Упражнение 2 (Практическое). Предварительная сериализация в `writeJSON`.**  
Напишите вариант функции `writeJSONSafe(w http.ResponseWriter, status int, payload any)`, который сначала кодирует `payload` через `json.Marshal` (вместе с завершающим `\n`), и если `Marshal` вернул ошибку — отвечает статусом `500 Internal Server Error` с JSON-ошибкой `{"error":"ошибка формирования ответа"}`, а не отправляет оборванный `200 OK`.

> [!solution] Показать решение
> ```go
> func writeJSONSafe(w http.ResponseWriter, status int, payload any) {
> 	data, err := json.Marshal(payload)
> 	if err != nil {
> 		w.Header().Set("Content-Type", "application/json; charset=utf-8")
> 		w.WriteHeader(http.StatusInternalServerError)
> 		_, _ = w.Write([]byte(`{"error":"ошибка формирования ответа"}` + "\n"))
> 		return
> 	}
> 	w.Header().Set("Content-Type", "application/json; charset=utf-8")
> 	w.WriteHeader(status)
> 	_, _ = w.Write(append(data, '\n'))
> }
> ```
> Поскольку запись в `w` происходит только после успешного `json.Marshal`, клиент гарантированно получит либо корректный ответ со статусом `status`, либо аккуратную ошибку `500`.
