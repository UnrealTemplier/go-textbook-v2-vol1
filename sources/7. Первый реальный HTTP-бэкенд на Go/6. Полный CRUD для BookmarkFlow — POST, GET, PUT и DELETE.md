*Собираем все пять операций CRUD для `BookmarkFlow` (`POST`, `GET`, `PUT`, `DELETE`), разбираем query-фильтры, `parseIDParam` и семантику статусов `201` и `204`.*

Набор операций создания, чтения, обновления и удаления называют аббревиатурой **CRUD** (*Create, Read, Update, Delete*). Над каждым ресурсом — у нас это закладка `/api/v1/bookmarks` — эти четыре действия естественно ложатся на стандартные методы протокола HTTP, которые мы разобрали в Модуле 5:

| Операция | Маршрут в `ServeMux` | Вход | Успешный статус и тело |
|---|---|---|---|
| Create | `POST /api/v1/bookmarks` | JSON `CreateInput` | `201 Created` + созданный `Bookmark` |
| Read (список) | `GET /api/v1/bookmarks` | query `?tag=...&q=...` | `200 OK` + `{"items":[...],"count":N}` |
| Read (одна) | `GET /api/v1/bookmarks/{id}` | параметр пути `{id}` | `200 OK` + объект `Bookmark` |
| Update | `PUT /api/v1/bookmarks/{id}` | `{id}` + JSON `UpdateInput` | `200 OK` + обновлённый `Bookmark` |
| Delete | `DELETE /api/v1/bookmarks/{id}` | параметр пути `{id}` | `204 No Content` (пустое тело) |

Давайте посмотрим на реализацию обработчиков из `project/final/server.go` и разберём тонкие места каждого шага.

## Чтение списка с фильтрами и чтение по ID

Обработчик списка `handleList` извлекает необязательные параметры фильтрации из строки запроса через `r.URL.Query()`:

```go
func (s *Server) handleList(w http.ResponseWriter, r *http.Request) {
	filter := ListFilter{
		Tag:   r.URL.Query().Get("tag"),
		Query: r.URL.Query().Get("q"),
	}
	items, err := s.store.List(filter)
	if err != nil {
		writeJSONError(w, http.StatusInternalServerError, "не удалось получить список закладок")
		return
	}
	writeJSON(w, http.StatusOK, map[string]any{"items": items, "count": len(items)})
}
```

Вызов `r.URL.Query().Get("tag")` автоматически декодирует URL-кодирование (например, `%20` или кириллицу в `q=поиск`) и возвращает пустую строку `""`, если параметр не передан. Внутри `FileStore.List` оба фильтра необязательны и складываются по «И»: запрос `GET /api/v1/bookmarks?tag=go&q=doc` вернёт закладки с тегом `go`, в названии или URL которых встречается `doc`.

Для чтения одной записи, её обновления и удаления требуется числовой идентификатор из пути `{id}`. Чтобы не дублировать разбор в трёх местах, в `server.go` вынесен общий помощник:

```go
func parseIDParam(w http.ResponseWriter, r *http.Request) (int, bool) {
	raw := r.PathValue("id")
	id, err := strconv.Atoi(raw)
	if err != nil || id <= 0 {
		writeJSONError(w, http.StatusBadRequest, "идентификатор id должен быть положительным целым числом")
		return 0, false
	}
	return id, true
}
```

Если клиент запросит `/api/v1/bookmarks/0` или `/api/v1/bookmarks/abc`, он сразу получит `400 Bad Request` ещё до обращения к хранилищу. В самом `handleGet` остаётся шесть чистых строк: распарсить `id`, спросить `s.store.Get(id)`, при ошибке делегировать в `s.writeStoreError(w, err)` (который отдаст `404` для `ErrNotFound`), иначе вернуть `200 OK`.

## Создание (`201`), обновление (`200`) и удаление (`204`)

Посмотрите на три изменяющих обработчика рядом — их структура почти зеркальна:

```go
func (s *Server) handleCreate(w http.ResponseWriter, r *http.Request) {
	var in CreateInput
	if !decodeJSONBody(w, r, &in) {
		return
	}
	created, err := s.store.Create(in)
	if err != nil {
		s.writeStoreError(w, err)
		return
	}
	writeJSON(w, http.StatusCreated, created)
}

func (s *Server) handleUpdate(w http.ResponseWriter, r *http.Request) {
	id, ok := parseIDParam(w, r)
	if !ok {
		return
	}
	var in UpdateInput
	if !decodeJSONBody(w, r, &in) {
		return
	}
	updated, err := s.store.Update(id, in)
	if err != nil {
		s.writeStoreError(w, err)
		return
	}
	writeJSON(w, http.StatusOK, updated)
}

func (s *Server) handleDelete(w http.ResponseWriter, r *http.Request) {
	id, ok := parseIDParam(w, r)
	if !ok {
		return
	}
	if err := s.store.Delete(id); err != nil {
		s.writeStoreError(w, err)
		return
	}
	w.WriteHeader(http.StatusNoContent)
}
```

Три детали здесь заслуживают отдельного внимания:

1. **Зачем возвращать объект в `POST` (`201 Created`).** Клиент присылает только `title`, `url` и `tags`, а сервер сам присваивает `id`, `created_at` и `updated_at` и нормализует теги. Возвращая готовую структуру `created`, мы экономим клиенту лишний `GET`-запрос — он сразу узнаёт присвоенный `id`.
2. **Почему в `handleUpdate` сохраняется `CreatedAt`.** Внутри `FileStore.Update` новое состояние берёт `ID` и `CreatedAt` у прежней записи `prev`, меняет пользовательские поля и обновляет только `UpdatedAt: time.Now().UTC().Truncate(time.Second)`. Время создания ресурса в истории меняться не должно. Кроме того, метод `PUT` предполагает **полную замену** ресурса: даже если клиент опустил `tags`, список тегов перезапишется пустым (в отличие от частичного `PATCH`).
3. **Строгое правило `204 No Content`.** При успешном удалении `handleDelete` вызывает **только** `w.WriteHeader(http.StatusNoContent)` и ничего не пишет в тело ответа — и даже не ставит `Content-Type`. По спецификации HTTP ответ со статусом `204` не имеет тела; попытка записать туда даже `{"ok":true}` нарушит стандарт и может сбить с толку HTTP-клиенты и прокси.

## Подводный камень: утечка `nil` в списке и порядок проверок в `PUT`

В `handleUpdate` сначала вызывается `parseIDParam`, и только затем `decodeJSONBody`. Если в URL передан мусор вроде `/bookmarks/abc`, сервер не тратит время на чтение и разбор мегабайтного тела запроса, а мгновенно отклоняет запрос со статусом `400`.

А ещё обратите внимание на поля временных меток `time.Time`: в `FileStore` используется `time.Now().UTC().Truncate(time.Second)`. Все серверные метки времени хранятся строго в часовом поясе **UTC**, а округление до секунды убирает лишние наносекунды, которые не нужны в JSON API и мешают при сравнении структур в тестах.

> [!check] Проверь понимание
> Что произойдёт, если клиент отправит `DELETE /api/v1/bookmarks/1` дважды подряд?
>
> Первый запрос удалит закладку и вернёт `204 No Content`. Второй запрос не найдёт закладку `#1`, получит `ErrNotFound` и вернёт `404 Not Found` (ресурса больше нет, повторное удаление не ломает состояние сервера).

## Практика

**Упражнение 1 (Базовое). Выбор статуса ответа.**  
К запущенному серверу с одной закладкой (`id = 1`) приходят запросы. Какой статус вернёт сервер на каждый из них?
1. `GET /api/v1/bookmarks?tag=nonexistent`
2. `PUT /api/v1/bookmarks/99` с валидным JSON
3. `DELETE /api/v1/bookmarks/1`
4. `PATCH /api/v1/bookmarks/1`

> [!solution] Показать решение
> 1. **`200 OK`** с `{"count":0,"items":[]}` — отсутствие совпадений в поиске по фильтру не ошибка, а пустой список.
> 2. **`404 Not Found`** — закладка `#99` не найдена.
> 3. **`204 No Content`** без тела ответа.
> 4. **`405 Method Not Allowed`** — путь `/api/v1/bookmarks/{id}` есть, но метод `PATCH` не зарегистрирован в `ServeMux`.

**Упражнение 2 (Практическое). Округление `Location` при создании.**  
По стандарту HTTP ответ `201 Created` часто дополняют заголовком `Location` со ссылкой на только что созданный ресурс (например, `/api/v1/bookmarks/1`). Допишите установку этого заголовка в `handleCreate` в правильном порядке относительно `writeJSON`.

> [!solution] Показать решение
> ```go
> created, err := s.store.Create(in)
> if err != nil {
> 	s.writeStoreError(w, err)
> 	return
> }
> w.Header().Set("Location", fmt.Sprintf("/api/v1/bookmarks/%d", created.ID))
> writeJSON(w, http.StatusCreated, created)
> ```
> Заголовок `Location` ставится строго **до** вызова `writeJSON`, потому что внутри `writeJSON` вызывается `w.WriteHeader(http.StatusCreated)`.

**Упражнение 3 (Со звёздочкой \*). Проверка `r.URL.Query()` с несколькими значениями.**  
Клиент случайно или намеренно прислал запрос `GET /api/v1/bookmarks?tag=go&tag=http`. Что вернёт `r.URL.Query().Get("tag")` в текущем коде и как можно прочитать оба переданных значения, не ломая существующий случай с одним тегом?

> [!solution] Показать решение
> `r.URL.Query()` возвращает `url.Values` (псевдоним `map[string][]string`). Метод `.Get("tag")` возвращает только **первое** значение для ключа `"tag"`, то есть `"go"`, а `"http"` проигнорирует. Чтобы забрать все значения параметра, нужно обратиться к мапе напрямую: `tags := r.URL.Query()["tag"]` вернёт срез `[]string{"go", "http"}` (или `nil`, если параметр не передан).
